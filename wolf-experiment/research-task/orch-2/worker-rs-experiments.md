# Worker Experiments — доказательная база схемы Mr. Wolf (по REPORT.md)

Источник: wolf-experiment/REPORT.md (638 строк; находки 1–37, механика M1–M12, гипотезы H1.1–H1.5/H2, эксперименты SPLIT-001 / COST-001 / LONG-001 / LONG-002 / REVIEW-001).

## Сводка

Схема Wolf → Executor → Workers нативно реализуема и механически надёжна: спавн,
границы (permission.task + globs + subagent_depth), квоты, файловый протокол
с докатом и Council Mode подтверждены прогонами и независимой верификацией.
Опровергнуто экономическое обоснование на генеративных задачах (налог 3–11×
токенов) и capacity-гипотеза (flat не тонет). Подтверждённые преимущества:
тонкий wolf-контекст, больше найденных дефектов при ревью, −29% full-токенов,
живучесть. Итого: 16 подтверждено, 7 опровергнуто, 7 не проверено.

## 1. Подтверждено экспериментами

- Трёхуровневая иерархия нативна: вложенный спавн тулом task без CLI-обходов; три режима (конвейер/консилиум/совет) — [источник: §1 H1.1–H1.2, §2.1, §5.1–5.3]
- Тул task субагентам denied по умолчанию; без permission.task executor уходит в CLI-импровизацию (задача выполнена, контроль потерян) — [источник: находка 1, §4 M2, §7 TEST-001 №1]
- subagent_depth режет глубину в рантайме, даже при task: allow (probe уровня 2 заблокирован) — [источник: находка 2, §1 H1.4, §7 D-5]
- Glob-границы «кто кого спавнит» жёсткие, с информативной ошибкой (wolf→worker запрет / цепочка разрешена) — [источник: находка 3, §4 M3, §7 D-6]
- Массив tools: в frontmatter deprecated и невалиден (конфиг не грузится) — только permission-мапа — [источник: находка 4, §4 M1]
- Файловый протокол переживает прерывание: докат после user abort и kill@50% без пересоздания готового, дефекты импорта ловит фиксер — [источник: находки 7, 17, 26; §5.4, §9c]
- Лимит воркеров через throw в before-хуке плагина = жёсткая квота (3 OK, 4-й блок, task.blocked в журнале) — [источник: находка 8, §7 D-9, §6]
- Кворум/консенсус wolf (k3-256k) считает безошибочно «строго по файлам» (независимый пересчёт 10/10); TIMEOUT-член честно эмулируется VOTE-контрактом — [источник: находки 9, 10; §1 H1.5, §6, §7 COUNCIL-001..008]
- Council Mode целиком: 11 советов, 8 сценариев, кворумы/эскалация/итерации/параллельность (7 спавнов одним сообщением) — [источник: §1 H2, §5.3]
- Permission-стена покрывает только встроенные тулы: MCP/кастом-тулы проходят мимо deny — [источник: находка 11, §4 M8]
- Живучесть в run-режиме: эскалация = файл + второй запуск; упавший rtk-grep wolf пережил нативными Grep/Glob — [источник: находки 12, 13]
- Дробление задач executor-ом (таблица декомпозиции, лимит 5) работает: слот-голодание COST-001 не воспроизвелось, качество 167/167 — [источник: §9c H2 (LONG-001), находка 31]
- Capacity-свойство уровня wolf: пик контекста координатора 11–18k на двух классах задач (втрое+ тоньше flat) — [источник: находка 23, §9c, §9d]
- Изоляция перспектив бьёт по слепым зонам саморевью: major-дефектов вдвое больше (57 vs 26), пик — completeness-раунд — [источник: находка 32, §9e H1]
- full-токены — первая метрика, где иерархия выигрывает (−29%, cache.read 7–12M у flat), и пик контекста распараллеливается (author ~100k, ревьюеры 37–155k вместо одного 190k) — [источник: находки 33, 35; §9e]
- Специфицируемая задача = однопроходная: flat строит фреймворк по спеке за один проход с 0–1 правками — [источник: находка 28, §9d]

## 2. Опровергнуто / не подтвердилось

- H1 capacity (LONG-001): FLAT чисто мигрировал 48 файлов/2597 строк — регулярная (темплейтная) база скриптуется, flat не тонет — [источник: находка 22, §9c]
- H1 capacity (LONG-002): flat 3/3 чисто (100% API/тестов, пик 53–66k), ни один из 5 предсказанных failure-режимов flat не материализовался — [источник: §9d]
- H2 преимущество иерархии (LONG-002): ни один из 4 критериев переломного пункта не выполнен (нет экономии: +410% new, качество паритетно) — [источник: §9d]
- Гипотеза «flat тонет на T3» (COST-001): не подтвердилась — задача мала для контекста 1M — [источник: §9b]
- H3 REVIEW-001 (финал выше по слепой оценке): паритет 43.7 vs 43.0 при шуме 41–46; судья не отличает финалы от базы — [источник: §9e, находка 34]
- H2 REVIEW-001 (насыщение позже): лишь частично — «всплеск» r2 есть смена перспективы, не отложенное насыщение; к 3-му раунду темп падает у обоих — [источник: §9e]
- «Чистый» раскол планов по всем 3 критериям эксперта не достигнут: хранилищевая ось не развелась (обе философии отвергли sqlite) — [источник: находка 15, §9a, §10]

## 3. Не проверено / заявлено без доказательств

- Версия-зависимость: механика M1–M12 проверена только на opencode v1.18.18; при апгрейде — перепроверять smoke-ом — [источник: §4, §10]
- Взвешенные голоса советов (участник ×2) не проверялись (эквивалент — вес при синтезе wolf-ом) — [источник: §10]
- Переломный пункт «оркестрация vs flat» (overhead ≤50%) не достигнут ни в одном эксперименте: нужен класс задач, где flat реально упирается в контекст — [источник: §9b, §9c, §10]
- Класс задач, где flat объективно не справляется (пик >200k), в песочнице не построен; гипотеза-кандидат — неспецифицируемые задачи (отладка legacy без спеки, «сделай как лучше») — [источник: находка 28, §10]
- Экономия контекста всей схемы: пик переезжает на executor-а (56–76k, выше flat в 2/3 прогонов LONG-002) — «тонким» остаётся только wolf — [источник: находка 27, §9d, §10]
- Эффект иерархического ревью для молодых/черновых документов (где остались critical) может быть выше — не проверено — [источник: §9e вывод]
- Рантайм-учёт токенов (вариант 2, плагин usage-logger.ts) спроектирован, но точное имя события — проверить при реализации — [источник: §9]
