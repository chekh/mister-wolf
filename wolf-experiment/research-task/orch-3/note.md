## 1. Подтверждено экспериментами

**Механика иерархии (фаза 1, §1, H1.1–H1.5).** Нативная конфигурируемость подтверждена: 12 md-агентов загружаются и диспетчерятся в изолированном подпроекте без CLI-обходов. Вложенный спавн executor→воркеры работает только при `permission.task`; без него субагент импровизирует CLI `opencode run` — задача выполняется, но контроль теряется (находка 1). `subagent_depth` жёстко блокирует третий уровень в рантайме даже у агентов с `task: allow` (находка 2). Границы «кто кого спавнит» жёсткие: нарушение падает с информативной ошибкой (находка 3). Жёсткая квота воркеров реализуема throw'ом в before-хуке плагина: 3 спавна проходят, 4-й блокируется (находка 8).

**Файловый протокол и устойчивость.** Обмен только артефактами (brief/decision/report) подтверждён как рабочий протокол контекстной изоляции. Протокол переживает прерывание процесса: докат без пересоздания готового стоит ~0.7× чистового прогона (находки 7, 17, 26; §5.4).

**Наблюдаемость.** Плагин-журнал пишет до permission-проверки — форензика отклонённых попыток работает (находка 6; §4 M7). Подтверждённые артефакты механики конфигурации: массив `tools:` в frontmatter невалиден (только permission-мапа), `todowrite` субагентам denied by design, кастом-тулы субагентам выдаются (находки 4, 5). Подтверждена и дыра: MCP/кастом-тулы проходят мимо `bash: deny` (находка 11; §4 M8).

**Council Mode (H2).** Кворумы, пороги, эскалация, итерации и параллельность проверены на 11 советах; независимый пересчёт совпал с синтезами wolf 10/10; timeout-член честно эмулируется через `VOTE: TIMEOUT` (находки 9, 10).

**Экономика и контекст (§9).** Картина контекстных пиков двоякая: wolf остаётся тонким (11–18k против flat 47–51k), но пик переезжает на executor (56–76k, выше flat в 2/3 прогонов), а в ревью-схеме распараллеливается по агентам (находки 23, 27, 35). Дробление задач стабильно: таблица декомпозиции присутствует во всех чистых отчётах; при лимите 5 слот-голодание ревью не воспроизвелось (находка 31). Первый измеренный выигрыш иерархии — full-токены на ревью (−29%; находка 33), учёт per-agent/per-model проверен живыми данными SQLite.

**Ревью.** Изоляция перспектив ревью бьёт по слепым зонам саморевью: +31% issues, major 57 против 26 (находка 32).

**Принципы схемы** (по документам, воркер concept): трёхуровневая иерархия Wolf → Executor → Workers; файловый протокол; изоляция ответственности уровней (Wolf не пишет код и не запускает команды; executor делегирует; воркеры не спавнят); градация TRIVIAL/SIMPLE/MEDIUM/COMPLEX; тиры моделей «сложность ↔ модель»; «самодекларациям — нет» (системный журнал + независимая верификация); машиносчитаемые контракты (`VERDICT:`, `VOTE:`); три режима оркестрации (конвейер/консилиум/совет); эскалация к человеку через файл; дисциплина каталогов. Большинство заявлялось как гипотезы фазы 1 и получило эмпирический статус ✅.

## 2. Остаётся гипотезой

**Гипотезы, не подтвердившиеся в проведённых экспериментах** (воркер experiments):

- «Flat тонет на сложной задаче» (T3) — не подтвердилась: 100% зелёных тестов, задача мала для 1M-контекста (§9b, COST-001). H1 capacity (LONG-001) опровергнута: темплейтная фикстура мигрируется flat-агентом «скриптом» 167/167 ×3 — задача сопротивлялась скриптованию недостаточно (находка 22). H1/H2 LONG-002 не подтверждены: flat 3/3 чисто, ни один из 5 предсказанных failure-режимов не проявился; налог иерархии +410% new при паритетном качестве (§9d).
- H3 REVIEW-001 («финал выше по слепой оценке») — не подтверждена: 43.7 vs 43.0 при base 42 — паритет в пределах шума (находка 34).
- «Конфликта приоритетов планировщиков достаточно для раскола» — нет: оба сходятся на аттракторе без брифа с развилками (находка 14); хранилищевая ось провокации планы не развела (находка 15).

**Непроверенное** (кандидаты в гипотезы следующего этапа): переломный пункт «flat тонет» и безубыточность иерархии по new-токенам (порог 50%) не достигнуты — даже миграционный масштаб дал +239% (находка 24, §10); класс задач, где flat объективно не справляется (пик >200k), не построен — кандидат: неспецифицируемые задачи, отладка legacy без спеки (находка 28); взвешенные голоса совета не проверялись (§10); эффект иерархического ревью на черновых документах с critical-дефектами не измерен (§9e); механика M1–M12 проверена только на opencode v1.18.18 (§10); «у задачи был аттрактор» — интерпретация-предположение, а не установленный факт (concept, §9a).

## 3. Альтернативы в индустрии

Обязательная четвёрка (по отчёту industry, с URL) + один дополнительный фреймворк:

- **AutoGen** (Microsoft) — трёхуровневый стек Core (event-driven runtime) / AgentChat (conversational API) / Extensions; GroupChat и Rundown; распределённые агенты через gRPC. Ограничения: Core низкоуровневый, требует ручной оркестрации, нет встроенных графовых структур, ломающая миграция 0.2→0.4. Use cases: прототипирование, бизнес-процессы, R&D. Источник: https://microsoft.github.io/autogen/stable/, github.com/microsoft/autogen.
- **CrewAI** — «crew» из Agents и Tasks; процессы Sequential / Hierarchical (менеджер делегирует воркерам) / Hybrid + Flows (start/listen/router); memory short/long-term + entity + knowledge base; guardrails. Ограничения: enterprise-фичи (triggers, RBAC, деплой) платны; ограниченный контроль над внутренним промптингом. Use cases: автоматизация поддержки/sales, data pipelines. Источник: https://docs.crewai.com/.
- **LangGraph** (LangChain) — StateGraph: направленный граф узлов и рёбер, смешивание детерминированных и LLM-шагов (вдохновлено Pregel/Apache Beam); общий State через Channels; persistence и human-in-the-loop через interrupts. Ограничения: низкоуровневый, не абстрагирует промпты и архитектуру. Use cases: stateful workflows (Klarna, Uber, J.P. Morgan), production через LangSmith. Источник: https://docs.langchain.com/oss/python/langgraph/overview, langchain-ai.github.io/langgraph.
- **MetaGPT** — ролевая модель (PM, Architect, Engineer, QA), философия `Code = SOP(Team)`; координация publish/subscribe артефактов; из одной строки требований — полный пакет документов и код. Ограничения: SOP фиксированы под software development; позиционируется скорее как продукт (MGX). Use cases: генерация ПО, Data Interpreter. Источник: https://github.com/geekan/MetaGPT (github.com/FoundationAgents/MetaGPT).
- **Дополнительно: OpenAI Swarm** (заменён Agents SDK) — два примитива Agent + Handoff, полностью stateless; educational. Источник: https://github.com/openai/swarm.

**Позиционирование Mr. Wolf против четвёрки** (воркер comparison; факты по альтернативам в этой части — «без верификации» из-за rate limit, URL официальные): ни один из фреймворков не реализует строгую трёхуровневую иерархию с файловой изоляцией «из коробки». Уникальное у Mr. Wolf: (а) системные, а не промптовые границы — denied-by-default спавн, glob «кто кого», depth-лимит, throw-квота воркеров; (б) файловый протокол как единственный канал с докатом после сбоя — у AutoGen результат nested chat возвращается пересказом, у CrewAI/MetaGPT общая память/pool; (в) «анти-самодекларационная» наблюдаемость: журнал до permission-проверки + независимый пересчёт. Совпадает с индустрией: паттерн «менеджер-делегатор» (AutoGen Team, CrewAI hierarchical), программируемая изоляция state у LangGraph идейно родственна файловой. Слабее Mr. Wolf: нет аналога LangSmith UI по трейсингу; дыра MCP-тулов вне permission-стены; depth-лимит 2 жёстче вложенности AutoGen/LangGraph.

## 4. Риски и ограничения

**Реестр M1–M12** (воркер risks): закрыты — M1 (тихий отказ конфига от невалидного `tools:`; находка 4), M2 (CLI-обход без `permission.task`; находка 1), M3 (границы спавна; находка 3), M7 (форензика до permission; находка 6), M12 (учёт токенов: агент-фильтр + inline-маркеры; находка 20). Частично закрыты — M4 (depth-лимит есть, семантика версиозависима), M6 (after-хук слеп при ошибке тула; находка 6), M9 (`--pure` и автодискавери), M11 (нет нативного таймаута `opencode run`: завис 46 мин — находки 21, 25a; внешний watchdog bg+poll+kill 1800с — находка 30). **Не закрыты — M8** (permission-стена не покрывает MCP/кастом-тулы; находка 11) и M10 (кастом-тулы всем субагентам — допустимо для read-only).

**Failure-режимы оркестрации (наблюдённые)**: слот-голодание ревью (находка 19; закрыто лимитом 3→5); path drift (§9b; детект без превенции); монолитный завис executor'а (находка 25a; watchdog+ретрай); fast-fail rtk-обёртки (находка 25b; закрыто ретраем); немые обрывы провайдера при параллельном трафике, 4/7 flat-запусков, exit=0 (находка 36; ретраи оперативны, причина не устранена); скретч-файл executor'а — нарушение «код только воркерами» (системно не закрыто); переезд пика контекста на executor (находки 27, 35; в генерации не закрыт); **токен-налог иерархии +274–1141% (малые), +239% (миграция), +410% (фреймворк по спеке)** (находки 18, 24); нулевая конверсия ревью в финальное качество по слепому судье (находка 34) — ревью позиционируется как «процессор качества поиска», не генератор лучшего документа.

**Открытые вопросы (7, воркер risks)**: существует ли класс задач, где flat объективно тонет; где точка безубыточности по токенам; масштабируется ли пик executor'а линейно и нужен ли дробящий слой выше воркеров; даёт ли изолированное ревью измеримо лучший финал на черновых документах; достижим ли «чистый» раскол планов по трём осям; структурна ли устойчивость ORCH к немым обрывам (0 падений, выборка мала — находка 36); стабильна ли механика M1–M12 при апгрейде opencode.

## 5. Рекомендации

1. **Применять иерархию точечно — там, где выигрыш измерен**: поиск/ревью дефектов (+31% issues, находка 32; full-токены −29%, находка 33). Для генерации — только когда flat не справляется: налог new-токенов +239–410% не окупается паритетным качеством (§9d).
2. **Построить класс задач, сопротивляющихся скриптованию** — неспецифицируемые задачи (отладка legacy без спеки, «сделай как лучше») как главный кандидат на переломный пункт (находки 22, 28; §10). Без этого экономический смысл иерархии остаётся недоказанным.
3. **Закрыть M8**: распространить permission-стену на MCP/кастом-тулы (находка 11) — единственный наблюдённый риск с статусом «не закрыт» в механике.
4. **Ограничить пик executor'а**: исследовать дробящий слой выше воркеров (открытый вопрос 3, находка 27) — иначе изоляция контекста переносит, а не решает проблему пика.
5. **Стандартизировать watchdog + ретраи** против немых обрывов и зависов (находки 25a, 30, 36) — как внешний контур, пока `opencode run` не имеет нативного таймаута (M11).
6. **Smoke-регресс механики M1–M12** при каждом апгрейде opencode (версиозависимость depth/permission, §10); уточнить событие usage-logger при реализации рантайм-плагина (§9).
7. **Дозакрыть исследовательские пробелы**: взвешенные голоса совета; эффект ревью на черновых документах; изолированная репродукция немых обрывов (воркер risks, вопросы 4–6).
8. **Заимствовать из индустрии** (comparison): наблюдаемость уровня LangSmith (трейсинг/UI) при сохранении уникальных механизмов — файлового протокола и анти-самодекларационного журнала; не копировать общую память CrewAI/MetaGPT — она противоречит подтверждённому принципу изоляции.
