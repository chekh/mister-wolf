# Мнение совета: производительность (COUNCIL-TEST-002)

VOTE: B

## Обоснование

Модульный монолит даёт наилучшие показатели производительности для команды из 3 разработчиков: внутрипроцессные вызовы между модулями на порядки быстрее сетевых (нет сериализации, TCP/HTTP-overhead, ретраев). Микросервисы (A) добавляют латентность 1–10 мс на каждый межсервисный вызов, распределённые транзакции и затраты на оркестрацию — при малой нагрузке стартапа это чистый оверхед без выигрыша. Вариант C близок, но B жёстче фиксирует границы модулей (чёткие интерфейсы, запрет сквозных зависимостей), что сохраняет возможность выделить «горячий» модуль в отдельный сервис именно там, где профилирование покажет реальное узкое место. Масштабирование целого монолита горизонтально (stateless-реплики за балансировщиком) покрывает подавляющее большинство нагрузок стартапа без потери производительности. Бенчмарки и профилирование при этом проще: один процесс — один flamegraph, нет распределённой трассировки. Рекомендация: B, с метриками на границах модулей, чтобы решение о выделении сервиса принималось по данным, а не заранее.
