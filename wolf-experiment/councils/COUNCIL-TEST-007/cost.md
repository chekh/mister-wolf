# Мнение: Council Cost Analyst (COUNCIL-TEST-007)

## Оценка вариантов

- **A) Удалить сразу** — минимальные текущие затраты (чистый код, нет дублирования), но потенциально высокий стоимость поддержки при негативной реакции 1000 пользователей (массовые обращения, форки, экстренные фиксы). Риск непрогнозируемых затрат без данных.
- **B) Оставить навсегда** — накапливающаяся стоимость владения: поддержание двух веток логики, увеличение тестовой матрицы, технический долг растёт экспоненциально. При ~1000 пользователях это неоправданная нагрузка на команду в долгосрочной перспективе.
- **C) Deprecation warning + удаление через 6 месяцев** — оптимальный баланс стоимости: предупреждения стоят почти ничего (один лог/заголовок), а 6-месячный период даёт пользователем мигрировать. Команда получает реальную метрику использования через логи, что позволяет принять взвешенное решение о реальном удалении. Модерные затраты на поддержку устаревшего кода — минимальны.

## Рекомендация

Вариант C — единственный, который конвертирует неопределённость (нет данных об использовании) в измеримую информацию через логирование deprecation warning. Это снижает риск дорогих ошибок при минимальных вложениях. Удаление «навсегда» — дорого; удаление «сразу» — рискованно без данных.

VOTE: C

## Риски

- Если никто не использует устаревший функционал, 6 месяцев deprecation — лишняя стоимость поддержки (минимальная, но ненулевая). Можно смягчить: собрать метрики за 2–3 месяца и удалить раньше при нулевом трафике.
