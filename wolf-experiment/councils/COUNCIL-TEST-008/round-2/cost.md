## Оценка вариантов

**A) csv-parser** — 0 зависимостей (~50 KB), минимальная поверхность атаки, стабильный API, нативный Transform-stream. Стоимость владения минимальна: нет каскадных обновлений зависимостей, нет транзитивных CVE. Security-история чистая (в отличие от PapaParse, уязвимость в котором подтверждает риск «толстых» библиотек с широкой функциональностью).

**B) fast-csv** — больше зависимостей, шире API → выше поверхность атаки и выше стоимость сопровождения (обновления, аудит транзитивных зависимостей). Для задачи импорта до 100 МБ избыточен по функциональности, переплата в TCO.

**C) Собственная реализация** — максимальная стоимость: разработка, поддержка edge-cases (quoted fields, multiline, BOM, escape-символы), регулярный security-аудит за свой счёт.csv-parser уже решает это за ~50 KB без зависимостей — reimplement не имеет экономического обоснования.

## Рекомендация

csv-parser остаётся оптимальным с точки зрения TCO: нулевые зависимости устраняют каскадные риски безопасности, минимальный размер снижает поверхность атаки, а стабильный API сокращает стоимость миграций. Уязвимость PapaParse подтверждает, что выбор «тонкой» библиотеки с узкой ответственностью — правильная стратегия минимизации стоимости безопасности.

## Риски

- Единая точка отказа: если csv-parser перестанет поддерживаться, потребуется миграция (mitigated: 0 зависимостей → легко форкнуть). Остальные варианты не снижают этот риск, а вариант C увеличивает его (одиночный мейнтейнер — мы сами).
