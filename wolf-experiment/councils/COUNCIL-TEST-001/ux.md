# Мнение UX — COUNCIL-TEST-001

## Оценка вариантов

- **A) requests** — классика: минимальный когнитивный порог, интуитивный API, тонны примеров; для простого сервиса экспорта CSV удобство разработки максимально.
- **B) httpx** — современный API (таймауты по умолчанию, HTTP/2, sync+async), чуть лучше эргономика ошибок, но лишний вес, если async не нужен.
- **C) urllib** — ноль зависимостей, но многословный, неочевидный API: разработчику приходится писать бойлерплейт, выше риск ошибок и хуже читаемость.

## Рекомендация

С позиции UX/удобства разработки: requests даёт самый понятный и короткий код, что напрямую снижает число ошибок и ускоряет онбординг. Одна зависимость — приемлемая цена за читаемость; urllib ради «нулевых зависимостей» ухудшает DX несоразмерно. Если async не планируется — requests оптимален.

VOTE: A

## Риски

- requests в «замороженном» состоянии (новые фичи — в httpx); если сервис позже потребует async/HTTP/2, придётся мигрировать.
- Зависимость всё же есть — для ультра-минимальных окружений (lambda-слои) может быть аргумент за urllib.
