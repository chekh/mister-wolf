# Мнение члена совета — роль: performance (COUNCIL-TEST-001)

## Оценка вариантов

- **A) requests** — синхронный, блокирующий; на пуле соединений держит приемлемый throughput, но без async и HTTP/2; под нагрузкой требует потоков/процессов, что дорого по CPU/памяти.
- **B) httpx** — синхронный и асинхронный API, HTTP/2, пул соединений, таймауты из коробки; в async-режиме масштабируется на порядки лучше по конкурентным запросам при той же памяти.
- **C) urllib** — стандартная библиотека, ноль зависимостей, но низкоуровневая, без удобного пула и современных фич; ручная обвязка съест любой выигрыш в производительности и добавит риск ошибок.

## Рекомендация

Для сервиса экспорта CSV с акцентом на надёжность и скорость httpx — оптимален: connection pooling, гранулярные таймауты, async при росте нагрузки. Переход с requests почти бесплатен по API, а по эффективности при конкурентных запросах httpx выигрывает заметно. urllib — только ради нуля зависимостей, ценой ручной работы и риска деградации latency.

VOTE: B

## Риски

- httpx добавляет одну зависимость (httpcore, anyio) — приемлемо.
- Если сервис гарантированно однопоточный и низконагруженный, выигрыш httpx над requests минимален — но и проигрыша нет.
