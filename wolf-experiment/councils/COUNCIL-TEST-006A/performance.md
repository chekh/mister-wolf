# Мнение члена совета: performance (производительность)

## Оценка вариантов

- **A) PostgreSQL** — зрелый планировщик запросов, параллельное выполнение,
  оконные функции, CTE, материализованные представления и эффективные
  GIN-индексы по JSONB дают высокую производительность на сложных
  аналитических запросах. JSONB хранится в бинарном виде — разбор не нужен
  при каждом чтении.
- **B) MySQL** — оптимизатор слабее на сложных join/subquery, JSON хранится
  как текст с парсингом при доступе (функциональные индексы — обходной путь),
  параллельное выполнение запросов отсутствует. Для аналитики заметно
  проигрывает.

## Рекомендация

Для аналитического сервиса со сложными запросами и JSON-полями PostgreSQL
объективно быстрее: лучший оптимизатор, бинарный JSONB, богатые типы
индексов и параллелизм снижают latency и стоимость выполнения тяжёлых
запросов.

VOTE: A

## Риски

- PostgreSQL требует тюнинга (work_mem, индексы, vacuum) — без него выигрыш
  не гарантирован.
- На простых OLTP-нагрузках разница с MySQL несущественна; выбор обоснован
  именно аналитическим профилем из контекста.
