# Мнение: Council Security — COUNCIL-TEST-006A

## Оценка вариантов

- **A) PostgreSQL** — зрелая модель безопасности: row-level security (RLS), гранулярные роли, SCRAM-SHA-256 и mTLS из коробки, SELinux/AppArmor-интеграции, регулярные CVE-патчи. JSONB + GIN-индексы закрывают задачу JSON-полей без сторонних расширений (меньше поверхности атаки).
- **B) MySQL** — базовая защита достаточна, но ролевая модель и RLS беднее (RLS появился только в 8.0 LE и ограничен), JSON-тип — прослойка над текстом, что расширяет поверхность для инъекций при сложных запросах; исторически больше инцидентов с unsafe defaults.

## Рекомендация

Для аналитического сервиса со сложными запросами и JSON-полями PostgreSQL даёт более сильный профиль безопасности «из коробки»: детальный контроль доступа (RLS, роли), современная аутентификация, типизированный JSONB вместо текстовой эмуляции. Это напрямую снижает риск SQL-инъекций и утечек при многопользовательском аналитическом доступе.

VOTE: A

## Риски

- Ни одна СУБД не снимает риски приложения: параметризованные запросы и миграции обязательны.
- Расширения PostgreSQL (pg_jsonschema и пр.) требуют контроля версий и аудита стороннего кода.
