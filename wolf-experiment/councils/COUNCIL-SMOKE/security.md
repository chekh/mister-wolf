# Мнение совета (специалист по безопасности) — COUNCIL-SMOKE

**Вопрос:** как хранить пароли пользователей веб-приложения?

## Оценка вариантов

- **A) bcrypt** — адаптивная медленная хеш-функция с настраиваемым cost factor и встроенной солью; устойчива к GPU-брутфорсу, соответствует рекомендациям OWASP для хранения паролей.
- **B) MD5 с солью** — категорически неприемлемо: MD5 криптографически сломан (коллизии) и слишком быстр, соль не спасает от оффлайн-перебора на современном оборудовании (миллиарды попыток/сек на GPU).

## Рекомендация

bcrypt — отраслевой стандарт для хранения паролей: медленность является фичей (перебор дорогостоящий), cost factor позволяет масштабировать защиту по мере роста мощностей, соль встроена в формат. MD5 с солью — устаревший паттерн 2000-х, его использование сегодня расценивается как уязвимость ( CWE-916 : пароль захеширован слабой функцией). При угрозе компромисса БД вариант B практически гарантированно приводит к восстановлению паролей.

VOTE: A

## Риски

- Даже с bcrypt нужен адекватный cost factor (≥10) — заниженный параметр снижает защиту.
- bcrypt ограничен 72 байтами входа; длинные пароли следует нормализовать (например, pre-hash), а миграцию со старых схем — планировать заранее.
