# Мнение council-performance по COUNCIL-TEST-005

**Вопрос:** TypeScript или JavaScript для нового микросервиса?

## Оценка вариантов

- **A) TypeScript.** Runtime-производительность идентична JS (компилируется в него); типизация стирается. Дополнительные затраты — шаг сборки (tsc/esbuild), но esbuild/swc делает его почти бесплатным. Типы снижают количество runtime-проверок и защитного кода, косвенно улучшая эффективность.
- **B) JavaScript.** Нулевая стоимость сборки, чуть быстрее старт проекта. Но отсутствие типов ведёт к избыточным runtime-валидациям и отладке, что на дистанции проигрывает по скорости разработки — ключевому требованию контекста.

## Рекомендация

С позиции производительности варианты почти паритетны в runtime, но TypeScript выигрывает за счёт раннего обнаружения ошибок без заметных накладных расходов на сборку (esbuild/swc). Для микросервиса с приоритетом скорости разработки выбор очевиден.

## Риски

- Шаг транспиляции добавляет время в CI и при холодном старте dev-цикла (минимально с esbuild).
- Сложные generic-типы могут замедлять type-check на больших кодовых базах.
