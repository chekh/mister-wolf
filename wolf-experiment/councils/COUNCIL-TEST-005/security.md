# Мнение council-security (COUNCIL-TEST-005)

## Оценка вариантов

- **A) TypeScript** — статическая типизация снижает класс ошибок вида undefined/null, некорректных контрактов API и инъекций через нетипизированные данные; экосистема инструментов (strict-режим, lint-правила безопасности) зрелая.
- **B) JavaScript** — отсутствие типов увеличивает риск ошибок в валидации входных данных и сериализации/десериализации; безопасность границ (валидация схем, парсинг внешних данных) ложится целиком на рантайм-проверки, которые легко забыть.

## Рекомендация

С позиции безопасности TypeScript предпочтительнее: строгие типы работают как первый слой защиты на границах сервиса (входящие запросы, конфиги, внешние данные), уменьшая поверхность для ошибок, которые эксплуатируются как уязвимости. Для команды из 2 разработчиков это ещё и дешёвая страховка от человеческого фактора. Рантайм-валидацию (zod и т.п.) нужно сохранить в любом случае, но TS даёт её типизировать.

VOTE: A

## Риски

- Ложная уверенность: типы не заменяют рантайм-валидацию внешних данных — нужен schema-парсинг на границе.
- При выключенном strict-режиме TS вырождается в «JS с аннотациями» — требовать `"strict": true`.
