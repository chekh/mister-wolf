# COUNCIL-TEST-003 — Синтез совета

## Вопрос

Какой алгоритм использовать для хеширования паролей? (веб-приложение с
аутентификацией, GDPR, требование — максимальная безопасность)

## Состав совета

council_id=security: council-security, council-architect, council-cost
(quorum=2, consensus_threshold=1.0)

## Голоса

| Роль | VOTE |
|---|---|
| council-security | B |
| council-architect | B |
| council-cost | B |

Рекомендация: B (argon2, в режиме Argon2id) (3 из 3 валидных)

## Обоснование рекомендации (сводка мнений)

- **security**: Argon2id — победитель Password Hashing Competition, первичная
  рекомендация OWASP; memory-hard, устойчив к GPU/ASIC-атакам; bcrypt ограничен
  72 байтами и малой памятью, scrypt хуже стандартизован. Параметры не ниже
  m=19 МиБ, t=2, p=1, per-user соль.
- **architect**: действующий стандарт OWASP/RFC 9106 для новых систем,
  гибкая настройка памяти/времени/параллелизма, достаточная экосистемная
  поддержка; риск DoS через стоимость памяти закрывается дефолтами OWASP.
- **cost**: выше瞬时 стоимость RAM/вычислений при пиковой нагрузке, но ниже
  стоимость риска компрометации — оправдано для GDPR-контекста.

## Разногласия

Нет — голосование единогласное (3/3 за B).

## Quorum

Достигнут: 3 валидных голоса из требуемых 2. Не ответивших нет.
Консенсус: доля победителя 3/3 = 1.0 >= 1.0 — достигнут.
