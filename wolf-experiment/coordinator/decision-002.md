## План A (кратко)
Лексер → рекурсивный спуск с вычислением на лету (без AST), грамматика expr/term/factor/primary, унарный минус рекурсивно, унарный плюс — SyntaxError, мусор в конце — SyntaxError. Воркеры: ОДИН implementer создаёт оба файла (согласованность контракта) → reviewer → опциональный фиксер (сохраняется слот лимита 3).

## План B (кратко)
Тот же лексер + рекурсивный спуск (parse-and-evaluate), токен EOF, явная проверка деления на вычисленный ноль. Воркеры: ДВА implementer'а параллельно (модуль и тесты отдельно против зафиксированного контракта) → reviewer; максимум 1 фикс-итерация.

## Выбор
**План A**, с одним заимствованием из B: явное требование, чтобы `ZeroDivisionError` возникал и при делении на «вычисленный» ноль (`1/(2-2)`), и соответствующий тест.

## Обоснование
- Алгоритмы идентичны (лексер + рекурсивный спуск, те же краевые случаи) — решает схема воркеров.
- План A: один implementer на оба файла исключает риск рассинхрона контракта/импортов между параллельными воркерами (риск B) и сохраняет 1 слот лимита (3 воркера) на фикс-итерацию.
- План B тратит все 3 слота сразу и не оставляет резерва на правки после ревью.
- Из B заимствовано акцентирование: проверка деления на ноль — на этапе вычисления (покрывает `1/(2-2)`), а не только литеральный ноль.

## Финальная инструкция для executor-lead

### Подход
Лексер → рекурсивный спуск с вычислением на лету, только stdlib, без eval/exec/compile.

Грамматика:
```
expr    := term (('+' | '-') term)*
term    := factor (('*' | '/') factor)*
factor  := '-' factor | primary
primary := NUMBER | '(' expr ')'
```

Фиксации контракта:
- Результат всегда `float`; `/` — true division.
- Унарный минус поддержан (`-3 + 5`, `2 * -3`, `-(2+3)`, `--3`); унарный плюс НЕ поддержан → `SyntaxError`.
- Числа: `\d+(\.\d*)?` или `\.\d+` (`3.14`, `.5`, `10` валидны; `1e3`, `3..5`, `.` → `SyntaxError`).
- Пробелы/табы игнорируются; `1 2` (два числа подряд) → `SyntaxError`.
- Пустая строка / только пробелы → `SyntaxError`.
- Мусор после валидного выражения (`1 + 2 3`), непарные скобки в обе стороны, оператор без операнда, неизвестные символы (буквы, `%`, `^`, unicode-минус) → `SyntaxError`.
- Деление на ноль — на этапе вычисления: `1/0`, `1/0.0`, `1/(2-2)` → `ZeroDivisionError`.

### Файлы
- `workers/expr.py` — лексер (`_tokenize`), класс `_Parser` (parse/expr/term/factor/primary + проверка исчерпания токенов), публичная `evaluate(expression: str) -> float` с Google-style docstring. Строгая типизация.
- `workers/test_expr.py` — `unittest.TestCase`, импорт `from workers.expr import evaluate` (namespace package, `__init__.py` не нужен), дробные сравнения через `assertAlmostEqual`, в конце `if __name__ == "__main__": unittest.main()`.

Покрытие тестов (обязательное): все 4 операции; приоритет `*`/`/` над `+`/`-`; вложенные скобки; целые и дробные литералы (`3.14`, `.5`); унарный минус; пробелы; тип результата float; `ZeroDivisionError` (`1/0`, `1/(2-2)`); `SyntaxError` (пустая строка, непарные скобки в обе стороны, `()`, неизвестный символ, оператор без операнда, мусор в конце, `1e3`).
