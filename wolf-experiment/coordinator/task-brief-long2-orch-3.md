# Task Brief LONG-002 / orch-3 — веб-фреймворк nanohttp

## Metadata

- **Задача:** LONG-002, итерация orch-3 (оркестрованный прогон, архитектурная)
- **Координатор:** Wolf (уровень 0)
- **Исполнитель:** executor-lead
- **Корень работ:** `long-task-002/orch-3/` (внутри `wolf-experiment/`)
- **Отчёт:** `executor/report-long2-orch-3.md`

## Task

Построить минималистичный веб-фреймворк **nanohttp** с нуля ПОЛНОСТЬЮ ПО
СПЕЦИФИКАЦИИ `long-task-002/orch-3/spec.md`.

**Спецификацию прочитать ЦЕЛИКОМ** — она определяет:

- 8 модулей с точными сигнатурами, поведением и edge cases;
- обязательную структуру пакета;
- Приложение A — 40 пунктов публичного API;
- Приложение B — обязательные тесты с точными именами;
- раздел «Пример использования» — должен работать.

Отклонение от спеки = провал задачи.

## Acceptance Criteria

1. Пакет `nanohttp/` + тесты `tests/` созданы внутри
   `long-task-002/orch-3/` строго по обязательной структуре из спеки.
2. Только stdlib Python (никаких внешних зависимостей).
3. Из каталога `long-task-002/orch-3` команда
   `python3 -m unittest discover -s tests -t .` — **все тесты зелёные**
   (включая все обязательные тесты из Приложения B с точными именами).
4. Все 40 пунктов публичного API из Приложения A реализованы.
5. Пример из раздела «Пример использования» спеки запускается и работает.
6. Проведено обязательное ревью воркером worker-reviewer; замечания
   устранены или обоснованно отклонены (с записью в отчёте).

## Constraints

### Декомпозиция (обязательна)

- Архитектурные компоненты (MEDIUM/COMPLEX) — отдавать воркерам.
- Тривиальное (константы, заглушки, простые структуры) — можно себе, но
  по минимуму; задача архитектурная, основная масса — воркерам.
- Декомпозицию оформить **таблицей** в отчёте: компонент → исполнитель
  (self/worker-N) → сложность → статус.

### Процесс

- Обмен с воркерами — только файлами (brief/отчёты/код), не пересказом.
- Воркеры не спавнят агентов.
- Тесты гонять до полностью зелёного состояния; красные тесты в финальном
  отчёте недопустимы (либо явная эскалация с причиной).
- Не выходить за пределы `wolf-experiment/`.
- Отметки tasklog: START/END (и PROGRESS на долгих этапах) — включить
  строки в отчёт.

### Отчёт

`executor/report-long2-orch-3.md` должен содержать:

- статус (DONE / PARTIAL / FAILED);
- таблицу декомпозиции (self vs воркеры);
- покрытие: API (x/40), обязательные тесты (x/y из Приложения B);
- вывод `python3 -m unittest discover -s tests -t .` (итоговая строка);
- результат ревью worker-reviewer;
- известные ограничения/отклонения от спеки (если есть).
