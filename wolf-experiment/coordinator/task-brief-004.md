# Task Brief 004 — Rate limiter для локального Python API (SPLIT-001, раунд B)

## Metadata

- ID: TEST-004 / SPLIT-001 раунд B
- Корень проекта: `wolf-experiment/`
- Код и тесты: только в `workers/`
- Новые файлы: `workers/rate_limiter_b.py`, `workers/test_rate_limiter_b.py`
  (существующие `rate_limiter.py` / `test_rate_limiter.py` **не трогать**)

## Task

Спроектировать rate limiter для локального однопроцессного Python API.

Требования:

- Лимит **N запросов за окно T секунд** на клиента (`client_id` — строка).
- Превышение лимита — исключение `RateLimitError`.
- Настраиваемые `N` и `T`.
- **Контекст масштаба: до 100 000 активных клиентов** — потребление памяти
  значимый фактор. **O(1) памяти на клиента предпочтительно**, но выбор за
  исполнителем.
- **Переживание рестарта процесса:** желательно (плюс), **НЕ обязательно**.
- **Строгость на стыке окон** (всплеск до 2N при fixed window): допустимая
  строгость — на усмотрение исполнителя, но своё решение и его цену
  **зафиксировать в trade-offs**.
- Только stdlib (**включая sqlite3**).
- unittest-тесты:
  - превышение лимита;
  - восстановление после окна;
  - независимость клиентов;
  - минимум 2 граничных случая на выбор исполнителя.

## Acceptance Criteria

1. `workers/rate_limiter_b.py` — реализация лимитера с `RateLimitError`.
2. `workers/test_rate_limiter_b.py` — unittest-тесты, покрывающие все 4
   пункта выше.
3. Все тесты проходят (`python -m unittest`).
4. Источник времени инъекционный: параметр `clock`, дефолт `time.monotonic`;
   реальные `sleep` в тестах запрещены.
5. Только stdlib.
6. Решение по строгости на стыке окон и его цена зафиксированы в коде
   (docstring/комментарий trade-offs).

## Constraints

- Алгоритм **НЕ фиксирован** — выбор за исполнителем.
- Хранилище **НЕ фиксировано** (in-memory, sqlite3 и т.п. — на усмотрение).
- Только stdlib.
- Не выходить за пределы `wolf-experiment/`.
