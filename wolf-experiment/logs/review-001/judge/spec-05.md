## 0. Правило ценности

**Самостоятельная** метрика входит в атлас ⟺ у неё есть строка в Decision
Table (C8). Новая сущность — только с operational definition (§3.11) и
QA-протоколом, показывающим обслуживаемую строку. **Диагностические
co-статистики** допускаются без отдельной строки DT — при условии, что явно
указана основная метрика/строка DT, которую они интерпретируют (пример:
`both_share` → `dir_ratio`; raw counts, sensitivity-варианты, QA-показатели
обслуживают свои основные строки). Co-статистика не порождает решение.

## 1. Главный вопрос

> Для каждой комбинации `direction × target × horizon` измерить доступность,
> частоту и календарную регулярность будущего движения, длительность
> потенциальных окон входа, порядок направленных касаний, время до исхода,
> глубину adverse excursion, время её наступления и совместное распределение
> favourable/adverse excursions.

Результат — **статистическое описание предложения движения и риска пути**.
Проектирование последующих компонентов в этот раунд не входит.

## 2. Граница

Исключено: капитал/маржа/плечо/ликвидация; размер позиции; портфельная
concurrency; precision/recall селектора; «прибыльность ячейки»; «подходит для
стратегии»; P(L∪S) как вероятность успеха направления; oracle-hit как ex-ante
признак; adverse-уровень как рекомендуемый stop.

### 3.2 Единицы и семантический контракт ядра (as-built; верифицировано в WП-0 — 6/6 PASS)

| Вход | `entry = close[t]` (mid, без спреда) |
| Окно исхода | бары `t+1 … t+h`; только при `h ≤ window_len` |
| `window_len` (внутр. `k_total`) | фактическая длина окна якоря: `min(H_max, бары до OOS-границы)`; не целевой уровень k |
| Касание | включительное, по `high`/`low`: bps(high) ≥ k для long-TP, bps(low) ≤ −k для short-TP |
| `fp_tau_{dir,k}` | первый tp-бар в **индексах баров**; **sentinel отсутствия = −1** (Int32-материализация: `np.where(isinf, −1)` в сборке корпуса). Правило потребителя: любое сравнение (`fp_tau ≤ h` и т.п.) допустимо **только после маски `fp_tau > 0`** — иначе все no-hit якори молча проходят фильтр и знаменатели завышаются до 100%. **Гранулярность (as-built, WП-0):** M1-точный при τ ≤ 7200 баров (`Z_FP_M1_MIN`); при τ > 7200 — **дневная (D1) решётка**: значение = граница дня, содержащего касание, ≥ точного t_tp (≤ 1 дня). | `mae/mfe/t_mae/t_mfe_{dir,h}` | экстремум/время на полном окне h (баров); sentinel времени = **−1** (горизонт за пределами `window_len`); при `h ≤ window_len` значения валидны |
| `mae_before_fp` | adverse-снимок в момент касания, включая touch-бар; NaN без касания; для разбиения исходов не используется (**as-built имя поля ядра; в анализе v4.2 соответствует `mae_through_touch_bar_bps` §3.4 — синоним, errata e34**) |
| `terminal_bps` | close правого края `window_len`; NaN при truncated |
| Data-gap бары | `dt > 1 мин` → классификация перехода (§3.13); из последовательности баров не удаляются |
| OOS | клип по `reserved_oos_start` (2025-08-04) в ядре; **WП-0 вердикт: бары после 2025-08-04 существуют локально (до 2026-08) и потреблялись ранними стадиями (Э1–Э3, scope=full_row; attempts до 2026-08-03) — программный holdout consumed; финальная валидация потребует нового prospective holdout. Корпуса c1*/atlas v4 хвост не читали** |

WП-0 проверил (6/6 PASS; протокол и вердикты —
`data/corpus/analysis_v4/wp0_semantic_audit.md`): единицы `fp_tau`/`window_len`/`h` и семантику `bar_id`; **sentinel:
доля строк с fp_tau = −1 в parquet совпадает с kernel-расчётом no-hit, и все
тесты-потребители начинают с маски `fp_tau > 0`**; шаг/плотность
ряда — **распределением дельт по всему ряду** (`ts.diff().value_counts()`), не
`head()` (урок L4); поведение через Friday→Monday (горизонт в наблюдаемых барах
не «тратится» на выходные — подтверждено); перевод h в календарную длительность;
равенство `t_tp_direct = fp_tau` — **в M1-зоне (τ ≤ 7200)** на всех
`dir × k` вне неоднозначных/пропущенных строк; в D1-зоне (τ > 7200) равенство
побитово невозможно по построению (корпусной `fp_tau` = граница дня, ≥
точного `t_tp`) — сверка эмуляцией правила записи корпуса (протокол WП-0 §3).

**Знаменатели ячеек.** Каждая (k, h) имеет свой валидный набор якорей
(`h ≤ window_len`): из-за усечения у правого края scope n различается между
горизонтами. n публикуется в каждой ячейке; меж-h сравнения — только с явными n.

### 3.3 touch_id и система координат баров

```
touch_row(t, dir, k) = row_index(t) + t_hit_{dir,k}(t)    # индексы баров
touch_id(t)          = timestamp[touch_row]               # lookup
```

`t_hit` — M1-точный `t_tp` прямого прохода §3.4 (единый источник касаний
всего раунда; наследует sentinel-конвенцию §3.2: −1 при отсутствии, маска
`t_hit > 0` до любого сравнения). Корпусной `fp_tau` — только кросс-чек в
M1-зоне τ ≤ 7200 (побитово, по образцу WП-0). Арифметика `timestamp + τ`
запрещена. **`row_index` — позиционный индекс в едином отсортированном ряду
наблюдаемых баров scope (том же, что читает ядро корпуса), НЕ календарный
`bar_id` корпуса** (урок L15: `bar_id` может быть календарным — арифметика
касаний только по позиционным индексам; семантику `bar_id` верифицирует WП-0
— подтверждена позиционная). Все таблицы анализа джойнятся по `timestamp`
либо по согласованному позиционному маппингу. **Входной инвариант ряда
(тест шага 1 WП-1; errata e11):** timestamp единого отсортированного ряда
**строго возрастает, дубликатов нет** — иначе `touch_id = timestamp[…]`
даёт коллизии, сортировка ряда нестабильна, touch-group conservation
нарушается молча; обнаружение дубликата — **стоп до разбора**, молчаливая
обработка (удаление/переименование строк) запрещена.

### 3.4 Прямой first-passage проход (основа C1/C4/C5)

Для каждого якоря t и пары (k, a) — проход по барам `t+1…t+h` с барьерами:

```
long:  tp = first j: high[j] ≥ entry·(1 + k/10⁴)
       adv = first j: low[j]  ≤ entry·(1 − a/10⁴)
short: tp = first j: low[j]  ≤ entry·(1 − k/10⁴)
       adv = first j: high[j] ≥ entry·(1 + a/10⁴)
```

**Зарегистрированная арифметическая конвенция реализации** (побитовая
совместимость с корпусом, WП-0 A3: 1 870 709/1 870 709): сравнение
выполняется в bps-форме `(x − entry)/entry·10⁴ ≥ lvl` — ровно как в ядре
корпуса (`_path_fp_tau_zone`); мультипликативная форма выше — математическое
определение барьера (в float64 на границе ULP формы могут расходиться;
канонической для кросс-чеков является bps-форма).

Два исходных поля (раздельные неоднозначности, не смешивать):

```
order_tp_adv (для C5):   TP_FIRST | ADV_FIRST | NEITHER | UNRESOLVED_TP_ADV
  (механическое правило, hit-маски и обязательные тесты — ниже,
  «Нормализация sentinel-времён»)
order_direction (для C1): LONG_FIRST | SHORT_FIRST | NEITHER | UNRESOLVED_LONG_SHORT
  по первым tp-барам двух направлений (k без a); совпадение бара → UNRESOLVED_LONG_SHORT
  (не зависит от a — считается один раз на k в том же проходе)
```

**Нормализация sentinel-времён (обязательна до любых сравнений; sentinel
никогда не участвует в сравнении времени как обычное число):**

```
t̃_tp  = t_tp  при t_tp  > 0;   +∞ при t_tp  = −1
t̃_adv = t_adv при t_adv > 0;   +∞ при t_adv = −1
```

**Механическая классификация** (единственный источник истины для классов;
только hit-маски, без сравнения sentinel'ов):

```
tp_hit  = 0 < t_tp  ≤ h          # эквивалентно t̃_tp  ≤ h
adv_hit = 0 < t_adv ≤ h          # эквивалентно t̃_adv ≤ h

if tp_hit and adv_hit and t_tp == t_adv:        UNRESOLVED_TP_ADV
elif tp_hit  and (not adv_hit or t_tp < t_adv): TP_FIRST
elif adv_hit and (not tp_hit  or t_adv < t_tp): ADV_FIRST
else:                                           NEITHER
```

Обязательные тесты (шаг 1 WП-1): (t_tp=−1, t_adv=−1) → NEITHER;
(t_tp>0, t_adv=−1) → TP_FIRST; (t_tp=−1, t_adv>0) → ADV_FIRST; (равные
положительные) → UNRESOLVED_TP_ADV; свойство «sentinel не проходит ни одно
сравнение» — ни один no-adverse якорь не попадает в множество A §3.10, ни
один no-hit якорь — в H_resolved §3.9; кейс no-hit для pre-touch полей
(errata e7): при t_tp = −1 — `pre_touch_mfe_bps`, `pre_touch_mae_bps`,
`t_pre_touch_mae` = NaN, `pre_touch_window_empty` = false; чтение pre-touch
полей — только под hit-маской `0 < t_tp ≤ h`.

Накапливаемые величины прохода (для C4/C5; **знаковая конвенция: MAE-поля
со знаком ≤ 0; для DT/квантилей используется `adverse_depth_bps = −mae ≥ 0`**):
`t_tp` (первый tp-бар) для time-to-hit; `t_adv` (первый adv-бар — нужен
терцилям §3.9); `mae_through_touch_bar_bps` (signed, running adverse через
конец tp-бара); **pre-touch-поля — строго по барам `t+1 … t_tp−1`** (target-бар
исключён — эти величины описывают путь ДО касания и не сравниваются с
through-touch): `pre_touch_mfe_bps`, `pre_touch_mae_bps` (signed, ≤ 0),
`t_pre_touch_mae` (бар adverse-экстремума до tp: **running min для long,
running max для short**; sentinel −1), `pre_touch_window_empty` (маска пустого
интервала; пусто ⟺ `t_tp = 1`). **Семантика пустого pre-touch интервала
отделена от нулевой экскурсии:** 0.0 — содержательное значение «путь
наблюдался, adverse-экскурсии не было»; при пустом интервале вычислительный
массив может хранить 0.0/NaN, но **публикация обязана давать null**, маска
`pre_touch_window_empty` обязательна в артефакте **или выводится
потребителем по тождеству `(t_tp = 1)` (errata e51)**. `touch_bar_adverse_bps`
(≥ 0; adverse-экстремум самого tp-бара относительно entry). `UNRESOLVED_LONG_SHORT` —
отдельно per k. На tp-баре favourable ≥ k
известен по определению касания и не смешивается с pre-touch-полями.
Same-bar неоднозначность per (k,a): **источник истины** —
`order_unresolved_tp_adv[dir,k,a] = tp_hit ∧ adv_hit ∧ (t_tp = t_adv)`
(сравнение только положительных времён; hit-маска обязательна — без неё
поля touch-бара не читаются). Формула через накопленные поля — **проверочный
инвариант** (storage-agnostic, с обязательной маской пустого интервала):
`pre_adverse_below_a = pre_touch_window_empty ∨ (−pre_touch_mae_bps < a)`;
`1[order_unresolved_tp_adv] = 1[tp_hit ∧ adv_hit ∧ touch_bar_adverse_bps ≥ a
∧ pre_adverse_below_a]` (для hits; тест шага 1 WП-1; пустой pre-touch без
дизъюнкции даёт ложное нарушение: `−NaN < a` = False).

Граничные правила: касание включительное; adv ровно на последнем баре окна у
no-hit → ADV_FIRST с пометкой (**флаг `adv_at_window_edge ≡ (t_adv = h)` —
материализация в fp-артефакте или производная потребителя (e51);
t_adv = h; публикуется в C5; errata e34**); no-hit с adv в окне → ADV_FIRST.

### 3.5 Направленные окна (touch groups)

`W(τ; k, h, dir) = {t : t_hit_{dir,k}(t) ≤ h ∧ touch_id(t) = τ}` (после маски
`t_hit > 0`; источник касания — M1-точный `t_hit` прямого прохода §3.4 для
всех h, включая h=10080; корпусной `fp_tau` за пределами 7200 баров имеет
дневную гранулярность и непригоден как точный touch — кросс-чек только в
M1-зоне). Поля
группы: `direction, k, h, touch_id, touch_row, first_anchor, last_anchor
(row_index), span_first_to_last = last_anchor_row − first_anchor_row,
`gross_span_to_touch_bars = touch_row − first_anchor + 1` (gross-протяжённость
до касания: включает неуспешные якори, внутренние разрывы и периоды
отсутствия возможности — **не мера доступного времени**; доступное время —
`n_successful_anchors`, `longest_contiguous_run`, `contiguous_run_count`),
`n_successful_anchors, contiguous_run_count` (число максимальных серий
подряд идущих anchor row_index), `longest_contiguous_run`,
`is_contiguous` (⟺ `contiguous_run_count = 1`). Интерпретация
непрерывности — только по `longest_contiguous_run`/`is_contiguous`.

### 3.6 Задержка наблюдения — три метрики

`delayed_row = row_index(t) + δ_bars`, δ ∈ {5, 15, 60} баров. Проверки:
delayed_row в scope, не в OOS, `window_len(delayed) ≥ h`, иначе строка
исключается из знаменателя (с публикацией доли исключённых).

```
same_touch_survival          = 1[ delayed_row < touch_row(t)
                                   ∧ touch_id(delayed_row) = touch_id(t)
                                   ∧ 0 < t_hit(t+δ) ≤ h − δ ]
original_horizon_survival    = 1[ 0 < t_hit(t+δ) ≤ h − δ ]  # остаток исходного окна
renewed_horizon_availability = 1[ 0 < t_hit(t+δ) ≤ h ]      # новое полное окно
```

(`t_hit` — M1-точный источник §3.3 на всех h; маска `0 < t_hit` обязательна:
sentinel −1 у no-hit delayed-якоря иначе даёт ложное «выживание».)

Проверяемый инвариант same-touch (тест WП-1): для выживших
`t_hit(t+δ) = t_hit(t) − δ` (то же касание из отложенного входа — ровно на
δ баров ближе; выполняется без ограничения M1-зоной — выводится из
first-passage-построения). Явная проверка `≤ h−δ` дублирует
first-passage-гарантию, делая контракт проверяемым.

Уточнения семантики: `touch_id(delayed_row)` определён только для успешного
delayed-якоря (`0 < t_hit ≤ h`) — иначе индикатор = 0. t_hit(delayed)
считается от **своего** входа `close[t+δ]`: все три метрики отвечают
«достижима ли цель k из отложенного наблюдения», а не «исходная сделка всё
ещё в плюсе».

Знаменатель всех трёх — успешные якори (`0 < t_hit ≤ h`) с валидным
delayed_row;
доля исключённых из-за невалидного delayed_row публикуется. Три метрики не
взаимозаменяемы; `renewed_horizon` систематически мягче
`original_horizon` и публикуется только вместе с ним.

### 3.7 Балансы направлений (годовые)

`B_only = onlyL/(onlyL+onlyS)`; `B_marginal = P(L)/(P(L)+P(S))`;
`B_first = P(L first | L first ∨ S first)` — по `order_direction` (§3.4).
**Определения (errata e25):** `onlyL = #{t: 0 < t_hit_long ≤ h ∧
t_hit_short = −1}` — якоря ячейки (k,h) с единственным long-hit;
`onlyS` — зеркально; `P(L)`/`P(S)` — маргинальные hit-вероятности §3.8.

**Уровни (по определимости):** `B_first` — **только якорный уровень** (long и
short сравниваются для одного входа). Touch-group показатель — **другая
величина с отдельным именем**:

```
B_touch_group_direction = N_long_groups / (N_long_groups + N_short_groups)
```

— баланс **количества направленных touch groups** (k,h), не first-touch
вероятность; прямо с якорным `B_first` не сравнивается. Причина: long- и
short-группы строятся независимо, один рыночный участок может породить обе.
Episode-level first-touch потребовал бы сопоставления long/short-групп с общим
объектом — такого сопоставления в v4.2 нет (отложено). B_only/B_marginal —
якорный уровень. `both` не подмешивается. Годы: 2022–2024 полные,
2021ᵖ/2025ᵖ помечены; вывод — raw + min–max range.

### 3.8 Обработка неоднозначностей — bounds-атрибуция

Вид bounds зависит от типа estimand (формула «P+U» верна только для простых
долей с фиксированным знаменателем):

- **Простые доли — только порядковые estimands с фиксированным знаменателем**
  (`P(L first)`, `TP_FIRST`, `ADV_FIRST` и производные): `P_pessimistic =
  P(X)`, `P_optimistic = P(X) + P(UNRESOLVED_X)`.
- **Доли с U-зависимым знаменателем (класс «отношения»):** `share_of_hits_heavy`
  и терцильные доли §3.9 — атрибуция same-bar U меняет числитель **и**
  знаменатель. Корректные границы (три величины, все публикуются):
  ```
  share_resolved = |B| / |H_resolved|                     # точка по разрешённым
  share_min      = |B| / (|H_resolved| + |U|)             # все U → clean
  share_max      = (|B| + |U|) / (|H_resolved| + |U|)     # все U → heavy
  ```
  (`share_resolved` — НЕ нижняя граница: она выше `share_min`, т.к. её
  знаменатель меньше; `|H_resolved| = |TP_FIRST|+|B|`.) Терцильные доли:
  точечная = `|B_i|/|A_i|` (U исключены — строгое определение A);
  `P_min,i = |B_i|/(|A_i|+|U_i|)`, `P_max,i = (|B_i|+|U_i|)/(|A_i|+|U_i|)`,
  где `U_i` — same-bar hits, назначенные терцилям **по границам тех же
  терцилей A** (`t_adv` ниже границы Q1 → Q1, выше границы Q3 → Q3 —
  клампинг; Σ|U_i| = |U|); интервал терцильной строки DT — `[P_min,i,
  P_max,i]` для Q1 и Q3. Для `eventual_target_after_adverse` bounds
  `|B|/|A| ≤ p ≤ (|B|+|U|)/(|A|+|U|)` корректны: при атрибуции U →
  TP-before-ADV они не входят ни в A, ни в B; при ADV-before-TP — в оба.
- **Маргинальные hit-вероятности публикуются точечно, без bounds:**
  `P(L), P(S), P(L∪S), P(L∩S)` — факт long/short-hit известен даже при
  `UNRESOLVED_LONG_SHORT` (неопределён только порядок сторон); неоднозначность
  порядка не меняет маргиналы.
- **Балансы-отношения** (`B_first = |L|/(|L|+|S|)`, `B_only`): экстремальные
  атрибуции неоднозначных считаются явно, обе стороны:
  `B_min = |L| / (|L|+|S|+|U|)` (все U → не-L) и
  `B_max = (|L|+|U|) / (|L|+|S|+|U|)` (все U → L). Публикуются B_min/B_max,
  а не точка.

Раздельно для `UNRESOLVED_TP_ADV` (в C5) и `UNRESOLVED_LONG_SHORT` (в C1/C3).
Гейт: если bounds-атрибуции дают разные выводы Decision Table — фиксируется
«разрешения данных недостаточно». Абсолютные доли обоих видов публикуются по
(k, h, a, dir).

### 3.9 Гейт исследования временной структуры пути

Две метрики (третьих имён нет; множества A, B — §3.10) + разбивка по терцилям
времени пересечения:

```
H_resolved = {t̃_tp ≤ h  ∧ t̃_tp ≠ t̃_adv}     # разрешённые hits (same-bar исключены; t̃ — §3.4, sentinel → ∞)
share_of_hits_heavy          = |B| / |H_resolved|   # доля разрешённых hits с adverse-first путём
eventual_target_after_adverse = |B| / |A|           # чем кончается adverse-first
```

Инвариант: `H_resolved = TP_FIRST ⊎ B` (дизъюнктное объединение) —
проверяется тестом. Знаменатель однозначен: TP_FIRST здесь — класс данного
adverse-уровня a, H_resolved собирает его с B.

По терцилям `t_adv` (границы — квантили t_adv по полной выборке A данной
ячейки (k,h,a,dir)): `P(t_tp ≤ h | t_adv ∈ Q_i)` с raw
знаменателями, медианным remaining horizon (**median(h − t_adv) по якорям
терциля A_i**; errata e34) и bounds §3.8. Различие условных
долей между терцилями — прямое свидетельство, что момент пересечения важен.
Решение о dynamic path surface принимается по обеим метрикам, терцилям и raw
counts.

### 3.10 Множества (строгие определения)

Конвенция: перед определением множеств применяется нормализация §3.4
(`t̃ = +∞` при sentinel −1; sentinel не участвует в сравнениях как обычное
число); same-bar TP/ADV
неоднозначность исключается из обоих множеств и публикуется отдельно:

```
A = {t̃_adv ≤ h  ∧ t̃_adv < t̃_tp}       # adverse пересечён до tp (tp мог не наступить)
B = {t̃_adv < t̃_tp ≤ h}                # adverse раньше, target достигнут в окне
eventual_target_after_adverse = |B| / |A|
```

Обязательные co-статистики: |A|, |B| raw; определение пересечения (§3.4);
направление; тег `oracle_path_conditional`; предупреждение «время пересечения
не учитывается — не является вероятностью восстановления в реальном времени».

### 3.11 Movement episodes — FSM (полный псевдокод)

Параметры определения (не путать):

```yaml
movement_scale_bps: k          # масштаб исследуемой цели
reversal_threshold_bps: r     # порог подтверждения разворота
qualifying_amplitude: amplitude ≥ k   # НЕ зависит от r
episode_definition_id: zigzag_reversal_v1_k{k}_r{r}
zigzag_same_bar_policy: unresolved   # внутрибарный порядок high/low не разрешается
```

Базовое определение D₀: `r = k`. Sensitivity: `r ∈ {0.5k, k, 2k}` при
квалификации `≥ k` всегда; известные смещения оговариваются в отчёте (r=0.5k —
больше мелких разворотов; r=2k — движения амплитуды [k, 2k) могут пропускаться);
при кратном изменении счёта публикуется диапазон.

```
Нормировка (единая для всего FSM, обобщение §3.2 «bps к явному ref»; все
сравнения включительные ≥, float64, без округления):
  развороты — bps к опорному экстремуму текущего направления;
  амплитуда — bps к start_price (началу ноги).

INIT (порядок на каждом баре j — как в TRACKING: сначала обновить, потом
проверять): (1) hi = max(hi, high[j]), lo = min(lo, low[j]) (с row; при
равенстве — БОЛЕЕ РАННИЙ row); (2) проверка первого подтверждения:
    UP-гипотеза:   bps = (high[j]/lo − 1)·10⁴ ≥ r   (ref = lo) → сегмент UP, старт = lo.row
    DOWN-гипотеза: bps = (1 − low[j]/hi)·10⁴ ≥ r    (ref = hi) → сегмент DOWN, старт = hi.row
    оба условия на одном баре j:
      hi.row ≠ lo.row → детерминированно сегмент от БОЛЕЕ РАННЕГО экстремума;
      направление зависит от неизвестного внутрибарного порядка high/low
      (в т.ч. hi.row == lo.row) → состояние INIT_UNRESOLVED: направление не
      назначается; hi/lo продолжают обновляться; выход — первое однозначное
      подтверждение; если не наступило до края данных — весь лид-ин censored
TRACKING (направление UP; DOWN зеркально); на каждом баре j строго по порядку:
  (1) обновить running-экстремум: high[j] > ext → ext = high[j], ext_row = j;
      при равенстве high[j] == ext — сохраняется БОЛЕЕ РАННИЙ экстремум
      (детерминизм);
  (2) проверить подтверждение: reversal_bps = (1 − low[j]/ext)·10⁴ ≥ r
      (DOWN зеркально: (high[j]/ext − 1)·10⁴ ≥ r);
      если подтверждение произошло на баре, который сам обновил экстремум
      (ext_row == j), — внутрибарный порядок high/low неизвестен → эпизод
      получает флаг episode_order_unresolved = true (в основной счёт не
      входит, учитывается в ledger-счётах `flagged_episode_count` /
      `count_if_flagged_included` и в sensitivity-range ниже; errata e35);
  if подтверждено:
    сегмент закрывается: episode = {dir UP, start_row, start_price (= цена
    экстремума предыдущего сегмента), ext_row, ext_price, confirm_row = j,
    amplitude_bps = (ext_price/start_price − 1)·10⁴  (DOWN: (1 − ext/start)·10⁴),
    qualifying: amplitude_bps ≥ k}
    новый сегмент DOWN: start = ext (row/price);
    бар j принадлежит НОВОМУ сегменту (low[j] обновляет его running min);
    НЕ БОЛЕЕ ОДНОГО подтверждения на бар — следующий reversal
    подтверждается только с бара ≥ j+1;
Overshoot/гэп через несколько уровней: обрабатывается естественно (амплитуда
  поглощает; счёт консервативен из-за «одно подтверждение на бар»);
Данные: FSM идёт по наблюдаемым M1-барам scope; data-gap/weekend бары не
  сбрасывают состояние; переходы классифицируются отдельно (§3.13);
Края: первый бар — INIT; последний незавершённый сегмент — censored,
  не считается (учитывается отдельным счётчиком);
OOS: только бары train ∪ val.
```

Поля эпизода: direction, start/confirm/extremum (row, price, timestamp —
extremum timestamp хранится отдельно), `duration_bars = ext_row − start_row`
(движение; co-поле `confirm_delay_bars = confirm_row − ext_row`; календарная
длительность — по timestamps тех же row), `amplitude_bps` (выше),
`overshoot_bps = reversal_bps(confirm_row) − r ≥ 0` (UP:
`(1 − low[confirm_row]/ext)·10⁴ − r`; DOWN: `(high[confirm_row]/ext − 1)·10⁴ − r`),
год/месяц. **Дата атрибуции эпизода к календарному периоду (поля год/месяц,
концентрации топ-1 года/квартала C2a, `episodes_per_year` DT) — календарная
дата extremum timestamp** (errata e13; согласована с определением active
days supply — по дате extremum), фиксируется в полях эпизода. Публикация:
«**distinct episodes under
definition D**»; запрещены «независимые движения/выборка/N_eff=episodes».
`episodes/year` — всегда с `episode_definition_id`.

`inter-arrival` — по **confirmation timestamp** (наблюдаемый ledger);
`active days` supply — по дате **extremum**; `active days` availability (C2b) —
по дате **anchor**. Все три фиксируются в артефактах. Определения:
**пустой месяц** (availability) — календарный месяц без единого активного дня;
(supply) — месяц без единого эпизода под D; **концентрация** (C2a) — доля
эпизодов топ-1 календарного года и топ-1 квартала.

QA до массового расчёта — два раздельных протокола:

1. **Implementation QA (0 расхождений):** ручной пошаговый прогон формального
   FSM (включая INIT_UNRESOLVED и episode_order_unresolved) на каждом
   фрагменте должен совпасть с выводом кода **точно** — это проверка
   правильности реализации, расхождения недопустимы.
2. **Face-validity QA (±1):** независимый визуальный подсчёт swing'ов ≥ k
   (разметка человеком по инструкции WП-1) сравнивается со счётом эпизодов;
   расхождение ≤ ±1 на фрагмент либо **объясняется конкретным правилом
   определения** — оно измеряет зазор между operational definition и
   человеческой интуицией, а не ошибку кода. **Фиксация (errata e16):** в
   QA-артефакт заносятся row-диапазоны выбранных фрагментов, версия
   инструкции разметки и каждое объяснение расхождения с указанием конкретного
   правила FSM; объяснение принимается пользователем (как §10.1), молчаливое
   прохождение гейта запрещено.

Фрагменты: 5 типов по формальному критерию (спокойный / тренд / волатильность
/ крупный гэп / незавершённый на краю); на каждом — какие эпизоды выделены,
причины старта/завершения, overshoot, соотношение эпизодов разных k,
привязанные touch groups.

**Публикация счёта при `zigzag_same_bar_policy: unresolved`.** Помеченный
эпизод меняет не только свой статус, но и последующую сегментацию (старт
следующей ноги, экстремум, будущие подтверждения) — две формы учёта
flagged-записей в одной operational-сегментации **не являются** границами
допустимого числа эпизодов. Слова «pessimistic/optimistic bounds» запрещены.
Схема публикации:
- основной ledger (политика unresolved): `resolved_episode_count`,
  `flagged_episode_count`, `count_if_flagged_included` — три именованных
  счёта, без интерпретации как min/max;
- **sensitivity-range:** две полные FSM-траектории с глобальными конвенциями
  `high_first` и `low_first` (каждая неоднозначность разрешается выбранной
  конвенцией, дальше — детерминированно); публикуется диапазон счётов двух
  конвенций (не probabilistic CI, не «рыночный порядок»); при кратном
  расхождении — только диапазон. Диапазон двух глобальных конвенций **не
  гарантирует покрытия всех локальных комбинаций внутрибара-порядка и не
  является границей (min/max) истинного episode count**.

### 3.12 Episode–window matching (для C2c)

Для touch group (τ, dir, k) и определения D:

1. НОГА эпизода (оба направления одинаково): `[start_row, ext_row]` — от
   экстремума-старта до экстремума-финиша. Касание сопоставляется эпизоду,
   чья нога содержит `touch_row(τ)` **и** направление совпадает
   (long-touch ↔ UP, short ↔ DOWN). **Матчинг к любой ноге** (не только
   qualifying): внутри UP-ноги цена может откатиться ниже `start_price` без
   подтверждения разворота — якорь ниже старта всё равно даёт k-касание
   относительно `entry=close[t]`, поэтому `touch of k ⇏ leg amplitude ≥ k`
   (разные базы: target к entry, амплитуда к start_price; инвариант не
   утверждается).
2. Внутри одного определения ноги не перекрываются (кроме граничного ext_row,
   где направление разрешает неоднозначность) → максимум один эпизод на группу.
3. Состояния матча (полное разбиение, все публикуются в C2c):
   `matched_qualifying` (нога qualifying, amplitude_bps ≥ k) ·
   `matched_nonqualifying` (нога-служба < k — **полезная статистика**
   расхождения anchor-relative и swing-start-relative масштабов, не QA-ошибка) ·
   `init_or_censored` · `direction_mismatch` · `unresolved_episode` ·
   `unmatched` — итого **шесть взаимоисключающих исходов** (partition-тест §4
   ждёт сумму долей = 1 по шести категориям). **Формальные предикаты
   (errata e26; матч-кандидат = эпизод, чья нога направления группы содержит
   `touch_row`; при отсутствии кандидата применяется первый подходящий
   предикат в порядке приоритета):** `matched_qualifying` = кандидат
   существует ∧ направление совпадает ∧ `amplitude_bps ≥ k`;
   `matched_nonqualifying` = кандидат существует ∧ направление совпадает ∧
   `amplitude_bps < k`; `unresolved_episode` = единственные кандидаты —
   эпизоды с флагом `episode_order_unresolved = true`;
   `init_or_censored` = `touch_row` лежит в лид-ине состояния INIT
   (включая INIT_UNRESOLVED) либо в censored-хвосте края данных;
   `direction_mismatch` = кандидаты есть только противоположного направления
   (нога long ↔ группа short или наоборот); `unmatched` = ни один предикат
   выше не применим (нет пересекающих ног). Детерминированный приоритет при
   нескольких применимых причинах: `unresolved_episode` → `init_or_censored`
   → `direction_mismatch` → `matched_qualifying`/`matched_nonqualifying` →
   `unmatched`.
4. Связь хранится покомпонентно: `episode_definition_id` → набор (episode,
   touch groups); разные sensitivity-варианты не смешиваются.
5. Топ-K-концентрация coverage (C2c) считается по вкладам **qualifying**
   эпизодов; `matched_nonqualifying`-группы публикуются отдельной долей
   (`nonqualifying_touch_share`) и в топ-K не входят.

### 3.13 Gap ledger (directional)

- Для **всех** соседних наблюдаемых баров: `signed_gap = open[t] − close[t−1]`
  (в bps к `close[t−1]`); публикуются signed / absolute / `adverse_long =
  max(0, −gap)` / `adverse_short = max(0, +gap)`.
- Тип перехода (флаги, не условие существования): `elapsed_time`,
  `is_regular_next_bar` (dt ≤ 1 мин), `crosses_weekend` (переход через ≥1
  календарный Sat/Sun — чисто календарно), `crosses_configured_holiday`
  (только по версионированному календарю праздников; календарь не определён —
  флаг не используется, слово «праздник» не употребляется),
  `long_elapsed_gap` (dt > 1 мин без weekend-перехода — data-gap).
- Пороги событийности для таблиц: bps {22, 50, 75}, ATR(H1) {1, 2}, квантили
  q95/q99 (**база квантилей — `|signed_gap|` по всем соседним наблюдаемым
  переходам train ∪ val; gap-событие порога P = переход с
  `|signed_gap| ≥ P`; errata e32**); один timestamp бара = одно событие. ATR-кратности — ATR(H1)
  **закрытого** H1-слота, предшествующего бару (конвенция B0), отдельный
  metric_id. **Построение H1-слотов (errata e12; регистрируется, два
  реализатора обязаны совпасть):** слот = **календарный час** по
  календарю ряда (не агрегат 60 наблюдаемых баров); полнота слота = 60
  наблюдаемых M1-баров внутри календарного часа; неполный слот (data-gap)
  ATR не порождает; если предшествующего **полного** H1-слота нет
  (начало ряда / серия гэпов) — событие **не классифицируется по
  ATR-порогам** (по bps/квантильным порогам — классифицируется),
  учитывается отдельным счётчиком в манифесте. **ATR(H4) (errata e29):**
  строится по тому же образцу — календарный **4-часовой** слот, полнота =
  240 наблюдаемых M1-баров, неполный/отсутствующий слот — события по
  ATR(H4)-порогам не классифицируются (счётчик в манифесте); кратности
  {1, 2}; значения словаря `gap_threshold`: `atr_h4_x1` \| `atr_h4_x2`,
  координата metric_id `.atr_h4`.
- Связь с окнами — два варианта, публикуются оба (границы — позиционные
  индексы баров; gap-переход индексируется правым баром `open[t] − close[t−1]`):
  `gap_in_group_span`: переход (b−1, b) принадлежит, если
  `first_anchor_row < b ≤ touch_row`; `gap_in_successful_anchor_path`:
  `anchor_row < b ≤ touch_row` для хотя бы одного успешного якоря группы
  (Friday→Monday-переход на touch-баре включён; до первого якоря — исключён).
  Span-ассоциация не выдаётся за непрерывную экспозицию.

якорь ровно в одной группе; Σ `n_successful_anchors` = числу успешных якорей
(k,h,dir)); |B| ≤ |A| ≤ n; доли ∈ [0, 1].

**Проверки-инварианты раунда** (тесты WП-1/WП-2, нарушения — в QA ledger
с объяснением):

- *First-passage partition:* `N_TP + N_ADV + N_NEITHER + N_UNRESOLVED = N_valid`
  для каждой (k,h,a,dir).
- *Direction partition:* `N_L + N_S + N_NEITHER + N_UNRESOLVED_LS = N_valid`
  для каждой (k,h); N_L/N_S — first-touch-классы, не маргинальные hits.
- *Delay monotonicity:* для якоря `same_touch ≤ original_horizon ≤ renewed`;
  агрегированно `P(same) ≤ P(original) ≤ P(renewed)`.
- *Adverse monotonicity:* для a₁ < a₂: `P(TP before ADV_a1) ≤ P(TP before
  ADV_a2)`; допустимые расхождения — только от same-bar bounds, объясняются.
- *Horizon monotonicity:* для h₁ < h₂ **на общем валидном наборе якорей**
  (`h₂ ≤ window_len`): `P(hit_h1) ≤ P(hit_h2)` — сравнение только на общем
  наборе, иначе разные правые края дадут ложное нарушение.
- *Touch-group conservation:* все якоря группы имеют один `touch_id`;
  `touch_row − anchor_row = t_hit` (источник §3.3; кросс-чек с корпусным
  fp_tau — только в M1-зоне τ ≤ 7200); якорь не встречается
  в двух группах одного (dir,k,h).
- *Zigzag matching:* каждый touch group имеет ровно одно из **шести**
  состояний §3.12(3) (сумма долей по шести категориям = 1);
  для matched: направление совпадает, `start_row ≤ touch_row ≤ ext_row`;
  **не более одного matched-эпизода на группу (§3.12(2)); один эпизод
  может матчить несколько групп — перекрытие вкладов в топ-K устраняется
  подсчётом по уникальным успешным якорям, без двойного счёта (errata
  e37)**.

### 4.1 Decision Table (C8) — трёхисходная, пороги прeregistered

Правила чтения: (1) зоны фиксированы **до расчётов** (могут быть изменены
пользователем до WП-2, не после просмотра чисел); (2) для величин с bounds
сравнение состоялось ⟺ bounds-интервалы **не перекрываются** — иначе
`inconclusive`; **перекрытие = непустое пересечение замкнутых интервалов
(errata e17): совпадение граничной точки (P_max,i = P_min,j) — перекрытие →
`inconclusive`**; (3) действие при `inconclusive`/переходной зоне — публикация
значений и ранжирования дескриптивно, решение переносится до появления
внешнего критерия; (4) **замкнутость зон:** граничные значения числовых
порогов принадлежат **переходной зоне**, крайние зоны — строгие неравенства,
сравнение по неокруглённому float64; (5) **маломощные ячейки:** `n_raw < 30`
— абсолютный минимальный stop-rule (оценка публикуется с
`support_status = insufficient`, в DT — `inconclusive`); поверх него действуют
специализированные критерии: хвосты — §5.5; терцили — `|A_i| ≥ 30` каждого;
отношения — ненулевой знаменатель и его размер; годовые сравнения — поддержка
в каждом полном году. **Единое правило нулевого знаменателя отношений
(errata e14):** знаменатель = 0 (`share_resolved` при |H_resolved| = 0;
`share_min/max`, терцильные доли при |A_i|+|U_i| = 0; `B_only`/`B_marginal`
при zero-hit ячейке; `B_first`/`B_touch_group_direction` при нуле
соответствующих объектов) → estimate = null, `support_status =
insufficient`, зона DT — `inconclusive`; замена нуля неявной константой
запрещена. **Распространение на все строки DT и пустые множества
(errata e27):** то же правило действует для любой строки DT при нулевом
знаменателе или пустом множестве наблюдений — `dir_ratio` (P(either) = 0),
`both_share`, `tp_first_ratio` (N(hit) = 0), `surv60`,
`mae_p90_over_k` (пустое множество hits — квантиль не определена),
`max_slice_top10_coverage_share`, `top_year_share` (0 gap-событий),
`range_B` (0 полных лет). **Известное отклонение прототипа (errata e48):
`supply/wp2_cells.py` (`_ratio`, `c1_cell`, `TercileStats`) возвращает 0.0
при нулевом знаменателе — при реализации WП-2 обязательное приведение к
настоящему правилу (null + insufficient), 0.0 как замена нуля запрещена.**
При n = 0 инварианты разбиения тривиально истинны,
доли не публикуются (NaN к публикации запрещён). Единая нотация числовых
строк: нижняя и верхняя зоны — строгие
неравенства (`<` / `>` по неокруглённому float64), переходная зона —
замкнутый интервал `[lo, hi]`, содержащий обе границы; для строк с
предикатными (составными) условиями зоны задаются предикатами и обязаны
образовывать разбиение; целочисленные пороги (Σ пустых месяцев)
интерпретируются как записано («≥ 6» — нижняя зона) — правило границ
применяется к непрерывным величинам; (6) **частичные годы (errata e33):**
календарные предикаты DT (`active_days_share`, Σ пустых месяцев),
концентрации C2a/C7 (`top_year_share`, топ-1 год/квартал) и годовые
агрегаты считаются **только по полным годам 2022–2024**; 2021ᵖ/2025ᵖ
публикуются с пометкой, в предикаты и концентрации не входят;
«мин по 2022–24» в колонках агрегации = минимум по трём полным годам.

## 5. Inference (протокол, не финальная процедура)

До пилота фиксируется только протокол; основная процедура выбирается после
WП-2 по опубликованным сравнениям:

1. **Якорные/групповые вероятности (C1, C3, C5) — метод A (фиксируется до
   WП-2):** **ресэмплинг совместного временного ряда уже вычисленных
   anchor-level исходов вместе с их валидностью**:
   `Z_t = (Y_t, window_len_t, V_360(t), V_1440(t), V_10080(t))`, где
    `Y_t = {order_tp_adv, order_direction, mae-поля, …}`;
    **точный состав `Y_t` (errata e39) — все per-anchor поля fp-артефакта
    §8** (`t_tp[dir,k]`, `t_adv[dir,k,a]`, `mae_through_touch_bar_bps`,
    pre-touch-поля + маска, `touch_bar_adverse_bps`, `mae_window_bps`,
    `mfe_window_bps`, `terminal_bps`, `window_len`; перечень расширяется
    только новой ревизией контракта модуля);
    ресэмплируются блоки вектора `Z`; labels и маски на границах блоков **не
   пересчитываются и не обрезаются**; **ценовые блоки не склеиваются**
   (пересборка пути — метод B — не используется). **Маски перемещаются
   вместе со своими якорями**: применять к переставленной реплике маску,
   оставшуюся в исходном временном порядке, запрещено.
   **Вселенная ресэмплинга — полный упорядоченный ряд всех якорей scope
   (N = 1 507 711, WП-0 keys; бары 0…1 507 710), с per-ячейковыми масками внутри каждой реплики**:
   `V_h(t) = 1[window_len_t ≥ h]`. Primary estimand — собственная валидная
   поддержка ячейки (`V_h`): point estimate и bootstrap distribution относятся
   к одному estimand. Common-support-срез (`V_10080`, N = 1 497 646)
   публикуется **отдельно** как sensitivity — только для прямых меж-h
   сравнений. Один joint block draw обслуживает все long/short × (k,h,a);
   каждая метрика внутри draw считается по своей маске на соответствующих
   позициях реплики.
   **Алгоритм (MBB, moving-block с перекрытием):** (1) candidate-блоки — все
   `Z[s:s+ℓ]`, s = 0…N−ℓ (`candidate_block_starts = N − ℓ + 1`);
   (2) draw `ceil(N/ℓ)` стартов блоков с возвращением;
   (3) конкатенация; (4) усечение реплики до длины N; (5) вычисление метрик
   по маскам `V_h`, перенесённым вместе с якорями. Никаких
   «отбрасываний последнего блока» (это не-MBB) и wrap-around нет.
   **2000 реплик, seed=42** — в манифесте.
   **Параметры блоков (в манифесте, не в строке записи; поле `n_blocks` из
   схемы записи удалено):** `block_length`; `candidate_block_starts =
   N − ℓ + 1`; `drawn_blocks_per_replicate = ceil(N/ℓ)`;
   `nonoverlap_equivalent_blocks = floor(N/ℓ)` (только диагностически).
   Sensitivity: ℓ ∈ {h_max, 2·h_max, 4·h_max} = {10080, 20160, 40320}
    → drawn ≈ 150/75/38 реплик-блоков (**ceil(N/ℓ)**; errata e54 —
    37 = `nonoverlap_equivalent_blocks = floor(N/ℓ)`, только
    диагностически и в §5.5).
   **Публикуются раздельно:** `bootstrap_se` = std оценок по репликам
   (sampling uncertainty); `bootstrap_ci_lo/hi` — перцентили реплик;
   `bootstrap_mcse` — с указанием точного объекта: `mcse_of_bootstrap_mean =
   sd(θ*)/√B` — только для бутстреп-среднего реплик mean-like статистик;
   для самой `bootstrap_se` — `mcse_of_se ≈ SE/√(2(B−1))`; для перцентильных
   CI-эндпоинтов и хвостовых квантилей `sd/√B` **не применяется** — только
    binomial ранговая неопределённость (или повтор с 3 seeds — **seeds
    зафиксированы: 42/43/44**, errata e15; основной метод — ранговый
    binomial CI, повторы seeds — при его неприменимости к данной
    статистике; выбор фиксируется в манифесте до расчётов). Термины «Monte
   Carlo error = std по репликам» и немодифицированное `bootstrap_mcse =
   sd/√B` запрещены.
   Дополнительно: доля эпизодов/окон, пересекающих границы блоков; результат
   leave-one-full-year-out (2022/2023/2024). При 4·h_max бутстреп грубее —
   публикуется как есть. Единственный «финальный CI» до пилота не обещается;
   тип бутстрепа не меняется после просмотра CI.
2. **Эпизоды/inter-arrival (C2a):** raw точки первично; бутстреп вторично;
   пересечение эпизодами границ блоков публикуется.
3. **Окна (C2b/C2c):** raw описательные распределения; блочный бутстреп
   исходного ряда; sensitivity к thinning (**thinning — повтор
   window-дескриптивов на прореженном ряду успешных якорей: каждый s-й
   успешный якорь, s ∈ {2, 5}; мера устойчивости к перекрытию окон;
   errata e40**); `n_windows` ≠ эффективный размер.
4. **Годы:** raw + min–max range (3 полных года); bootstrap-выводов о годах нет.
5. **Хвосты (p95+, gap events) — априорные процедурные пороги:**
   q95 публикуется при N ≥ 400 (≈20 наблюдений за квантилем), q99 — при
   N ≥ 2000, но при < 50 уникальных tail-событий за квантилем —
   `support_status = exploratory_tail`; бутстреп-CI — только при ≥ 30
   nonoverlap-equivalent блоках с ≥ 1 tail-событием (при 4·h_max ≈ 37
   nonoverlap-equivalent блоков правило оценивается по фактической
   раскладке); иначе raw order statistics + `support_status = insufficient`.
   Gap-хвосты — по **уникальным timestamp-событиям**, не по оконным
   ассоциациям.
   Максимум = «max observed». Пороги могут быть изменены до расчётов, но не
   после просмотра хвоста.

Счёт событий — только после дедупликации (touch_id, timestamp бара, эпизод D).

## 6. Контроли

1. Отрицательный контроль always-on: e_net при floor=2 bps, 0/32 — «**ни
   одна из 32 проверенных always-on target-or-terminal политик не получила
   положительного selection-adjusted свидетельства** при заданном payoff
   rule и cost floor»; роль — контроль, не утверждение о существовании
   направленной премии вообще. **Привязка и источник определений (errata
   e30):** исполняется в WП-4; состав 32 политик, payoff rule, cost floor —
   v4 (`2026-08-12-atlas-v4-deal-level-design.md`), в спеке не
   дублируются; `terminal_bps` для terminal-политик — из контракта модуля
   §8 (errata e24).
2. Инструментальные контроли v4 — повторно (**в WП-2, вместе с пилотом
   C1+C5; перечень — v4, errata e30**).
3. Embargo/OOS: раунд на train ∪ val; WП-0 вердикт — программный holdout
   consumed (Э1–Э3), требуется новый prospective holdout для финальной
   валидации будущих стадий. **Операционализация prospective holdout
   (errata e5):** граница (дата/бар) регистрируется в `run_manifest.json`
   до первого использования; все пакеты текущего раунда обязаны читать
   только бары ≤ oos_cut (train ∪ val); манифест каждого прогона фиксирует
   фактический max(timestamp) прочитанного входа; обнаружение в входе баров
   за зарегистрированной prospective-границей (или пополнение ряда после
   регистрации) — **стоп до разбора**, а не молчаливое включение.
4. Перекрытие окон — все CI блочные по протоколу §5.
5. Масштабы: bps первично; a/k первично-относительно; ATR(H1)/ATR(H4) —
   отдельные metric_id.
6. Точность M1: **OHLC сохраняет зарегистрированные экстремумы бара, но не
   порядок их достижения и не микроструктуру внутри минуты**; поэтому same-bar
   first-passage может быть неразрешим (§3.8); фильтрация/ошибки исходных
   котировок — отдельное data-quality ограничение. **Минимальный входной
   инвариант цен (errata e11; тест шага 1 WП-1, до расчёта):** для каждого
   бара — `close > 0`, `high ≥ low`, `open ∈ [low, high]`,
   `close ∈ [low, high]`; нарушение (`bps(x,e)` при close=0 даёт молчаливый
   inf/NaN; инверсии OHLC искажают first-passage без детекции) — **стоп до
   разбора**; счётчик нарушений — в манифесте прогона.

## 9. Критерии готовности раунда

Отчёт позволяет: (1) ранжировать (k,h) по доступности и регулярности; (2)
установить необходимость раздельного анализа направлений; (3) определить, как
доступность уменьшается при задержке наблюдения (три метрики); (4) описать
распределения MAE до target и на no-hit путях; (5) измерить компромисс
target/adverse (4 исхода, bounds); (6) решить, нужно ли исследование временной
структуры (гейт §3.9); (7) выделить конфигурации с недостаточной численностью
или концентрацией; (8) различить регулярный поток и концентрированные
движения (C2a/C2b/C2c). Плюс: WП-0/QA пройдены; оба вида UNRESOLVED
опубликованы с bounds; ruff/mypy/pytest чисты; детерминизм соблюдён
(операционализация — §8(5) errata e18: детерминированные редукции,
побитовая воспроизводимость при том же seed).
