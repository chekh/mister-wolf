## 3. Инструментальный артефакт серии (выявлен по замечанию пользователя, аудит БД постфактум)

**Наблюдение пользователя**: воркеры мучаются с rtk-инструментом и ищут
обходные пути; их издержки — не неэффективность иерархии, а проблемы
инструментов. **Проверка по SQLite-БД opencode (tool-части, статусы):
подтверждено, с уточнением механизма.**

### Факты (за всю серию экспериментов)

| агент | витков | rtk-ошибок | веб-ошибок | доля провальных тул-вызовов | bash |
|---|---|---|---|---|---|
| worker-rs-industry (turbo) | 193 | 122 | 74 | **≈100%** | deny |
| worker-rs-comparison (5.2) | 213 | 126 | 47 | **81%** | deny |
| worker-implementer (turbo) | 511 | 171 | 0 | **33%** | deny |
| worker-reviewer (turbo) | 215 | 41 | 0 | 19% | deny |
| worker-rs-risks (5.2) | 48 | 13 | 0 | 27% | deny |
| flat-worker (5.2) | 422 | 2 | 0 | **0.5%** | allow |
| flat-researcher (5.2) | 74 | 0 | 16 | 22% (ушёл в bash+curl) | allow |

Всего: **500 rtk-ошибок + 137 веб-ошибок** у воркеров против 2 rtk у
flat. Тексты ошибок: `python3/cd/mkdir/rg не в allowlist` (66+52+20+13),
rtk-curl FAILED (76), `rtk: No such file or directory` (28).

### Механизм (три слоя)

1. **Дизайн песочницы**: воркерам `bash: deny` (изоляция), flat-агентам
   bash разрешён — **асимметрия построена конфигурацией**: у flat был
   путь отхода, у воркеров нет.
2. **Глобальная MCP-инструкция** «обязан использовать rtk для всех
   shell-команд» + узкий rtk-allowlist → воркеры буквально послушны
   инструкции и бьются в закрытую дверь (turbo — сотнями ретраев).
3. **Разница адаптивности моделей**: glm-5.2 переключается за 1–2
   провала (flat-worker → bash навсегда; flat-researcher при падающем
   веб-стеке → bash+curl, поэтому и источников больше); turbo-воркеры
   продолжают ретраить.

Каждый провальный вызов = полный виток модели с перечитыванием
контекста → прямое раздувание времени и full-токенов ORCH
(RESEARCH-001 orch-2: full=13.8M раздут трешем comparison-воркера).

### Урок (находка 42, §11(е) REPORT.md)

Инструментальная политика — предусловие честных A/B-метрик: у каждого
агента обеих веток должна быть рабочая трасса оболочки (bash allow или
rtk-allowlist, покрывающий класс задачи). Перед сравнительными
экспериментами — сверять тул-статусы по БД; иначе измеряется ловушка,
а не схема.

### Тюнингованные оценки перерасхода (декомпозиция по шагам, из БД)

Метод: каждому шагу модели приписана доля отходов = доля провальных
тул-вызовов среди вызовов шага; отходы вычтены из ОБОИХ веток (у flat
они ≈0). Чистые окна (killed/aborted исключены). Это нижняя граница
артефактной части (не учитывает время на обдумывание обхода).

| эксперимент | налог new: измерен → скорр. | налог full: измерен → скорр. | waste-доля ORCH (new/full) | время на треш |
|---|---|---|---|---|
| LONG-001 | +211% → **+157%** | +97% → **+68%** | 17% / 15% | ≈1.3 из 7.2 мин |
| LONG-002 | +410% → **+347%** | +221% → **+172%** | 12% / 15% | ≈3.1 из 16.0 мин |
| REVIEW-001 | +48% → +46% | **−29% → −29%** | 2% / 1% | ≈0.9 из 32.7 мин |
| RESEARCH-001 | +439% → **+258%** | +365% → **+211%** | **36% / 36%** | ≈6.6 из 15.6 мин |

(База LONG-001 здесь +211%/+97% против +239%/+111% в отчёте серии B —
разница набора окон/агрегации; поправка вычислена внутри одной базы.)

**Скорректированные вердикты серии**:
- REVIEW-001: без изменений — waste 1–2%, win иерархии (−29% full,
  +31% находок) полностью честен.
- LONG-001/002: вывод «реализация = ниша flat» устойчив (скорр. налог
  +157…+347% new — всё ещё ×2.5–4.5), величина налога снижена на
  ~50–60 п.п.
- RESEARCH-001: разрыв был завышен ≈вдвое: new +439%→+258%, full
  +365%→+211%, время ×2.3→≈×1.35 (6.6 из 15.6 мин — треш). H1/H2/H3
  остаются опровергнутыми (flat всё равно быстрее и дешевле), но
  «источников ×2 меньше» объясняется в заметной части голоданием
  веб-воркеров, а не только синтез-горлышком.
- Остаточный (после вычета waste) налог — это уже честный налог самой
  иерархии: спавны, передача контекста, ревью-циклы.

## 5. Рекомендации (итог серии C)

1. **Для критичных документов лаборатории** (спеки MC/атлас): раунд
   изолированного ревью security → completeness → consistency узкими
   ревьюерами в чистых сессиях; ожидать +30% находок при −30% full-
   токенов; не ожидать прироста слепой оценки на зрелых документах.
2. **Для веб-исследований** — одиночный агент с bash; конвейер не
   окупается (даже без поправки §3 — по чистым FLAT-цифрам).
3. **Слепой судья** — стандарт приёмки документ-продуцирующих задач;
   для тонких сравнений — контрастные пары (дженералист упирается в
   потолок 45–48/50).
4. **Инструментальная гигиена A/B** (из §3): рабочая трасса оболочки
   всем участникам; аудит тул-статусов по БД до вердиктов.
5. **Открытые вопросы серии**: ревью черновых документов (H3 может
   перевернуться — там critical-дефекты); неспецифицируемые задачи как
   последний кандидат ниши иерархии; повтор RESEARCH-001 с чистой
   веб-трассой для честной величины разрыва.
