Симптом: если запустить CLI из каталога, который к моменту запуска уже удалён (например, оболочка находится в удалённом worktree), приложение падает с необработанной ошибкой и сырым стеком внутренних модулей:

```text
Error: ENOENT: no such file or directory, uv_cwd()
    at ... (длинный стек фреймов)
```

Пользователь видит этот краш без какого-либо объяснения. Проект сам создаёт и удаляет рабочие каталоги, поэтому ситуация «оболочка в удалённом каталоге» — регулярная.

Задача: почини поведение CLI при запуске из удалённого cwd: корректная обработка на входе в CLI вместо сырого краша и понятное сообщение пользователю — что случилось и что сделать.

Ожидаемый итог: запуск CLI из удалённого каталога не роняет процесс необработанным стеком; пользователь получает внятную диагностику; проверки проекта остаются зелёными.
