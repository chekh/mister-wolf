# WolfEval v1 — протокол WEV-001

> Продольная A/B кампания «strong-baseline vs full-wolf» на реплеях реальных
> догфуд-инцидентов (семья TF-1-infra-hardening), оценка конечным состоянием
> через скрытые оракулы. Дизайн и обоснования —
> `docs/superpowers/specs/2026-09-04-wolfeval-v1-design.md` (далее «спека»);
> бюджетное решение координатора (2 повтора вместо 3, A/A — 1 пара вместо 3) —
> `docs/plans/2026-09-04-wolfeval-v1.md`, раздел «Бюджет сессий».

## Руки

Полные конфигурации — `arms.yaml` (по спеке §5.1). Сводка:

| Рука | kind      | Setup                                                                  | Агент                                                                   |
| ---- | --------- | ---------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| BASE | strong-baseline | снапшот инстанса без волчьих артефактов (`.wolf/`, `.opencode/` нет); никаких pre-seeded заметок (запрет П2) | default opencode (build), флаг `--agent` не передаётся |
| WOLF | full-wolf | снапшот + `wolf init` пинованного релиза: память `.wolf`, MCP mr-wolf-\*, плагины, AGENTS.md, opencode.json | worker-implementer (лицо из памяти — часть исследуемого механизма) |

Обе руки — **один агент без спавна субагентов** (WEV-001 измеряет накопление,
не иерархию). Файловая система доступна обеим рукам одинаково; baseline-руке
НЕ запрещено вести NOTES.md, дневник, доки, перечитывать свои файлы — это и
есть strong baseline (П2). Различие рук — только механизм накопления и его
носители. `start_instruction` идентична в обеих руках, промпты эпизодов
дословно одинаковы.

## Порядок эпизодов

Кампания = 7 сессий, подряд внутри повтора:

**E1 → E2 → E3 → E4 → E5 → E6a → E6b**

Каждая сессия — чистый диалоговый контекст; состояние репо инстанса и
накопленные артефакты (память Wolf / файлы baseline) сохраняются, история
разговора не переносится. Эпизод E5 механически состоит из двух запусков
лаунчера: planned_kill (обрыв на фиксированной точке) + восстановительная
сессия в чистом контексте. Дословные промпты — в
`task-families/TF-1-infra-hardening/instances/WEV-001/` (WA4).

Между повторами — полная пересборка инстансов обеих рук (fresh fixture);
внутри повтора ничего не откатывается (продольный дизайн, спека §7.2).

## Статправила

- **Кластер = повтор кампании** (не ран и не эпизод): эпизоды внутри кампании
  коррелированы общим накопленным опытом — единица рандомизации и анализа
  повтор, bootstrap по кластерам (П10).
- **Интерливинг повторов**: повтор 1 = BASE→WOLF, повтор 2 = WOLF→BASE
  (зеркальный порядок; сид рандомизации фиксируется в run-configs, WA8).
- **Fixed stopping**: 2 повтора на руку (бюджет v1), досрочных остановок и
  добавлений нет. Потолок бюджета — **40 сессий**: 38 плановых (A/A 6 +
  2 руки × 2 повтора × 8 запусков) + резерв ретраев ≤2. Ретраи сверх резерва
  НЕ запускаются — повтор помечается invalid.
- **Ретрай-политика** (спека §7.4): невалидный прогон (F21-hang: exit 124 без
  planned_kill; F25-truncation: структурный брак лога; F24-класс: сломанная
  фикстура) → **один** ретрай из резерва ≤2; при повторном фейле повтор
  помечается invalid, анализ — на выживших с явной записью асимметрии. Все
  прогоны (включая невалидные) публикуются в `measurements/WEV-001/runs.jsonl`.

## F12-контроль окружения

Перед каждым повтором: путь `readlink -f "$(which wolf)"` сверяется с путём,
записанным при lock в `measurements/WEV-001/environment-lock.json`.
Расхождение = мутация глобального окружения (класс F12) — стоп до выяснения.
Тройка (model, tools, wolf_release) не меняется до конца эксперимента (П4).

## Карта эксперимента

`playground-lab/experiments/2026-09-xx-wev-001-core-value.md` — заполняется до
запуска (pre-launch freeze, WA8); после старта гипотеза/метрики/stopping rule
не редактируются.
