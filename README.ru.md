# Mr. Wolf

![Mr. Wolf logo](https://raw.githubusercontent.com/chekh/mister-wolf/main/docs/Mr.%20Wolf.png)

> **I solve problems.**
>
> Постоянная проектная организация из временных AI-помощников.

Mr. Wolf организует работу AI-помощников вокруг вашей цели. Он связывает агентов, скиллы, инструменты, правила и память проекта в процесс: понять потребность, организовать выполнение, проверить результат и сохранить существенное для следующей сессии. Через Стюарда обратная связь и опыт могут превращаться в управляемые изменения способов работы организации.

Wolf — ваша точка общения с этой организацией: объясните потребность обычным языком, обсудите существенные решения и получите результат, который можно понять и оценить.

## Зачем Wolf

- **Удерживать цель.** L0 отвечает за цель и итоговую приёмку; L1 организует поставку; L2 выполняют ограниченные задачи. Разделение ответственности сохраняет связь частной технической работы с ожидаемым результатом на длинном пути.
- **Связывать методы.** Процесс определяет применимые скиллы, правила, контекст и инструменты, распределение задач, момент вопроса и способ проверки. Лицо воркера и назначенные скиллы задают нужную специализацию.
- **Продолжать между сессиями.** Документы проекта — часть памяти наряду с решениями, рабочим состоянием и уроками. Исходные документы остаются каноничными в своих файлах; Wolf сохраняет ссылки и относящийся контекст для дальнейшей работы.
- **Менять будущее поведение через Стюарда.** Жалобы могут приводить к новым версиям методик; зрелые уроки — обобщаться. Сохраняются причины и история изменений, для версий лиц доступен откат. Это обучение организации, а не обучение весов модели.
- **Комфортно общаться с человеком.** Содержательное уточнение намерения, ясное объяснение и своевременный вопрос входят в методику работы. Внутренние отчёты воркеров собираются в полезный ответ пользователю.
- **Накапливать собственные способности.** Полезные скрипты и методы могут становиться ресурсами проекта. Локальные файлы, CLI и MCP сохраняют контроль над состоянием; обращения к модели используют настроенного вами провайдера.

[Обзор продукта](https://chekh.github.io/mister-wolf/ru/guide/overview) объясняет связи компонентов. [Сравнение подходов](https://chekh.github.io/mister-wolf/ru/guide/capabilities#связь-с-другими-решениями) показывает отношение к памяти агентов, наборам скиллов, харнесам и мультиагентным фреймворкам без вымышленного рейтинга эффективности.

## Начните со своего проекта

Полная организация сейчас — **OpenCode-first**. Требования: Node.js 22 или 24; macOS либо Linux с glibc.

```bash
npm install -g mister-wolf
cd my-project
wolf init --full --platform opencode
wolf bootstrap
```

Имя пакета — **`mister-wolf`**; `mr-wolf` — другой пакет. После инициализации перезапустите OpenCode, чтобы загрузились проектный MCP-конфиг и агент по умолчанию.

Затем поручите Wolf результат, например:

> Помоги подготовить руководство для новых участников проекта. Используй существующие документы, выясни, что нужно новичку, и подготовь краткое руководство с проверенными шагами запуска. Спроси меня, если недостающее решение влияет на результат.

Поставляемые методики предписывают Wolf уточнить цель, организовать ограниченные задачи, проверить результат и сохранить существенное состояние. Ответ должен объяснять, что подготовлено, что проверено и что осталось открытым. Фактический запуск зависит от проекта, модели и харнеса; это пример поручения, а не запись выполненного прогона.

[Первый сеанс](https://chekh.github.io/mister-wolf/ru/guide/getting-started) объясняет bootstrap, восстановление и дополнительный режим только памяти. Для начала работы с организацией изучать таксономию памяти не требуется.

## Повседневная работа и обновление

Обсуждайте задачу или замечание с Wolf в своей агентной среде. [Работа с Wolf](https://chekh.github.io/mister-wolf/ru/guide/working-with-wolf) описывает уточнение, прогресс, продолжение и обратную связь. [Стюард](https://chekh.github.io/mister-wolf/ru/guide/feedback) — изменение методик по опыту и сохранение вашего контроля.

```bash
wolf upgrade --check   # проверить актуальность CLI и зарегистрированных проектов
wolf upgrade          # обновить пакет и зарегистрированные проекты
```

Перед выбором исхода обновления изучите локальные изменения. [Порядок обновления](https://chekh.github.io/mister-wolf/ru/guide/upgrade) объясняет diff, защиту и резервные копии.

## Границы и разработка

Организационные методы Wolf применимы за пределами программирования; в поставке есть исследования, работа с документами и отчёты. Текущая реализация основана на репозитории и прежде всего OpenCode. Доступ по MCP или конфигурация другой платформы не означают проверенную полную организацию на ней. Экспертный консилиум поставлен как метод, а не автоматический рантайм: роль `worker-expert` с read-only каналом в границах проекта (включая код; запись, shell, субагенты, webfetch и внешние каталоги запрещены), методика `wolf-council` для L1 и запись консилиума (`wolf council record`); см. [руководство по консилиуму](https://chekh.github.io/mister-wolf/ru/guide/council). Пользовательская консоль и устойчивое выполнение после сбоя пока не гарантируются. См. [возможности и границы](https://chekh.github.io/mister-wolf/ru/guide/capabilities). [Изоляция чтения](https://chekh.github.io/mister-wolf/ru/guide/read-isolation) применяется к доставке через `wolf call`, а не к общему доступу на чтение.
