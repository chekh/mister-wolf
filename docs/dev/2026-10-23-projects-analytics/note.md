- Дата: 2026-10-23
- Тред: mem_20261023_analitika_parka_proektov_wolf_obnovlenie_a1bdf7
- Режим: LITE, read-only по чужим `.wolf/` (записи — только в mister-wolf)
- Инструмент сбора: wolf CLI 2.18.5 (глобальный, обновлён с 2.17.1 в рамках задачи)

## 1. Цель

Определить, какие проекты на этой машине обслуживает Wolf, собрать по каждому
статистику памяти/доставок/версий, выполнить кросс-проектную аналитику и
подготовить базу для следующего этапа работ владельца.

## 2. Методика и источники

Все команды воспроизводимы; операции с чужими `.wolf/` — только чтение.

| Что                            | Команда / источник                                                                                                                                            |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Реестр проектов                | `wolf projects`; `wolf doctor`; `cat ~/.config/wolf/projects.yaml`                                                                                            |
| Поиск всех памятей             | `find ~/Development -maxdepth 4 -name ".wolf" -type d`                                                                                                        |
| Объекты по типам/статусам      | разбор frontmatter `*/.wolf/memory/shared/**/*.md` + каталоги `memory/threads/`                                                                               |
| Активность (недельные корзины) | `.wolf/memory/events.jsonl` (поля `timestamp`, ISO-неделя)                                                                                                    |
| Доставки/промахи               | `.wolf/router.log`: `playbook=hit` = доставка, `variant=fallback` = промах (fallback-playbook вместо канонического); окно 7d — скользящее 7×24ч (как в recap) |
| Версии CLI в использовании     | `.wolf/metrics/session-metrics.jsonl`, `detail.wolf_version` событий `mcp_call`                                                                               |
| Base-set штампы                | маркеры `wolf:rendered … set=X.Y.Z` в `AGENTS.md` / `.opencode/skills/using-skills/SKILL.md` проекта                                                          |
| Диск                           | `du -sk` по подкаталогам `.wolf/`                                                                                                                             |

Контрольная перепроверка доставок по двум проектам независимо (awk по
`router.log`) сошлась с парсером; расхождения только на границе 7d-окна.

## 5. Аналитические выводы

1. **Реестр занижает парк в 4 раза.** `wolf projects` показывает 4 проекта,
   реальных памятей — 17 (источник: projects.yaml против `find`). Все 4
   записи реестра датированы 2026-10-13/14 — механизмом реестра охвачены
   только проекты, переинициализированные после его появления; более ранние
   внедрения (июнь–сентябрь) не бэкфиллены. Аномалия №1.

2. **43% всех доставок — fallback-промахи, и тренд ухудшается.** 29 938 из
   68 918 hits ушли с `variant=fallback`; за последние 7 дней доля промахов
   57% (источник: router.log всех проектов). Ответственный агент почти
   монополен: **executor-lead** — топ промахов в каждом активном проекте
   (trading-signal ×16 955; mister-wolf ×4 219; Tender ×2 068; adminvps
   ×195). Канонического playbook'а для executor-lead в проектах нет — роутер
   каждый раз отдаёт универсальный fallback. Это крупнейший измеримый
   источник недополученной ценности памяти.

3. **Метрики весят в 9 раз больше памяти.** `.wolf` парка ~503 MB при
   полезной памяти 44,5 MB; главный потребитель — `metrics/`
   (session-metrics.jsonl: 56 MB в mister-wolf, 159 MB метрик в
   trading-signal) и `cache/` (115 MB у trading-signal) (источник: du).
   Ротации/сжатия нет — рост линейный по числу сессий. Аномалия №2
   (дисковая).

4. **Парк не обновляется за релизами.** Актуальная версия 2.18.5 (5 релизов
   2.18.x с 2026-10-15), но CLI на машине был 2.17.1, base-set штампы
   проектов — 2.16.2–2.17.1, вызовов 2.18.x в метриках нет (источники:
   `wolf --version`, маркеры set=, session-metrics). Обновление — ручной
   шаг, которого в парке не делали. Отдельный случай: config.yaml
   mister-wolf штампует `wolf_version: 2.12.0` — штамп не обновляется при
   обновлении CLI.

5. **Половина внедрений — «попробовал и бросил».** Из 17 памятей 8 не
   активны ≥3 недель, из них 5 прожили один день (Мартовский заяц,
   photo-restoration — 5 доставок, my_home, wolf-playground; плюс
   worktree-скоп wolf-l0-dispatcher с осиротевшим 28-объектным скоупом)
   (источник: events.jsonl, router.log). Живое ядро — 4 проекта (сам
   mister-wolf, trading-signal с подсетью из 4 подпроектов, Tender, adminvps)
   плюс растущие октябрьские подпроекты trading-signal (iaac, mt5-edge-lab,
   trading-hub).

6. **«Теневой парк» без инъекций.** У 8 памятей нет router.log (и у трёх —
   ноль opencode-скиллов, т.е. плагин не установлен): infra/Stratographer,
   mt5-edge-lab, trading-hub, iaac, opencode-agent, Resadviser-корень,
   wolf-playground (источник: ls `.wolf/router.log`, `.opencode/skills/`).
   Память в них накапливается, но в сессии агентов не доставляется —
   ROI таких внедрений ограничен CLI-режимом.

7. **Эффективность доставки коррелирует со зрелостью настройки.** adminvps —
   4% промахов против 66% у mister-wolf (источник: router.log): в adminvps
   почти все доставки канонические. Промахи сконцентрированы не в платформе,
   а в отсутствующих face-плейбуках конкретных агентов — точечная работа по
   закрытию топ-N агентов устранит большую часть потерь.

## 6. Ограничения данных

- Одна машина (macOS), один пользователь; `~` вне `~/Development` сканировался
  с maxdepth 4 — глубокие вложенности могли быть пропущены.
- 7d-окно скользящее (7×24ч), как в recap; при независимой перепроверке awk
  границы дня дают ±2% расхождения — неопределённость принята.
- Промах = fallback-вариант доставки (семантика recap); «miss»-строки
  (playbook=miss) в расчёт доставок не входят.
- Содержимое записей чужих проектов не выгружалось (приватность): только
  агрегаты и frontmatter-статусы.
- `mcp_call wolf_version` фиксирует версию в момент вызова CLI; метрики до
  появления поля не атрибутируются.

2. **Ротация session-metrics.jsonl и gc cache/** — дисковая гигиена парка
   (до 0,5 GB; trading-signal: 159 MB метрик при 27 MB памяти).
3. **Канонический playbook для executor-lead** — закрывает 42% всех
   промахов парка одним лицом; контекст-кандидат — активный тред Волны
   2.19.0 async learning (mem*20260930*…/mem_20261015_volna_2_19_0_async_learning_avtonomnyy_f_882fc6):
   авто-генерация недостающих playbook'ов из статистики роутера — ровно этот
   сигнал.

   mister-wolf и лаг 2.16–2.17 при 2.18.5): владелец видит парк, а не
   один проект.
5. **Судьба «брошенных» памятей**: promote/архив осиротевшего worktree-скопа
