## Зависимости и разделение труда

BA-T01 → BA-T02 → BA-T03. После согласования candidate BA-T04 и независимая
подготовка сценарных проб BA-T05 могут идти параллельно при раздельной записи;
результаты сходятся в BA-T06a → BA-T06b → BA-T07. При изменении общего канона затронутые
пробы/проверки актуализируются. Общие plan/test-plan и release metadata имеют
одного writer. Интеграцию выполняет назначенный L1, L0 принимает по метаданным.

Это возможные ограниченные поставки L1, не требование создавать отдельный L1 или
worktree на каждый пункт: BA-T02/03 составляют одну поставку до приёмки с независимым L2
review. Завершённая поставка не продлевается новым независимым TASK. Детальную
разбивку L2 определяет соответствующий L1. Параллельность не обязательна при
реальной зависимости, малом бюджете или отсутствии capability.

## Подготовительный пакет и владение

Владелец актуальности quartet, patch и release-agent.md — агент внедрения/выпуска.
`release-agent.md` — единственное дополнительное долговечное пояснение для
следующего этапа: команды применения, состав candidate, rollout/rollback.
Полезно отдельно от плана как точка входа исполнителя; не временный отчёт.
`patches/releases/2.30.0-bounded-assignments.patch` — запрошенный пользователем
ресурс внедрения вне docs/dev, не исполняемый скрипт и не отдельный source of truth.
При конфликте требований и candidate действуют принятые requirements/design;
патч корректируется, слепое применение запрещено.
