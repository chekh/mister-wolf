# Агенту внедрения: ограниченные поручения L1

Владелец поручил подготовить релиз, который уточняет разделение труда и lifetime
исполнителей. Исходная боль — один L1 последовательно получает новые законченные
поручения в течение всей пользовательской сессии. Новый самостоятельный результат
должен получать fresh L1 даже без параллельности. Исправления того же непринятого
результата допускают continue; непригодная сессия заменяется через handoff.

Сохрани действующие планирование, evidence, независимое ревью, проверки объединённого
состояния и DONE ≠ ACCEPTED. Общая методика действует L0→L1 и L1→L2, не расширяя
права. При необходимости распределения нескольких L1 план готовит L1 по поручению
L0; нанимает этих L1 сам L0. Малую связанную поставку не дроби на агентов по этапам.

## Ограничения подготовки

вернул отсутствие активных injections; `wolf brief` завершился SQLite-ошибкой

check/e2e, live observation, rollout и публикация на этой стадии не заявляются.
