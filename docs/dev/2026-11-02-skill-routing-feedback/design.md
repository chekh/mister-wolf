# Навыки и доставка

Baseline: `6cdd9f7`, пакет 2.24.0. Патч не назначает номер релиза.

## Решение

- `using-skills` — компактное обязательное ядро. Тематические references дают когда/как/результат; общий TASK, память и правила проекта загружаются адресно. Существующий renderer рекурсивно доставляет все references, включая обновление и protect.
- `wolf-feedback` — общий вход для вопроса, FRICTION, отклонения, W1–W4 и назначенной диагностики. Канон подачи/триажа — reference навыка; seed complaint-protocol ссылается на него. Активное лицо меняет авторизованный Стюард.
- `wolf-visual-dialogue` — композиция с explain/report; интерактивные средства выбираются по фактической среде, статический показ и ответ в чате — переносимый путь. Документ — по уже данному запросу/согласованию.
- L1 декомпозирует и назначает конечную предметную работу L2 с лицом и скиллами. L1 сохраняет координацию, решения, интеграцию и разрешённый Git. Новая самостоятельная задача — fresh; continue допустим для того же непринятого результата; закрытие после сохранения результатов.
- Инструмент хранится в проекте. `tool register` сохраняет относительную ссылку; явное обновление карточки не создаёт новый ID. Старый `.wolf/tools` остаётся допустимым источником. Реальные проверки пути и отсутствия файла не равны подтверждению всей среды инструмента.
- Повторяемые технические операции и история OpenCode получают исполняемые, ограниченные входом средства; они обслуживают поручение L2, не заменяют его и не выставляют ACCEPTED. Нет второго TaskState-store.

## Границы

Без изменения полномочий платформы, автоактивации лиц, личных скиллов ChatGPT, публикации, новой модели/variant и полного экспорта журналов. Нет обязательного сервера или нового постоянного агента. Дополнительные харнесы не объявляются проверенными без evidence.

## Обновление

Source templates являются каноном. Update-map пересобирается штатным генератором. Защищённые/локально изменённые файлы сохраняются по штатной политике. Live playbook сверяет Стюард, а не повторный init.
