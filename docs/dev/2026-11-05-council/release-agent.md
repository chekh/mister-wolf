# Агенту внедрения и выпуска

Владелец поручил новый релиз: рабочий консилиум, отдельная экспертная L2-роль,
точечное улучшение ревью и внутреннего языка. Цель и подготовка согласованы;
повторный discovery не нужен. Quartet пока draft: независимо проверь документы,
технические ADR и кандидат, затем реализуй, проверь и доведи до штатного выпуска
в пределах фактических полномочий. Пуш ветки подготовки не означает merge/tag/npm publish.

## Входы

Прочитай requirements.md, design.md, plan.md, test-plan.md из этой папки.
REQ/AC — источник scope; design определяет предложенный контракт, plan — задачи,
test-plan — evidence. Целевая версия 2.31.0: если занята, выбери следующий свободный
полный X.Y.Z и обнови ссылки. Точная база кандидата:
174e5102f85a515a75c47a670b99b507811bb688 (package 2.30.0, O1/U1 design уже в main).

Ветка пакета: feat/codex_council-release, chekh/mister-wolf.
Патч: patches/releases/2.31.0-council-candidate.patch.
Пакетная ветка содержит документы и патч, а не применённые исходники.
В своём worktree от проверенного актуального main прочитай AGENTS.md, wolf-git,
выполни wolf call/brief и восстанови активные ограничения пользовательской установки.
Локальный brief подготовки содержал документные note, не живое состояние владельца.

## Применение кандидата

PACKAGE_ROOT — checkout ветки пакета; patch сам не появляется в чистом worktree main.

```bash
PACKAGE_ROOT=/absolute/path/to/release-package-checkout
PATCH_FILE="$PACKAGE_ROOT/patches/releases/2.31.0-council-candidate.patch"
git apply --check "$PATCH_FILE"
git apply "$PATCH_FILE"
git diff --check
```

Не применяй patch второй раз к уже изменённым файлам. Если база продвинулась,
сопоставь затронутые источники и интегрируй изменения адресно; не подменяй целые
файлы старыми копиями, не force/reset чужой работы. Merge-политика проекта сохраняется.
Документы пакета перенеси явным коммитом/согласованной интеграцией, если рабочая
ветка не содержит их; не переписывай baseline происхождения.

## Что уже подготовлено и что обязательно завершить

Candidate: wolf-council, worker-expert и seed-face, профили expert/synthesis,
ссылки L0/L1/маршрутов, удаление дублированного council-контракта из brainstorm,
пакет ревью и finding-level повторная проверка. Candidate имеет безопасный
packet-only deny-профиль эксперта; это НЕ реализованный tool-enabled режим.

Обязательный остаток, даже если patch применился чисто:

1. Проверить реальные права OpenCode на всех доступных каналах, path/symlink и
   изоляцию первого раунда; доказать tool-enabled конфигурацию или вернуть блокер.
2. Дополнить agent registry/seed/injection/sync. Новый frame без active face и
   корректного роутинга не считается внедрённой ролью.
3. Реализовать `wolf council record --input` и MCP council_record общей операцией
   над note envelope; schema, lock/idempotency, recover relations/events/index.
4. Реализовать mixed reader/analytics без возврата removed core types. Отсутствие
   vote не TIMEOUT. Не ослаблять историческую v2 minItems-схему ради нового исхода.
5. Доставить EN/RU, upgrade/update-map и язык; защитить pin/variant/protect/keep и
   local face. Текущие лица не заменять seed-файлом в обход Стюарда.
6. Выполнить все применимые сценарии test-plan, включая три сквозных live кейса;
   отдельно предъявить structural/integration/live evidence и ограничения.
7. Провести независимое ревью итогового объединённого состояния, подготовить
   metadata через npm version/CHANGELOG/фактический prev update-map, штатные gates
   и staging rollback. Roadmap C синхронизировать, O1/U1 не переоткрывать.

Рекомендация не решение: только полномочный принимающий создаёт decision и
передаёт DECISIONS[]. Эксперты ничего не записывают, не делегируют, не исследуют
самостоятельно. Недостаток данных — допустимый результат; исследование назначает L1.

## Завершение и откат

Для каждой выполненной задачи plan.md: checkbox и «сделано → commit», затем
сводка REQ/AC с evidence/непроверенным. Не объявляй совет работающим по одному
файлу SKILL.md, числу агентов или сохранённой стенограмме. Требуется применение
решения и проверка. Экономию токенов без доступных измерений не обещай.

Откат непринятого собственного patch — только после `git apply -R --check` и
проверки владения; поверх дальнейших изменений — адресный revert своего commit.
Сохрани читаемость note и evidence; опубликованные теги не передвигай. Право
публикации релиза/тегов определяет действующее поручение/политика, не этот файл.
