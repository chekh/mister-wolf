перегенерация update-map → локальный гейт → тег).

# T1 — REQ-332-1: per-operation чтение (ADR-332-1)

Адаптер: убрать флаг `loaded`, перестраивать состояние на каждый публичный
вызов; триггер миграции без изменений. Тесты T-332-1.1–T-332-1.5 (сначала красные на
базе). Файлы: `src/adapters/fs/jsonl-micro-note-delivery-log.ts`,
`tests/unit/adapters/fs/jsonl-micro-note-delivery-log.test.ts`.

# T2 — REQ-332-2: общий корень внутри адаптера (ADR-332-2)

Адаптер: `resolveMemoryRoot(baseDir).root` для пути журнала и `indexPath(root)`
для legacy-поиска. Тесты T-332-2.1–T-332-2.5 (новый integration-файл с реальным
git worktree; фикстура `tests/fixtures/micro-note-index-330` для T-2.4).
Точки входа CLI/MCP не меняются.

# T3 — REQ-332-3: repair-on-write (ADR-332-3)

Адаптер: `append()` восстанавливает границу (обрывок → truncate; валидный хвост
без `\n` → финализация). Тесты T-332-3.1–T-332-3.5 (unit).

# T4 — интеграция и регрессия

Прогон: полный `npm run check` + `npm run e2e`; живой сквозной стенд §4
тест-плана на собранной сборке (все ответы трёх каналов согласованы).
Исполнитель возвращает доказательства (файлы стенда + выводы гейтов).

# T5 — документация

`CHANGELOG.md`: запись `[3.3.2] - 2026-11-19` (Fixed; три дефекта, сценарии
ревьюера как формулировки; ссылка на breaking-изменение 3.3.1 не дублируется).
CLI/MCP-контракт не меняется — `docs/reference/cli.md`, command-reference и
`mcp.md` не трогаются (guard-тесты подтвердят).

# T6 — гейт ведущего и релиз (не делегируется)

1. Приёмка результата разработчика, независимое ревью (wolf-reviewer).
2. `env -u WOLF_SESSION npm run check`, `npm run e2e`, `docs:verify` — лично.
3. Коммит волны (CHANGELOG + код + тесты + dev-пакет) → `npm version 3.3.2` →
   `node scripts/generate-update-map.mjs` → коммит → локальный `npm run check`
   (после бампа!) → push ветки → PR → merge → тег `v3.3.2` → контроль Publish →
   пост-проверки (npm latest, GitHub Release, сайт, смок артефакта) →
   синк проектов не требуется (доставляемый набор не меняется — проверить дифф
   update-map: только version/prev).

# Останов и риски

- Стоп-условие исполнителя: T1–T3 красный→зелёный + T4 гейты зелёные; любые
  расхождения с тест-планом — вопрос ведущему, не самостоятельное расширение.
- Риск гонки appender'ов осознанно вне скоупа (requirements §3).
- Если полный check выявит зависимые от кэша места вне журнала (например,
  тесты, полагающиеся на кэшированное состояние) — вернуть ведущему, не править
  прод-код сверх ADR.
