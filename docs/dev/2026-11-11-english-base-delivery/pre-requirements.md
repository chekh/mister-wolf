# Пред-требования: английская база поставки

## Намерение и польза

Перевести доставляемые методики (53 скилла, 9 агентов, 3 команды, onboarding-блок
AGENTS.md; 69 из 73 md-файлов `templates/` — 525 KB) на английский как единственный
канон поставки — тщательно, с несколькими независимыми ревью-циклами, без снижения
качества методик — и добавить в ядро поставки правило языка сессии, чтобы рабочий
язык пользователя (общение, память, рассуждения) не изменился вместе с языком
артефактов.

Основа: решение владельца `mem_20261111_lang-strategy-en-canon_2cf228` (2026-11-11);
консилиум (вопрос `mem_20261111_5413f8`, позиции `e422d0`/`920955`/`e91eff`,
синтез `e08602`); верификация внешнего ревью (`mem_20261111_external-review-2026-11-11-verification_3778f4`).

## Границы

Входит:

- перевод md-файлов поставки `templates/**` (скиллы, агенты, команды, AGENTS.md-блок);
- правило языка сессии в ядре поставки (см. D2);
- глоссарий RU→EN (согласованность терминов между 68+ файлами);
- обновление тестов, гейтов и демо-сценариев, зависящих от языка поставки
  (package-hygiene, e2e-состав, scenario-1..8, check-english-surface, docs:build);
- миграционная волна `upgrade` для существующих проектов (массовая смена штампованных
  файлов, штатные бэкапы и resolve-стратегии);
- синхронизация RU-зеркала сайта по итогам (сайт остаётся EN-канон + RU-зеркало).

Не входит: код Wolf без необходимости (кроме мест, где язык поставки зашит в логику),
память пользователей, перевод сайта-доков сверх синхронизации.

## Принятые решения

- **D1 — EN-канон поставки** (владелец, 2026-11-11). Основание: единогласный
  консилиум (3×B); двойное сопровождение при 1 контрибьюторе; конвенция экосистемы;
  токен-стоимость always-загружаемого ядра (~25 KB) платится в каждой сессии.
- **D2 — правило языка сессии в ядре поставки** (владелец, 2026-11-11): Wolf
  уточняет предпочтительный язык пользователя и ведёт на нём общение, записи памяти
  и рассуждения исполнителей; выбор фиксируется в памяти и не переспрашивается.
  Язык артефактов поставки (EN) — ортогонален языку работы.
- **D3 — миграция одной выделенной волной upgrade** (консилиум E2/E3): не размазывать
  по релизам; раньше — дешевле, каждый релиз штампует новые RU-копии.

## Отвергнутые варианты

- **A: двуязычная поставка с `--lang`** — двойное авторство либо дрейф RU-набора
  при темпе 65 релизов/72 дня и одном контрибьюторе; новая поверхность выбора ради
  отсутствующей внешней аудитории; со временем коллапсирует в B.
- **C: RU-подмножество ядра** — самый дорогой язык в всегда-загружаемой зоне.
- **C: перевод как отдельный сервис сессии** — закрывается D2; недетерминированность
  без спроса.

## Предложения по исполнению

- Порядок перевода: ядро всегда-загрузки (AGENTS.md-блок, using-skills) → частые
  скиллы → остальное.
- На каждую группу файлов: перевод → семантическое ревью против оригинала →
  редактура читаемости носителем языка → повторный контроль выборки. Глоссарий
  RU→EN утверждается до старта перевода.
- Гейты качества: 0 файлов с кириллицей в `templates/`; глоссарий-консистентность;
  прогоны тестов состава поставки; замер токен-выигрыша на 2–3 файлах
  (validation из синтеза консилиума).

## Открытые вопросы

- Механика правила языка сессии: где живёт (onboarding-блок AGENTS.md /
  session-start / using-skills), где фиксируется выбор пользователя, как выглядит
  уточнение при первой сессии.
- Границы перевода в нетекстовых артефактах: строки ошибок CLI, update-map,
  заголовки/термины в коде.
- Миграционные resolve-стратегии по умолчанию для штампованных файлов (подсказка
  take/keep пользователю при волне).
- Переходный период смешанных проектов владельца (часть проектов RU, часть EN).
