# Английская база поставки — требования

## 1. Контекст и проблема

Поставка npm-пакета `mister-wolf` распространяет методики Wolf как русскоязычные
md-файлы из `templates/`. По замеру 2026-11-11: 73 файла, из них 69 md, 67 md
содержат кириллицу, ~500 KB md-контента; группы — 53 скилла, 9 агентов, 3 команды,
onboarding-блок AGENTS.md. Значительная часть этого текста попадает в контекст
каждой сессии (always-загрузка), поэтому стоимость русского языка платится в каждой
сессии каждого проекта. Двуязычная поставка (`--lang`) была отвергнута: двойное
авторство не по силам одному контрибьютору при текущем темпе релизов; опции выбора
языка в CLI сейчас нет и добавлять её не планируется.

Решение владельца (2026-11-11, `mem_20261111_lang-strategy-en-canon_2cf228`,
по итогам консилиума `e08602` и внешнего ревью): английский — единственный канон
поставки. Перевод выполняется тщательно, в несколько независимых ревью-циклов,
без снижения качества методик. Одновременно в ядро поставки входит правило языка
сессии, чтобы переход артефактов на EN не изменил рабочий язык пользователей:
общение, записи памяти и рассуждения исполнителей остаются на языке пользователя.
Существующие проекты с русскими штампованными файлами мигрируются одной выделенной
волной upgrade, а не размазанным по релизам дрейфом.

Метрика успеха волны:

- 0 файлов с кириллицей в `templates/` при пройденных циклах качества перевода;
- правило языка сессии присутствует в always-загрузочном ядре поставки и проверяемо
  в e2e/demo-сценариях;
- существующие проекты мигрированы одной волной upgrade без потери пользовательских
  правок (бэкапы + resolve-стратегии);
- токен-стоимость always-загрузки не увеличилась относительно RU-версии (замер
  на 2–3 файлах).

## 2. Область

Входит:

- перевод md-файлов поставки `templates/**` на английский: onboarding-блок
  AGENTS.md, using-skills, остальные скиллы, агенты, команды (REQ-02, REQ-03);
- правило языка сессии в always-загрузочном ядре поставки (REQ-01, решение D2);
- глоссарий RU→EN как обязательный вход перевода (REQ-04);
- процесс качества перевода с независимыми ревью-циклами (REQ-05, NFR-01..03);
- автоматические гейты качества и состава поставки (REQ-06);
- синхронизация тестов, гейтов и demo-сценариев, зависящих от языка поставки:
  `tests/unit/package-hygiene.test.ts`, e2e-состав (bootstrap, base-set,
  distribution, scaffold, upgrade и др.), `scripts/demo/scenario-1..8`,
  `scripts/check-english-surface.mjs`, `npm run docs:build` (REQ-07);
- миграционная волна upgrade существующих проектов: массовая замена штампованных
  файлов (~68), автоматические бэкапы, resolve-стратегии protect/keep/take (REQ-08);
- RU-чтение методик — через существующее RU-зеркало сайта; синхронизация зеркала
  по итогам волны (REQ-09).

Не входит (не-цели):

- код Wolf без необходимости — кроме мест, где язык поставки зашит в логику
  (update-map, сообщения миграции о шаблонах); точный перечень таких мест —
  на design-волне (см. раздел 6, вопрос В2);
- память пользователей и содержимое их проектов вне штампованных файлов;
- перевод сайта-документации сверх синхронизации RU-зеркала (сайт остаётся
  EN-канон + RU-зеркало);
- переходный период смешанных проектов владельца (часть проектов RU, часть EN) —
  отдельная работа после волны (см. раздел 6, вопрос В4).

## 3. Глоссарий

- **Канон поставки** — единственный авторитетный язык артефактов, поставляемых
  пакетом `mister-wolf` (`templates/`); после волны — английский.
- **Всегда-загрузочное ядро (always-loaded core)** — файлы поставки, попадающие
  в контекст каждой сессии: onboarding-блок AGENTS.md и using-skills (~25 KB).
- **Правило языка сессии (session language rule)** — поведение Wolf: уточнить
  предпочтительный язык пользователя, зафиксировать выбор в памяти, вести на нём
  общение, записи памяти и рассуждения исполнителей (REQ-01).
- **Штампованный файл (stamped file)** — файл, скопированный в проект из
  `templates/` при init/upgrade и подлежащий замене при волне.
- **Resolve-стратегия** — штатное поведение upgrade при конфликте с локальными
  правками: protect / keep / take.
- **Глоссарий RU→EN** — согласованная до старта перевода таблица терминов методик
  Wolf; источник единообразия перевода между 68+ файлами.
- **Семантическое ревью** — независимая сверка перевода с русским оригиналом
  на сохранение смысла и полноты методики.
- **Редактура носителем языка** — независимая правка перевода на естественность
  английского (native-readability edit).
- **Волна upgrade** — выделенная серия релизов миграции существующих проектов
  на EN-поставку (решение D3), не размазанная по обычным релизам.

## 4. Функциональные требования

### REQ-01 — Правило языка сессии в ядре поставки

- История: Как пользователь Wolf на любом языке, я хочу вести работу на своём
  языке, чтобы переход поставки на английский не изменил мой рабочий язык.
- Требование: Когда always-загрузочное ядро поставки содержит правило языка
  сессии, Wolf должен: (а) при первой сессии в проекте, если предпочтительный
  язык пользователя не зафиксирован, уточнить его у пользователя; (б) зафиксировать
  выбор записью в памяти Wolf и далее не переспрашивать; (в) вести на выбранном
  языке общение с пользователем, записи памяти и рассуждения исполнителей;
  (г) сменить язык только по явному указанию пользователя. Язык артефактов
  поставки (EN) правилом не затрагивается — он ортогонален языку работы.
- Обоснование: решение владельца D2 — канон поставки меняется, язык работы нет;
  закрывает отвергнутый вариант «перевод как отдельный сервис сессии».
- AC:
  - Given поставка установлена, в памяти проекта нет записи о языке пользователя
    - When пользователь начинает первую сессию
    - Then Wolf задаёт вопрос о предпочтительном языке ровно один раз и сохраняет
      выбор записью в памяти Wolf.
  - Given выбор языка зафиксирован в памяти
    - When начинается новая сессия
    - Then правило применяется без переспрашивания: общение, записи памяти и
      рассуждения исполнителей — на выбранном языке; артефакты поставки — EN.
  - Given зафиксирован язык X
    - When пользователь явно просит перейти на язык Y
    - Then выбор обновляется в памяти Wolf и применяется, переспрашивания нет.
  - Given запись о языке отсутствует
    - When пользователь с первой реплики явно указывает язык X
    - Then Wolf не задаёт отдельный вопрос о языке: язык X фиксируется в памяти
      Wolf. Отдельный вопрос задаётся только когда явного указания нет.
- Приоритет: Must
- Источник: диалог с владельцем 2026-11-11 (pre-requirements, D2); решение
  `mem_20261111_lang-strategy-en-canon_2cf228`.

### REQ-02 — Перевод always-загрузочного ядра поставки

- История: Как пользователь Wolf, я хочу, чтобы всегда загружаемые методики были
  на английском, чтобы токен-стоимость каждой сессии снизилась без потери качества.
- Требование: Когда выполняется перевод волны, система должна первой группой
  перевести на английский файлы always-загрузки — onboarding-блок AGENTS.md
  и using-skills — с прохождением полного цикла качества (REQ-04, REQ-05)
  до перевода остальных групп.
- Обоснование: ~25 KB всегда-загрузки оплачивается в каждой сессии; это
  максимальный токен-выигрыш и основа для правила языка сессии (REQ-01).
- AC:
  - Given цикл качества REQ-05 пройден для группы always-загрузки
    - When выполняется гейт REQ-06
    - Then 0 файлов кириллицы в onboarding-блоке AGENTS.md и using-skills,
      семантическое ревью и редактура носителем зафиксированы для каждого файла.
  - Given перевод ядра завершён
    - When замеряется токен-стоимость (NFR-04)
    - Then стоимость always-загрузки не увеличилась относительно зафиксированного
      RU-бейзлайна замера (REQ-06).
- Приоритет: Must
- Источник: pre-requirements 2026-11-11 («Порядок перевода»); консилиум `e08602`.

### REQ-03 — Перевод остальных групп поставки

- История: Как пользователь Wolf, я хочу, чтобы вся поставка методик была
  на английском, чтобы канон был единым, а сопровождение — одинарным.
- Требование: Когда волна завершается, все md-файлы `templates/` (остальные
  скиллы, агенты, команды, прочие файлы поставки) должны быть на английском:
  по замеру 2026-11-11 — 53 скилла, 9 агентов, 3 команды и прочие файлы группами
  «перевод → цикл качества» по каждой группе.
- Обоснование: решение владельца D1 — EN единственный канон; двойное авторство
  при одном контрибьюторе не сопровождается (отвергнут вариант A).
- AC:
  - Given перевод всех групп завершён
    - When выполняется автоматический гейт кириллицы (REQ-06)
    - Then 0 файлов с кириллицей в `templates/` (по замеру 2026-11-11 таких 67
      из 69 md).
  - Given файл относится к любой группе поставки
    - When проводится контроль
    - Then для него существует запись о пройденных циклах REQ-05 (нет файлов,
      переведённых «в обход» процесса).
- Приоритет: Must
- Источник: диалог с владельцем 2026-11-11 (D1); решение
  `mem_20261111_lang-strategy-en-canon_2cf228`.

### REQ-04 — Глоссарий RU→EN до старта перевода

- История: Как переводчик волны, я хочу согласованный глоссарий терминов до старта
  перевода, чтобы 68+ файлов использовали одни и те же английские термины Wolf.
- Требование: Когда начинается перевод любой группы, должен существовать
  глоссарий RU→EN, утверждённый владельцем проекта (термины Wolf
  face/thread/steward/skill и методическая терминология), и каждый перевод
  должен использовать его варианты; новые термины добавляются в глоссарий,
  а не переводятся каждый раз заново.
- Обоснование: согласованность терминов — условие качества методик и проверки
  NFR-03; глоссарий, утверждённый владельцем, дешевле правки разнобоя после.
- AC:
  - Given глоссарий не существует или не утверждён владельцем проекта
    - When планируется перевод группы
    - Then перевод группы не начинается, пока владелец не утвердит глоссарий.
  - Given глоссарий утверждён
    - When выполняется контроль согласованности (NFR-03)
    - Then один русский термин оригинала соответствует одному английскому варианту
      во всех переведённых файлах (список исключений — в самом глоссарии).
- Приоритет: Must
- Источник: pre-requirements 2026-11-11; решение владельца (условие 3 перевода).

### REQ-05 — Циклы качества перевода

- История: Как владелец методик, я хочу несколько независимых ревью-циклов
  на каждую группу файлов, чтобы перевод не снизил качество методик.
- Требование: Когда группа файлов переводится, для каждой группы должны быть
  выполнены и зафиксированы независимые циклы: (1) семантическое ревью против
  русского оригинала, (2) редактура читаемости носителем языка, (3) повторный
  контроль выборки файлов группы после правок. Машинный прогон не засчитывается
  как цикл.
- Обоснование: требование владельца «тщательно, без снижения качества»; перевод —
  не машинный прогон (условие 3 решения `2cf228`).
- AC:
  - Given группа прошла только машинный перевод без ревью-циклов
    - When файл группы проверяется на готовность
    - Then файл не считается переведённым: нет записей о трёх циклах.
  - Given все три цикла группы выполнены
    - When повторный контроль выборки (≥10% файлов группы, минимум 1 файл)
      находит смысловой дефект
    - Then дефект исправляется и цикл (3) повторяется на новой выборке до первой
      выборки без смысловых дефектов.
- Приоритет: Must
- Источник: pre-requirements 2026-11-11 («Предложения по исполнению»); решение
  `mem_20261111_lang-strategy-en-canon_2cf228`.

### REQ-06 — Автоматические гейты волны

- История: Как контрибьютор Wolf, я хочу автоматические проверки языка и состава
  поставки, чтобы регрессия в RU или порчу состава поймала CI, а не пользователь.
- Требование: Когда поставка собирается или проверяется, автоматические гейты
  должны проверять: (1) 0 файлов с кириллицей в `templates/`; (2) зелёные тесты
  состава поставки (`npm run check`, включая `tests/unit/package-hygiene.test.ts`:
  files = dist + templates + update-map.json); (3) замер токен-выигрыша
  (`bench:tokens`) на 2–3 файлах always-загрузки против зафиксированного
  RU-бейзлайна; (4) глоссарий-консистентность — 0 несогласованных терминов
  по списку глоссария RU→EN (автоматическая проверка NFR-03).
- Обоснование: гейты из синтеза консилиума `e08602`; при темпе ~65 релизов/72 дня
  без автоматики EN-канон деградирует.
- AC:
  - Given перевод волны не начат
    - When выполняется замер `bench:tokens` на 2–3 файлах always-загрузки
    - Then RU-бейзлайн зафиксирован артефактом замера в репозитории (файлы,
      число токенов, версия) до старта перевода; гейт (3) сравнивает EN-замер
      с этим артефактом.
  - Given в `templates/` появился файл с кириллицей или несогласованный термин
    - When выполняется `npm run check`
    - Then проверка падает с указанием файла или термина.
  - Given волна перевода завершена
    - When выполняются гейты (1)–(4)
    - Then все проверки зелёные, и результат сравнения EN ≤ RU-бейзлайн приложен
      к закрытию волны.
- Приоритет: Must
- Источник: pre-requirements 2026-11-11 («Гейты качества»); консилиум `e08602`.

### REQ-07 — Синхронизация тестов и сценариев, зависящих от языка поставки

- История: Как контрибьютор Wolf, я хочу, чтобы тесты, гейты и demo-сценарии
  отражали EN-поставку, чтобы «зелёные» проверки соответствовали реальному
  содержимому пакета.
- Требование: Когда язык артефактов поставки меняется, все проверки, зависящие
  от языка поставки, должны быть синхронизированы до закрытия волны:
  `tests/unit/package-hygiene.test.ts`, e2e-состав (bootstrap, base-set,
  distribution, scaffold, upgrade и зависимые), `scripts/demo/scenario-1..8`,
  `scripts/check-english-surface.mjs`, `npm run docs:build` (генерация
  CLI-справки и сборка сайта от содержимого поставки).
- Обоснование: часть этих проверок ищет русские строки-маркеры или сравнивает
  тексты; без синхронизации волна закрывается на красной CI.
- AC:
  - Given EN-поставка в репо
    - When выполняются `npm run check`, `npm run e2e`, `npm run docs:build`
    - Then все три проходят без пропусков (skip), связанных с языком поставки.
  - Given demo-сценарий `scenario-1..8` прогоняется на EN-поставке
    - When проверяется его вывод
    - Then сценарий демонстрирует EN-методики и штатно завершается.
- Приоритет: Must
- Источник: pre-requirements 2026-11-11 («Границы», входит); замеры репо
  2026-11-11.

### REQ-08 — Миграционная волна upgrade существующих проектов

- История: Как владелец существующего проекта на Wolf, я хочу одной командой
  upgrade перейти на EN-поставку, чтобы не терять локальные правки и не мигрировать
  вручную.
- Требование: Когда выпускается волна upgrade, Wolf должен обновить штампованные
  файлы проекта (~68 по оценке владельца) на EN-версии с обязательными условиями:
  (а) автоматический бэкап каждого заменяемого файла до замены; (б) файл без
  локальных правок заменяется без вопросов; (в) файл с локальными правками не
  перезаписывается молча — Wolf показывает конфликт и предлагает штатные
  resolve-стратегии protect/keep/take; (г) итог миграции (заменено/сохранено/
  отложено, путь бэкапов) фиксируется в выводе upgrade.
- Обоснование: решение владельца D3 — одна волна, а не дрейф по релизам; каждый
  обычный релиз штампует новые RU-копии и увеличивает стоимость миграции.
- AC:
  - Given проект со штампованными RU-файлами без локальных правок
    - When выполняется upgrade волны
    - Then все штампованные файлы заменены на EN, бэкапы созданы, вопросов нет.
  - Given один штампованный файл имеет локальные правки
    - When выполняется upgrade волны
    - Then файл не потерян: Wolf показывает конфликт, пользователь выбирает
      protect/keep/take, выбор и исходная версия (бэкап) сохраняются.
  - Given upgrade волны завершён
    - When проект проверяется
    - Then в штампованных файлах проекта 0 кириллицы (кроме файлов, оставленных
      по protect/keep с зафиксированным выбором пользователя).
- Приоритет: Must
- Источник: диалог с владельцем 2026-11-11 (D3); решение
  `mem_20261111_lang-strategy-en-canon_2cf228`; консилиум E2/E3.

### REQ-09 — RU-чтение методик через зеркало сайта

- История: Как русскоязычный пользователь, я хочу продолжать читать методики
  по-русски на сайте, чтобы переход поставки на EN не лишил меня RU-чтения.
- Требование: Когда волна перевода закрывается, RU-чтение методик должно
  обеспечиваться существующим RU-зеркалом сайта: сайт остаётся EN-канон + RU-зеркало,
  и зеркало синхронизируется с итогами волны. Зеркало не является частью npm-поставки
  и не может заменить её канон.
- Обоснование: условие 2 решения владельца `2cf228`; RU-чтение — через сайт,
  не через поставку.
- AC:
  - Given волна перевода закрыта
    - When проводится синхронизация RU-зеркала
    - Then зеркало соответствует итоговому EN-канону методик (актуальные версии,
      помеченные датой синхронизации).
- Приоритет: Should
- Источник: решение `mem_20261111_lang-strategy-en-canon_2cf228` (условие 2);
  pre-requirements 2026-11-11 («Границы»).

## 5. Нефункциональные требования (NFR)

### NFR-01 — Семантическая эквивалентность перевода

- Требование: перевод каждого файла `templates/` должен сохранять смысл, полноту
  и структуру методики русского оригинала: ни одно правило, ограничение или шаг
  процедуры не теряется и не добавляется при переводе.
- AC: семантическое ревью против оригинала (REQ-05, цикл 1) пройдено для 100%
  файлов; повторный контроль выборки (цикл 3) не находит смысловых дефектов
  в закрываемой выборке; расхождения, где EN-формулировка сознательно улучшена,
  зафиксированы в журнале перевода группы, а не «потеряны».
- Источник: требование владельца «без снижения качества методик»; решение
  `mem_20261111_lang-strategy-en-canon_2cf228`.

### NFR-02 — Читаемость носителем языка

- Требование: переведённые файлы должны читаться как написанные на английском:
  каждый файл проходит независимую редактуру носителем языка (native-readability
  edit), а не только семантическую сверку.
- AC: для 100% файлов существует запись о цикле редактуры (REQ-05, цикл 2);
  контроль выборки не находит файлов с калькированным «русско-английским» текстом.
- Источник: pre-requirements 2026-11-11 («редактура читаемости носителем языка»).

### NFR-03 — Согласованность терминов по глоссарию

- Требование: один термин оригинала соответствует одному варианту перевода
  по глоссарию RU→EN во всех файлах поставки; исключения перечислены в самом
  глоссарии.
- AC: автоматическая проверка согласованности по списку глоссария находит 0
  несогласованных вариантов в `templates/`; новые термины появляются в глоссарии
  до их использования в переводе.
- Источник: pre-requirements 2026-11-11 («глоссарий-консистентность» как гейт).

### NFR-04 — Токен-бюджет always-загрузки

- Требование: токен-стоимость always-загрузочного ядра в EN-поставке не должна
  превышать стоимость зафиксированного RU-бейзлайна (артефакт замера до старта
  перевода, REQ-06); ожидается снижение (перевод русского текста на английский
  обычно короче).
- AC: замер `bench:tokens` на 2–3 файлах always-загрузки фиксирует
  EN ≤ RU-бейзлайн по каждому замеренному файлу; результат сравнения с бейзлайном
  приложен к закрытию волны.
- Источник: консилиум `e08602` (validation токен-выигрыша); pre-requirements
  2026-11-11 («Гейты качества»).

## 6. Ограничения и допущения

Допущения:

- Один контрибьютор, темп ~65 релизов за 72 дня (основание отказа от двуязычия) —
  любые процессы волны должны быть автоматизируемыми.
- Замер базы 2026-11-11: `templates/` = 73 файла (69 md, 67 md с кириллицей,
  ~500 KB); в pre-requirements фигурировало «69 из 73 с кириллицей» — итоговое
  число фиксируется гейтом «0», а не этой оценкой.
- Оценка ~68 штампованных файлов в существующих проектах — из решения владельца;
  точный набор подтверждается сценарием upgrade волны.
- Опция выбора языка поставки в CLI отсутствует и в этой волне не добавляется
  (отвергнутый вариант A).
- Память Wolf остаётся единственным источником состояния проекта; правило языка
  сессии фиксирует выбор записью в памяти Wolf (REQ-01), а не в конфиг-файле —
  если design выберет иное место фиксации, это изменение требований через CR.

Открытые вопросы (не разрешены этим документом — передаются design/ревью):

- **В1. Размещение правила языка сессии**: поведение зафиксировано REQ-01
  (в составе always-загрузки), но конкретный файл-носитель и точная формулировка
  уточнения при первой сессии — решение design-волны.
- **В2. Границы перевода в нетекстовых артефактах** (строки ошибок CLI, update-map,
  термины в коде): по умолчанию вне scope волны, кроме мест, где язык поставки
  зашит в логику; точный перечень — на design (см. раздел 2).
- **В3. Resolve-стратегия по умолчанию для волны upgrade**: REQ-08 фиксирует
  «конфликт не перезаписывается молча» и штатные protect/keep/take; значение,
  предлагаемое по умолчанию при волне (подсказка take пользователю), требует
  подтверждения владельца на ревью этого документа.
- **В4. Переходный период смешанных проектов владельца** (часть RU, часть EN) —
  вне scope волны; выделить отдельной работой после закрытия миграции.
