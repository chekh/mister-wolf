# Заметки релиза — mister-wolf 3.1.0 (волна english-base-delivery)

Дата: 2026-11-15. Ветка: en-base-wave. Номер версии 3.1.0 подтверждён владельцем;
публикация (npm version, тег `v*`, коммит) — отдельный шаг T-43 по явному
поручению владельца, в эти заметки не входит. Подготовлено на ревизии
3f9e5f66 (HEAD en-base-wave на момент подготовки); `update-map.json` на момент
подготовки — в рабочем дереве (незакоммичен, T-35).

## Состав волны

- **Полный перевод поставки на английский** — `templates/base/**`: 9 агентов
  (mr-wolf + 8 `wolf-*`), 35 скиллов (SKILL.md + references), 3 команды
  (`analyze-doc`, `complain`, `doc-review`), `AGENTS.md` с новой секцией
  «Session language» (правило языка сессии, REQ-01: уточнить язык один раз,
  зафиксировать решением Wolf, артефакты поставки остаются EN); кодовые файлы
  плагинов `opencode/plugins-reserved/wolf-router.ts` и `wolf-session-start.js`
  — переведены полностью, включая комментарии (решение R3), плюс их `README.md`.
- **wolf-git канон**: `git-collaboration-policy-v1.1.md` — канон
  (`docs/reference/`) и поставка (`templates/base/skills/wolf-git/reference/`)
  байт-в-байт равны; sha256
  `de60c9b5407d93fe32da93ceda15e6d8c638fe7640c126460f09b8afa81dde70`
  (константа `CANON_SHA256` в `tests/unit/skills/wolf-git-contract.test.ts`).
- Каждая группа G0..G5 прошла полный цикл качества REQ-05: перевод →
  семантическое ревью против RU-оракула (git-история до перевода) → редактура
  носителем языка → контрольная выборка ≥10% до чистой; пофайловый журнал —
  `translation-log.md` в папке волны.
- Тесты и demo синхронизированы с EN-поставкой (REQ-07): юнит- и e2e-ассерты
  бьют в EN-шаблоны; новые e2e — `tests/e2e/delivery-language-rule.e2e.ts`
  (SC-01) и `tests/e2e/upgrade-language-wave.e2e.ts` (SC-19..SC-23);
  demo-сценарии 1..8 синхронизированы и прогнаны.
- Гейты языка в `npm run check` (REQ-06): `check-delivery-language`
  (0 кириллицы в `templates/**`, байтовый скан без исключений) →
  `check-glossary-consistency` (approved-строки глоссария, запрещённые aliases)
  → `check-english-surface` → `format:check` → `build` → `test:run`.
- **Намеренно осталось русским** (design §6.1): RU-фикстуры тестов (это контент
  пользователя, не поставки) и вывод CLI `wolf` (RU-язычный продукт, вне скоупа
  волны); `src/` вне `adapters/**` — RU-комментарии не трогаются (F-P1, ADR-6).

## Миграция существующих проектов (REQ-08)

- Данные волны, без нового кода (ADR-5): переведённые `templates/` +
  перегенерированный `update-map.json` — 65 file targets `changed`
  (RU→EN против поставки 3.0.0), 7 faces (все `deprecated`, report-only),
  prev 3.0.0. Гейт карты:
  `node scripts/generate-update-map.mjs --verify` → «update-map.json is in sync
  with templates/» (exit 0 на T-35; guard-тест
  `tests/unit/adapters/update-map.test.ts` зелёный 9/9). Секция «Session
  language» доставляется в AGENTS.md проекта отдельным входом карты `agents_md`
  (mode `append-block`).
- **Порядок проверки пользователем**: обновить пакет
  (`npm install -g mister-wolf@3.1.0`) → `wolf upgrade` (или
  `wolf upgrade --here` для одного проекта) → прочитать отчёт
  (replaced / protected / kept / deferred + путь бэкапов).
- **Двухфазность миграции**: `wolf upgrade --here` без `--yes` только
  планирует (status `skipped`, decisions, ноль записей в проект); `--yes`
  применяет план. Конфликтные файлы при `--yes` — подсказка по умолчанию
  `take`, правка владельца бэкапится и заменяется; `protect` не предлагается
  и не трогается.

### (а) Faces волна не затрагивает

- Seed-шаблоны playbooks живут в `src/app/use-cases/seed-base-playbooks.ts`
  (русские тексты) — вне скоупа волны `templates/**`: перевод волны шаблоны лиц
  не меняет. Статус `diverged` существующих face-копий не меняется (F-R2
  скорректирован, design §4.6): число diverged до миграции равно числу после.
- Факт из теста SC-21: face-объекты в памяти проекта байт-в-байт нетронуты
  проходом `upgrade --here` (RU-тело цело). Существующие diverged-лица
  обрабатываются штатно, как и до волны (steward-zone; exit 2 «Done with
  attention» при needsDecision > 0).

### (б) Плагины — исход F-R3 (T-34)

- Исход (ведущий, 2026-11-14, подтверждён кодом и картой): копии
  `wolf-session-start.js` / `wolf-router.ts` **не штампуются** — рендер
  доставляет плагины только из `templates/opencode/plugins/`, в поставке
  есть лишь `plugins-reserved/` (R-12), поэтому копии вне AC-3 REQ-08 и вне
  целей миграции. Карта волны 3.1.0 (prev 3.0.0, 65 changed) записей
  плагинов не содержит вовсе: removed-записи остались в карте 3.0.0
  (report-only), существующие копии в проектах — локальное наследие
  ≤2.33.0, `wolf upgrade` их не трогает. Перевод G5 (wolf-router,
  wolf-session-start) выполнен в reserved-шаблонах репозитория до релиза —
  для будущих возвратов плагинов; пользовательские проекты он не затрагивает.
- Проверка карты: `node scripts/generate-update-map.mjs --verify` →
  «update-map.json is in sync with templates/».

### (в) base/README.md

- `templates/base/README.md` вне sync-целей карты — проходом `upgrade` не
  мигрируется (штатно для этой волны; файл уже EN, в журнале перевода запись
  «перевод не требуется»).

### (г) Откат

- Общий путь: restore из `.wolf/backup/` **копированием назад** — ручная
  процедура, новый код не требуется; конкретный путь бэкапов печатается в
  отчёте upgrade.
- Оба пути честно:
  1. **Локальные правки (mutated → take при `--yes`)** — бэкапятся в
     `.wolf/backup/upgrade/<date>/`; откат — копирование файла из бэкапа назад
     (правка владельца сохранена в бэкапе).
  2. **Синхронизационные замены (code `updated`)** — бэкапа не создают; старая
     версия доступна в пакете 3.0.0, поэтому откат sync-замен выполняется
     переустановкой `mister-wolf@3.0.0` и повторным `wolf upgrade`.
- Повторный upgrade после частично выполненной или откаченной миграции
  идемпотентен: EN-файлы видны как unchanged/taken, повторяются только
  отложенные конфликты.

### (д) Две строки по итогам волны

1. **Playbook-дублирование**: возобновлённые 3.0-сессии могут при первой
   пересборке показать playbook дважды — безвредно (разовое косметическое
   дублирование playbook-блока, самогаснущееся; вердикт переводчика E1 по
   INJECT_HEADER, T-29).
2. **Расхождение формулировок**: миграция двухфазна — `wolf upgrade --here`
   без `--yes` только планирует (status `skipped`, decisions, ноль записей);
   формулировка «конфликт не перезаписывается до явного resolve» относится
   к этой фазе; `--yes` применяет план, и mutated при этом бэкапится и
   заменяется (take) (T-37, находка контракта по SC-20/SC-23).

## Что волна не делает

- Не переводит `src/` вне `adapters/**`, вывод CLI `wolf` и RU-фикстуры тестов —
  намеренно (см. «Состав волны»).
- Не меняет код Wolf: волна — данные (переведённые шаблоны + карта); из кода —
  только два гейт-скрипта и wiring в `npm run check` (ADR-5, design «Места
  нового кода»).
- Не заявляет измеренных эффектов скорости или стоимости.
