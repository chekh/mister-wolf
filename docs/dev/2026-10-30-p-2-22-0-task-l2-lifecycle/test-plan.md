# 2.22.0 — срез P: компактный TASK и жизненный цикл L2 — тест-план

AC — единый источник: `requirements.md` этого пакета. Здесь не переизобретаются критерии,
а задаётся **как** и **чем** каждый проверяется, и — отдельной колонкой — чем **не**
проверяется. Последнее обязательно: structural lint не доказывает фактический выбор
сеанса (design ADR-4, NFR-P5).

Baseline: `5ec4e4f`. Профиль проекта: `node scripts/check-english-surface.mjs`,
`npm run format:check`, `npm run lint`, `npm run build`, `npm run test:run`; документация и
сайт — `npm run docs:build`.

## Классы проверок

- **mandatory** — общий гейт проекта; отсутствие при наличии риска — нарушение
  (REQ-14 действующего requirements).
- **impact** — по влиянию изменённого файла (шаблон, рендер, плагин).
- **exploratory** — исследовательская, не входит в гейт; результат честно помечается.

## Сценарии

### REQ-P01-1 — Общее ядро TASK

- Given канонический `templates/base/skills/using-skills/SKILL.md` на revision среза
- When читаю секцию «Контракты передачи»
- Then присутствуют восемь элементов ядра, каждый — предписанием, не перечислением через запятую
- И ядро обязательно для каждого TASK; опускаются только профильные поля
- И любая другая методика со словом TASK не содержит второй формулировки ядра
- Маппинг: grep-проверка по `templates/base/**` (impact) + чтение файла
- Класс: impact. Не проверяется: машинная валидация полноты ядра (парсера нет — design ADR-3)

### REQ-P01-2 — Три профиля TASK

- Given канон среза
- When собираю три поручения: правка кода, ревью, исследование
- Then `implement` содержит `base_sha`/allowlist; `review`/`research` их не требуют
- И сохранены роль-специфичные составы отчёта: `implement` — `DONE|…|BLOCKED`;
  `review` — `SUMMARY/VERDICT/FINDINGS/SCOPE/LIMITS/EVIDENCE` + `APPROVED|CHANGES_REQUIRED|INCONCLUSIVE`;
  `research` — `FINDINGS/CONFIDENCE/GAPS` и разделение источника/факта/вывода/гипотезы
- И формы заполнены на реальной задаче, а не только объявлены
- И дифф `src/domain/schemas/**` пуст
- Маппинг: чтение трёх форм в каноне + `git diff --stat src/domain/schemas/` (mandatory)
- Класс: impact

### REQ-P01-3 — Статический словарь

- Given канон среза
- When ищу определения TASK/RESULT/EVIDENCE/ACCEPTANCE/SCOPE/LIMITS-GAPS
- Then все шесть определены статически, без обещания непоставленного механизма
- Маппинг: чтение канона (impact)
- Не проверяется: генерация/эволюция словаря — механизма нет по определению среза

### REQ-P04-1 — Правило fresh/continue/replace

- Given `templates/base/agents/executor-lead.md` на revision среза
- When читаю секцию «Диспетчеризация воркеров»
- Then три выбора определены с основанием и действием
- И явно сказано, что `task_id` ≠ id сеанса
- И `continue` не расширяет scope
- И после ACCEPTED прежний L2 не свободный слот
- И зависимые методики содержат ссылки, не вторые формулировки
- Маппинг: чтение + grep-проверка отсутствия дубля (impact)
- Класс: impact

### REQ-P04-2 — Правило после решения делегировать

- Given канон правила
- When читаю границу применения
- Then содержит явное «после решения делегировать»
- И малая связанная работа не создаёт нового L2
- И self-review не засчитывается независимой приёмкой
- Маппинг: чтение (impact)
- Класс: impact. Не проверяется: фактическое число спавнов в прогоне (см. AC-08/NFR-P4)

### REQ-P04-3 — Замена: сохранность и model/variant

- Given канон порядка replace
- When читаю четыре шага
- Then прекращение записи и закрытие сессии различимы
- И таймаут не трактуется как доказанная остановка
- И read-only review не требует нового worktree
- И неподдержанная в resume смена модели требует нового исполнителя
- И незавершённая приёмка не обнуляется: результат и открытые замечания переходят через handoff
- Маппинг: чтение `executor-lead.md` + `wolf-handoff/SKILL.md:17,43` (impact)
- Класс: impact. Не проверяется: реальная семантика host при resume и фактический учёт
  расходов (A1.1/E2) — exploratory, результат помечается как непроверенный

### REQ-P04-4 — Независимость первого ревью

- Given раздел о первом review
- When читаю перечень непередаваемых материалов
- Then названы: история родителя, чужие findings, ожидаемый verdict
- И новый id при непроверенной изоляции не закрывает гейт: `INCONCLUSIVE`/ограничение
- И честный отчёт о возможностях host не приравнивается к успешной независимой приёмке
- Маппинг: чтение + сверка с `templates/base/skills/wolf-review/SKILL.md` (impact)
- Класс: impact

### REQ-P03a-1 — Указатель в действующем requirements

- Given `docs/dev/2026-10-26-wave-2-22-0-expert-package/requirements.md`
- When смотрю дифф против baseline
- Then добавлен блок-указатель на очередь (roadmap-v4 ред. 6) и матрицу §14
- И ни одна исходная формулировка REQ/AC не изменена
- И `status:` остаётся `draft`
- И отложенные идентификаторы перечислены с адресом остатка
- Маппинг: `git diff baseline -- <файл>` + проверка `status:` (mandatory для этого файла)
- Класс: mandatory

### REQ-P03b-1 — Доставка и фактическая загрузка

- Given срез смержен и `wolf sync` выполнен
- When повторяю `wolf sync`
- Then дифф пуст (идемпотентность)
- И штампы `.opencode/**` равны версии выпуска
- И файлы с `protect:` перечислены как удержанные
- When читаю установленный `.opencode/skills/using-skills/SKILL.md`
- Then он содержит новое ядро и профили (не только изменённые bytes)
- Маппинг: `wolf sync` дважды + grep штампа + чтение установленного файла (impact)
- Класс: impact. Не проверяется: загрузка скилла конкретным harness-клиентом — exploratory

### REQ-P03b-2 — Human-facing и совместимость

- Given release notes и документация среза
- When читаю объяснение
- Then описано, что изменилось и чего срез не делает
- И каждая упомянутая команда существует в `wolf --help` этой revision
- И публичные схемы и статусы не изменены
- Маппинг: чтение + `wolf --help` сверка + дифф схем (impact)
- Класс: impact

### Явный список целей и исключений NFR-P1

Проверка NFR-P1 — не «зелёный grep по дереву», а сверка по именованному списку:

**Цели (должны стать точечными ссылками на канон):**

- `templates/base/skills/wolf-plan/SKILL.md:23` — полный перечень полей ядра;
- `templates/base/skills/wolf-review/SKILL.md:17-19` — перечень полей TASK в трёх строках.

**Исключения (остаются как есть, владелец B0, не покрываются AC среза P):**

- `templates/base/skills/using-git-worktrees/SKILL.md:27` — частичный перечень
  (`base_sha`, `allowlist`, `checks`);
- `templates/base/skills/requesting-code-review/SKILL.md:21` и `:27-30` — частичные
  перечни полей в пакете ревьюера и в конечном мандате.

Граница: исключение фиксируется адресом, а не «файл целиком вне проверки»; при
добавлении нового перечня в этих файлах запись исключения обновляется вместе с ним.

## Существующие тесты, на которые опирается срез

Не создаём новых harness'ов (design ADR-4). Используются:

- `tests/unit/wolf-session-start-plugin.test.ts` — инъекция усечённого тела L2;
- `tests/unit/adapters/render/plugin-injection.test.ts` — тело инъекции как контракт;
- `tests/unit/adapters/render/opencode-renderer.test.ts` — штампы, protect, sync;
- `tests/unit/adapters/render/sync-state.test.ts` — «наши байты» vs локальные правки;
- `tests/unit/adapters/render/stamp.test.ts` — формат отпечатка;
- `tests/unit/conveyor-skills-guard.test.ts`, `tests/unit/base-frames-guard.test.ts` —
  структурные гварды шаблонов (место для проверки состава ядра, если понадобится).

Новый тест допустим только там, где существующий гвард не покрывает проверяемое свойство;
его отсутствие — не повод объявлять свойство проверенным.

## Прогоны

- Точечные: `npx vitest run tests/unit/adapters/render tests/unit/wolf-session-start-plugin.test.ts`
- Полный гейт: `npm run check` (english-surface → format:check → lint → build → test:run)
- Документация/сайт: `npm run docs:build`
- Структура артефакта: соответствие шаблону генератора + независимое ревью документа

## Что этим планом НЕ проверяется

- Реальная экономия/сокращение контекста — нет измерения (A1.1/A1.2, AC-08).
- Фактический выбор сеанса harness'ом — зависит от host; непроверенное помечается.
- Сценарии, зависящие от неисправного router fallback — исключены до P-02 (design ADR-5).
- Runtime-контроль бюджета/таймера по TASK — граница среза (roadmap §2 п. 7).
