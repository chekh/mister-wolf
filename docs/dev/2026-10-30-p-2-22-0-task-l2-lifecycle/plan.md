# 2.22.0 — срез P: компактный TASK и жизненный цикл L2 — план

Срез P роадмапа v4 (ред. 6, §3–4). Входы: `requirements.md` (draft) — единственный
источник AC; `design.md` (draft) — единственный источник контрактов; `test-plan.md` —
проверки и маппинг. Baseline `5ec4e4f` (v2.21.2, main). Целевая версия **2.22.0**.

Правила исполнения:

- задачи идут фазами по результату, не «одна задача на REQ»; каждая — обратимый шаг с
  зелёным собственным гейтом;
- **этот этап — только документы и хвосты**; реализация (изменение `templates/**`) —
  следующий мандат. Задачи Ф1–Ф4 ниже помечены как неприступившие;
- общие файлы (`using-skills`, `executor-lead`, `wolf-handoff`) ведёт один владелец
  интеграции в порядке **P → B0 → A1.2 → E1** (roadmap §13);
- коммит делает lead, не исполнитель; TASK для L2: цель, AC/REQ, baseline, allowlist,
  зависимости, проверки, ожидаемый RESULT.

## Фазы и зависимости

```
Ф0 входы      T0 (пакет документов + указатель P-03a) ─> независимое ревью каждого документа
Ф1 канон      T1 (ядро+профили+словарь в using-skills) ─┐
              T2 (правило fresh/continue/replace в executor-lead) ─┤
              T2b (порядок replace/handoff-инварианты) ─────────────┤
Ф2 ссылки     T3 (точечные ссылки wolf-plan/sdd/execute/review/handoff) ← T1,T2
              T4 (усечённое тело L2 в plugin) ← T1
Ф3 доставка   T5 (sync/штампы/protect/идемпотентность) ← T1–T4
              T6 (human-facing: CHANGELOG, docs/site) ← T1–T5
Ф4 гейт       T7 (интеграция, полный check, evidence на revision) ← T1–T6
Ф5 выпуск     T8 (версия 2.22.0, тег, публикация) — следующий этап
```

T1 и T2 — разные файлы, независимы; T3 требует оба (ссылается на два канона).
T4 зависит только от T1. T5/T6 последовательны после канона.

## Владелец интеграции общих файлов

`using-skills` и `executor-lead` — общие для P/B0/A1.2/E1. Владелец этих файлов в срезе
P — L1 поставки P (этот контур). B0/A1.2/E1 основывают свои ветки на SHA принятого P и не
заменяют файл своей копией (roadmap §13).

## Точки проверки и чекпоинты

- После T1: ядро читается без профиля — L2 получает значимые входы.
- После T2: правило читается одно и без дубля в зависимых методиках.
- После T5: установленный набор реально содержит новое правило.
- Перед T8: независимая приёмка среза на точной revision.

## Что НЕ делается в этом этапе

Реализация `templates/**`, тесты кода, `npm run check` релиза, версия/тег/публикация —
следующий мандат (см. §Границы этапа). Документ не является разрешением на эти действия.
