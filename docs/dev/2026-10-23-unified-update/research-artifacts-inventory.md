## 3. Находки

### 3.1 История состава base-set: файлы только росли; одно удаление — playbook

`git log --diff-filter=DR -- templates/` за всю историю даёт ЕДИНСТВЕННОЕ
удаление: `templates/base/playbooks/wolf-review-lenses.md` (9cb4b23,
2026-09-29, «диета волны 2.13»). Переименований нет. Вехи добавлений:

- 2026-08-31: агенты (6), команды (3), ядро скиллов, AGENTS.md, первые
  playbook-шаблоны (0531dec и др.);
- 2026-09-28: `executor-lead-playbook.md` (41cff97) — шаблон лица, которого
  не было у проектов, инициализированных раньше (корневой пробел из §1
  requirements);
- 2026-10-08…11: 5 скиллов (receiving-code-review, writing-skills,
  wolf-skill-intake, wolf-design, wolf-testplan, wolf-explain) — вошли
  в 2.18.0 (тег 2026-10-14).

Orphaned-ФАЙЛОВ в проверенном парке нет: состав 30 файлов во всех трёх
проектах соответствует текущему base-set.

### 3.2 Orphaned-лицо в парке (прямой прецедент)

adminvps, `.wolf/memory/shared/playbooks`: 7 live-объектов = 6 текущих
шаблонов + `mem_20260929_wolf_review_linzy_v1…` (owner_skill: mr-wolf),
посеян 2026-09-29 из шаблона, удалённого из main в тот же день (окно между
релизом шаблона и диетой 2.13). Механизма деприкации нет: лицо активно,
доставляется, обновляться по шаблону никогда не будет. Это единственный
найденный orphaned-артефакт, и он ровно того класса, который карта
обновления обязана уметь объявлять «устаревшим».

### 3.3 Лица в парке: расслоение память/base-set

- adminvps: полный набор лиц (7), штампы base-set 2.17.0 — память «новее»
  набора;
- trading-signal: base-set 2.18.5 (свежий sync), но 1 лицо из 6 — прямое
  подтверждение «sync не сеет»;
- Tender: лиц ноль (каталога playbooks нет; init до появления посева).

### 3.4 Аномалия штампов: set= отражает версию бегунка, не состав набора

adminvps и Tender: все 30 файлов `set=2.17.0`, при этом в составе 19 скиллов,
из которых 5 добавлены в main 2026-10-08…11 (вышли только в 2.18.0).
Ни один честный бинарь 2.17.0 такого состава не штампует. Гипотеза
(medium-high): sync выполнялся linked/dev-запуском из main в окне
08.10 → бамп 2.17.1, когда `package.json` на main ещё говорил 2.17.0, а
шаблоны уже были новыми (`wolfVersion()` читает package.json запустившего
кода). Вывод для карты: штамп — недостоверный маркер состава набора;
источник истины состава — сама карта/манифест, штамп годится только как
свидетель «когда последний раз касался».

### 3.5 Прочее

- AGENTS.md во всех трёх проектах — append-режим, без штампа: sync его не
  ведёт, онбординг-блок стареет вместе с версиями.
- Таксономия `memory_types` в config.yaml идентична во всех трёх проектах;
  обновление — ручная `wolf taxonomy`; в автоматический проход не входит
  (пробел для карты: класс «конфиг-схема» ≠ класс «таксономия»).
- Пользователи складывают своё в `.wolf/` (Tender: downloader.py, state.json,
  reports/) и `.opencode/` (trading-signal: edge-experiment — НЕ штампован,
  ihcc-\*, `agent/` с локальными агентами mql5/mt5) — граница «не трогать
  чужое» должна быть явной в карте.
- В mister-wolf восстановленное Стюардом лицо лежит в
  `.wolf/memory/shared/faces/`, посеянные в парке — в `shared/playbooks`:
  два места хранения playbook-объектов; карте нужен один канонический
  запрос «лицо по owner_skill», не обход каталогов.

## 4. Выводы для карты обновления

Покрывать в v1 (статусы уже дают существующие механизмы — карта лишь
декларирует их per-release):

- base-set файлы (агенты/скиллы/команды/плагины): new / changed / removed,
  статусы sync: created / updated / skipped-identical / skipped-mutated /
  conflict / orphaned;
- AGENTS.md: отдельный класс (цельный vs append-блок);
- базовые лица: seeded / skipped-live / diverged / legacy-absorbed —
  и объявление removed-шаблонов как «устаревших лиц» (сегодня обработчика
  нет — это ровно то, что карта делает видимым);
- config.yaml: schema_version (migrated ok / refusal-newer) и таксономия
  (ручная команда — кандидата в проход 2.19+);
- реестр: registered / schema_version / missing;
- CLI: from → to.

Отложить (не деструктивны / вне границы): events/relations/metrics форматы
(additive), кэши (перестраиваются), backup/, router.log, локальные и
сгенерированные артефакты (tool-скиллы, чужие файлы — инвариант «не
трогать»), доки/сайт.

Пробелы механики, которые карта должна зафиксировать как
«устаревшее без обработчика»: (а) удалённые playbook-шаблоны — лица живут
вечно (§3.2); (б) удалённые файловые шаблоны — orphaned только репортится,
удаления нет; (в) таксономия не входит в автоматическое обновление;
(г) недостоверность штампа set= как маркера состава (§3.4) — карте нужен
собственный манифест состава per-release.

  поставивший штампы, не восстанавливается.
- CHANGELOG использован только сверочно; первичный источник — git-история.
- FRICTION: 2× subagent (worker-researcher) — «Subagent depth limit reached
  (1)»; воркеры из под-сессии недоступны. Обошёл через самостоятельное
  исследование по wolf-execute (все правки — только в mister-wolf).
- Уверенность: механика (исходники) — high; парк (прямая проверка) — high;
  гипотеза §3.4 — medium.
