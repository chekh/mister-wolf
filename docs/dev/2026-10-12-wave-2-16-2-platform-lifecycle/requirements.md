# Волна 2.16.2 — функциональные требования

## 1. Контекст и проблема

Правило памяти mem_20261012_nomer_versii (полный X.Y.Z) должно жить в AGENTS.md каждого
проекта с Wolf, а не только в памяти. Переезд пользователей с OpenCode v1 на v2 не имеет
ремонтного пути: установка (плагины, конфиг) сделана под одну версию платформы, рантайм —
другой; `wolf doctor` этого не видит, починка ручная. Обратная операция — удаление Wolf из
проекта — отсутствует: пользователь не может штатно убрать штампованные файлы и записи в
конфигах платформ, не рискуя чужим контентом.

Метрика успеха: doctor детектит и чинит v1→v2 рассинхрон одной командой; uninstall удаляет
только Wolf-контент (проверяется тестами); правило версий доставляется в AGENTS.md.

## 2. Область

Входит: AGENTS.md-шаблон base-set (правило версий), детект+repair платформы в `wolf doctor`,
новая команда `wolf uninstall` (план, подтверждение, --purge).
Не входит: npm publish, деплой сайта, git-тег (запрещены до релиза), другие платформы
помимо OpenCode и Claude Code, миграции памяти.

## 3. Глоссарий

- **Штамп** — маркер `wolf:rendered base=<файл> set=<версия>` в начале отрендеренного файла.
- **wolf-sync-state** — `.opencode/wolf-sync-state.json`: rel-путь → sha256 записанного рендера.
- **Dual-плагин** — шаблон плагина, поддерживающий v1 и v2 OpenCode из одного файла (с 2.14.1).
- **Mutated-skip** — защита локально правленных штампованных файлов от перезатирания.

## 4. Функциональные требования

### REQ-01 — Версионная дисциплина в AGENTS.md
- История: Как владелец, я хочу чтобы формулировка правила «Номер версии всегда полный
  X.Y.Z» доставлялась в AGENTS.md каждого проекта, чтобы дисциплина соблюдалась агентами.
- Требование: правило в тексте mem_20261012_nomer_versii (полный X.Y.Z в планах, тредах,
  волнах, тегах и разговоре) добавляется в AGENTS.md шаблона base-set и доставляется в
  установленные проекты штатной sync-доставкой.
- AC: AGENTS.md шаблона содержит правило; sync-доставка покрыта существующими тестами
  стампов; счётчик скиллов не регрессирует (19).
- Приоритет: Must. Источник: бриф волны 2.16.2, решение владельца mem_20261012_28e792.

### REQ-02 — Ремонт платформы v1→v2 в wolf doctor
- История: Как пользователь, обновивший OpenCode с v1 до v2, я хочу чтобы doctor
  находил рассинхрон установки и чинил его, чтобы плагины и MCP работали без ручной чистки.
- Требование: `wolf doctor` детектит несоответствие «установлено под v1, рантайм v2» и
  зеркальное; `wolf doctor --repair` перерендеривает плагин и запись opencode.json под
  детектированную версию (расширение repair-зоны 2.16.0); `--dry-run` показывает план.
- AC: e2e-фикстура «установлено под v1 → рантайм v2 → doctor сообщает → --repair чинит →
  плагин/MCP работают»; идемпотентность повторного repair; dry-run без записей.
- Приоритет: Must. Источник: решение владельца mem_20261012_28e792 (вариант «а»).

### REQ-03 — wolf uninstall
- История: Как пользователь, я хочу штатно удалить Wolf из проекта, чтобы остаться с
  нетронутым собственным контентом.
- Требование: `wolf uninstall` печатает план и требует подтверждения (паттерн careful
  re-init: planInit + --yes); удаляет только штампованные Wolf файлы (.opencode/ агенты,
  скиллы, команды, плагины; wolf-sync-state) и wolf-записи в конфигах платформ, которые
  писал Wolf (OpenCode opencode.json, Claude Code .mcp.json); критерий принадлежности —
  штампы wolf-sync-state; `.wolf/` по умолчанию сохраняется с явным сообщением, `--purge`
  стирает; финальная подсказка `npm uninstall -g mister-wolf`.
- AC: после uninstall в конфигах и .opencode/ нет следов Wolf, чужой контент нетронут;
  с --purge .wolf/ удалена; dry-run (запуск без подтверждения) по умолчанию ничего не
  меняет; идемпотентность.
- Приоритет: Must. Источник: решение владельца mem_20261012_28e792.

## 5. Нефункциональные требования (NFR)

### NFR-01 — Идемпотентность
- Требование: повторный repair/uninstall — no-op с честным отчётом, exit 0.
- AC: тесты на второй прогон обеих операций. Источник: бриф.

### NFR-02 — Безопасность удаления
- Требование: без подтверждения ничего не удалять; чужие (нештампованные) файлы не
  трогать никогда; отсутствующий конфиг — честный skip с причиной.
- AC: тесты чужого контента (посторонний файл в .opencode/, посторонний MCP-сервер,
  занятый default_agent), skip-строки в отчёте. Источник: бриф.
