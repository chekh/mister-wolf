# patch-2-18-5 — требования и журнал изменений (fix-профиль)

## 1. Контекст и проблема

Независимое ревью 2.18.4 подтвердило два дефекта с воспроизведением (root cause установлен, расследование проведено ревьюером):

1. **ВЫСОКИЙ** — `templates/opencode/plugins/wolf-router.ts`: канонический `resolveFace` (type=face, status=active, проверка владельца) устроен верно, но router при результатах `none`, `multiple` и ошибке CLI одинаково откатывается к прежнему текстовому поиску, где проверяется только `owner_skill` без ограничения типа/статуса. Конфликт обнаруживается resolver'ом, а затем обходится: запасной поиск выбрал лицо в статусе `proposed` и внедрил его тело (подтверждено ревьюером на контролируемой фикстуре плагина).
2. **СРЕДНИЙ** — `src/app/use-cases/claim-artifact.ts`: полная проверка идентичности heartbeat работает только при явно переданных полях; обычный вызов учитывает только имя агента, хотя WOLF_SESSION доступен. Воспроизведение: старая сессия делает claim новой сессией того же агента — heartbeat без параметров и только с pid принят; старая session + token — отклонён.
3. **УЛУЧШЕНИЕ** (входит в scope): resolver возвращает version и hash, но router сохраняет только id и body; результат запасного поиска журналируется как variant=canonical — из журнала нельзя понять, как именно доставлена методика.

Base: tag v2.18.4 (commit 91a3d9a). Профиль: FIX (подтверждён L0). Методика: test-driven-development.

## 2. Функциональные требования

- REQ-01 (AC1): поведение router разделено по таблице — unique active face → доставить его; none → разрешён только явно ограниченный legacy-поиск note/howto с проверками типа/статуса (не только owner_skill); multiple → сообщить конфликт, НЕ выбирать и не внедрять методику; resolver error → диагностируемый сбой, не молчаливый fallback.
- REQ-02 (AC2): штатный вызов heartbeat проверяет сессию из WOLF_SESSION автоматически; фоновые задания обязаны передавать токен из claim; совместимость только по имени — явно обозначенный legacy-режим; поведение принятия переданного claim новой сессией определено и покрыто тестом.
- REQ-03 (AC3): журнал доставки фиксирует source=face/legacy/default, face_id, version, hash, resolution=unique/none/conflict/error, идентификатор сессии. Legacy-результат не маркируется variant=canonical.
- REQ-04: контракт resolver (resolveFace) не менять.
