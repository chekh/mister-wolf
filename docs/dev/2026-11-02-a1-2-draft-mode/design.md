# A1.2 — дизайн

## 1. Решение: ось плотности как носитель в существующем контракте execution

Носитель — расширение уже работающего контракта: `execution` в блоке TASK задаёт model/variant/mode и бюджет «существующим способом запуска, не новой конфигурационной схемой» (using-skills). Плотность входит той же дорогой: `density standard|draft` — отдельная ось, как требует §6. Операция выбора — запись поля L1 в TASK; операция доставки — доставленный TASK; операция исполнения — назначенная плотность в рамке/лице исполнителя; операция отчёта — фактическая плотность в RESULT. Никакого runtime, схемы, CLI: агент, игнорирующий поле, кодом не блокируется — это тексты-инструкции (та же природа, что P-01/P-04).

Альтернативы, отвергнутые:

- **Новая команда/флаг CLI** (`wolf density draft`) — новый публичный контракт без задачи: плотность живёт в поручении, а не в проекте; отвергнуто по границе A1.2 (не расширять публичную поверхность).
- **Поле в схеме памяти** — REQ-23A запрещает расширение публичной схемы; плотность доставки — свойство поручения.
- **Только текст в методиках без поля** — не носитель, прямо против REQ-12.

Значения: `standard` (умолчание, отсутствие поля = standard) и `draft`. Другие значения не вводятся; неподдержанное значение исполнитель возвращает L1.

## 3. Чего контракт не делает (честная граница)

- Не enforced кодом; no new statuses/parsers; модель и variant не меняются автоматически (плотность ≠ дешёвая модель, backlog «Расширенный standard/draft»).
- Экономия не заявляется: измеримое сравнение — последующее наблюдение разрешённой работы через `wolf usage import` (A1.1); этот релиз поставляет носитель, сценарии и протокол. Исход на момент выпуска: **эффект не оценён** (NFR-06/AC-08).

## 4. Протокол измеримого сравнения (REQ-24/25 минимум)

- **База:** 2.23.3 (§6: после 2.23.3 baseline именно эта версия; данные 2.23.0–2.23.2 — другая база).
- **Instrumentation:** `wolf usage import` (A1.1) — без новых событий; requested density — в TASK; фактическая — в RESULT; task_id — из явной карты поручения.
- **Парность:** сопоставимые задачи из сценариев fixture (см. test-plan §3); одинаковые права/инструменты/окружение; кэш и compacted-сессии фиксируются как условия прогона.
- **Вывод:** несколько обычных задач = пилотное наблюдение; причинный вывод и порог не заявляются. Данных мало → «эффект не оценён» с указанием покрытия.
