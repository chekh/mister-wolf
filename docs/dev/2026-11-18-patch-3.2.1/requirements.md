# 1. Цель

Закрыть дефекты, найденные пост-релизным ревью владельца v3.2.0 (журнал `mem_20261118_84e9a5`, вердикт CHANGES_REQUIRED). Решение о составе — `mem_20261118_c7374e`: в 3.2.1 входят
R-1, R-2, R-3, R-5; R-4 (CLI/MCP-операции противоречий) — отдельное поручение после патча.
Каждое требование имеет контрактом регрессионный тест: на коде 3.2.0 он красный
(воспроизведение владельца), после исправления — зелёный.

Базовая ревизия: `439d71d7` (v3.2.0), рабочая ветка `en-base-wave`.

# 2. Требования (REQ) и критерии приёмки (AC)

## REQ-321-1 (R-1, P1) — откат проверяет содержимое бэкапа до первой записи

Существующее поведение (дефект): проверка сравнивает сохранённое поле `entry.sha256`
с baseline-sha; содержимое бэкапа не хэшируется, порча обнаруживается после записи
в целевой файл.

- AC-1.1: повреждённый `backup.files[i].content` при интактном `sha256`-поле — откат
  отказывает со списком проблем, целевой файл не изменён, «nothing was written».
- AC-1.2: проверено содержимое **всех** backup-записей до первой записи (все-или-ничего).
- AC-1.3: повторное использование backup в `apply` (продолжение прерванного прогона)
  проходит ту же проверку содержимого до записи.
- AC-1.4: валидный кейс (не тронутый бэкап) — поведение отката не меняется (без регрессии).

## REQ-321-2 (R-2, P1) — единый фильтр допуска для всех секций доставки

Существующее поведение (дефект): legacy-ветки доставки (правила/принятая память в
`get-call-injections.ts` и `generate-agent-brief.ts`) работают без учёта применимости,
подавлений противоречиями и worktree; микро-селектор фильтрует только свой путь.

- AC-2.1: объект с тегом `micro-note` доставляется ТОЛЬКО через микро-селектор —
  legacy-ветка его не доставляет ни в `call`, ни в `brief`.
- AC-2.2: правило, помеченное `micro-note` и `applies: [darwin]`, при контексте `linux`
  отсутствует в выводе `call` и `brief`; селектор честно сообщает «исключено».
- AC-2.3: активный объект, подавленный открытым противоречием, отсутствует во всех
  секциях вывода (`call`, `brief`), пока противоречие не разрешено.
- AC-2.4: объект со scope чужого worktree не доставляется в main (и наоборот).
- AC-2.5: атрибуция `id@rev` сохраняется для каждой фактически доставленной записи;
  итоговый вывод не содержит записей, которые селектор сообщил как исключённые.
- AC-2.6: универсальные объекты (без `applies`) доставляются как прежде — без регрессии.

## REQ-321-3 (R-3, P2) — apply сверяет scope.target_paths с baseline и patch

- AC-3.1: `scope.target_paths` не пересекается с путями `baseline.files`/`patch.files`
  → кандидат не принимается и не применяется (отказ до первой записи, причина названа).
- AC-3.2: пути нормализуются перед сравнением (одинаковые пути в разной записи — не ложный
  отказ); согласованный кандидат применяется как прежде (без регрессии).

## REQ-321-5 (R-5, P2) — тело микро-заметки доставляется в пределах бюджета

Существующее поведение (дефект): `formatMicroBlock` берёт только первую строку body.

- AC-5.1: многострочный body доставляется целиком, если влезает в бюджет (реплика
  владельца: «Build note / NEVER run deploy before approval» — доставлены обе строки).
- AC-5.2: при нехватке бюджета текст усекается с видимым маркером усечения, а не молча.
- AC-5.3: запись с тегом `constraint` не теряет смысловой текст из-за форматирования:
  обязательное ограничение доставляется либо целиком в бюджет, либо с явным маркером.
