# Аудит путей изменения face — REQ-04 (R05), design §7

Контракт строки: **путь → кому разрешён → защита**. Инвариант (design §7): лицо
(owner_skill-цепочка версий) изменяется только версионирующими путями; generic
transition/supersede/edit на face-тип запрещены; защита — в use-case слое, не
только в CLI (REQ-04 AC-4, негативный сценарий — вызов use-case напрямую,
минуя CLI). Строка/ref — на момент задачи T3 (ветка
feature/2-17-1-t3-req04-migrate).

## 1. Версионирующие пути (разрешённые)

| Путь                                                  | Кому разрешён                                                                                                                  | Защита                                                                                                                                                                                                                                                                                                                          |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `wolf face new` (createFaceVersion, command `new`)    | только `agent:steward`                                                                                                         | guard в use-case ДО op_started (create-face-version.ts, `guardFailure`): актор env-only (WOLF_ACTOR), параметр-актор у API отсутствует — подмена `--created-by` исключена структурно; G17-шаблон неопционален; вся цепочка — журналируемая операция §3.3 (staging candidate → activation), отказ — событие `memory.face.denied` |
| `wolf face restore`                                   | только `user:*`                                                                                                                | тот же guard (`guardFailure`); основа `--from` проверяется до op_started                                                                                                                                                                                                                                                        |
| `wolf face breakglass`                                | `user:*` и НЕ из агент-сессии                                                                                                  | guard: отказ при `WOLF_SESSION=opc-*`; событие `memory.face.breakglass` в журнале операции                                                                                                                                                                                                                                      |
| `wolf face migrate` (migrateFaces, command `migrate`) | служебный вход (внутренний вызов use-case из CLI-команды migrate; guard полномочий не применяется по design — вход внутренний) | операция §3.3 + разбор §3.4 (resume / idempotent-skip / healing по доказуемой связи / конфликт с exit ≠ 0); healing и resume не пишут body (AC-3)                                                                                                                                                                               |
| посев base-set (command `seed`, `wolf init`/re-init)  | служебный вход (initiator `seed`; T4)                                                                                          | guard не применяется (внутренний путь посева); изменение — только новая версия через общий механизм §3.3                                                                                                                                                                                                                        |

## 2. Восстановление (изменяет состояние операции, не содержание)

| Путь                                | Кому разрешён                      | Защита                                                                                                                                                                                                                                                                                                                                                                                             |
| ----------------------------------- | ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `wolf face recover <opId>` (resume) | любой актор (CLI/локальный запуск) | **защиты по актору нет — по design**: guard design'а требует актора только для new/restore/breakglass; recover дозавершает уже начатую операцию из детерминированного input (op_started) и не создаёт новое содержание; заметка ревью T2 (m2): путь включён в аудит с пометкой текущей защиты. Ошибочный opId — честная ошибка; завершённая операция идемпотентно возвращает состояние без записей |
| `wolf face recover <opId> --abort`  | любой актор (см. выше)             | ограничен состоянием: только до activation (после — отказ, «только вперёд» через restore); candidate → archived, история не уничтожается (NFR-02); op_aborted в журнале                                                                                                                                                                                                                            |

## 5. Негативные сценарии use-case-уровня (S-36, evidence)

`tests/unit/use-cases/face-generic-guards.test.ts` — прямые вызовы use-case,
минуя CLI:

- `transitionMemoryObject(faceId, 'archived')` → отказ `/face/i`, запись не
  изменена — GREEN;
- `editMemoryObject(faceId, {body})` → отказ `/face/i`, body не изменён — GREEN;
- `supersedeMemoryObject(faceId, noteId)` → отказ `/face/i`, запись не
  изменена — GREEN (guard в use-case, внутренний путь помечен
  `internalFacePath`);
- позитивный контроль: те же use-case на note работают как раньше (состав
  видимых путей не сужен).

## 6. Статус закрытия и расхождения

- Закрыто в T3: transition (CLI+MCP+archive), edit, аудит-перечень, healing и
  разборы миграции (S-32…S-35 — см. tests/integration/migrate-faces-healing.test.ts).
- Закрыто T3 решением L1 (расширение allowlist на face-operation.ts и
  `legacyHeadId` в CreateFaceVersionInput — create-face-version.ts):
  1. guard generic supersede — guard в use-case + `internalFacePath` на
     внутреннем вызове (supersede_prev); PROOF-тест перевёрнут в GREEN;
  2. шаг `supersede_legacy` ВНУТРИ операции migrate между `supersede_prev` и
     `announce` (design §3.4/F9): fresh-миграция передаёт `legacyHeadId`,
     смежная healing-операция убрана (осталась только для докомпьютерных
     частичных переходов 2.17.0); PROOF-тест перевёрнут в GREEN.
- Открыто (для решения L1):
  1. `wolf update --tags` на face — путь вне design-списка §7 (см. §4).
