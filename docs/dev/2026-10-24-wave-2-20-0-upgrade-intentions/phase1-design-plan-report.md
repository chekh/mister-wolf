## Spike R-01 — результат (кратко; полное evidence — design §5)

Окружение: macOS, `opencode v2.1.4` (`/Users/chekh/.opencode/bin/opencode`),
изолированный `mktemp -d` с подменой `HOME`/`XDG_*`, live-проект и live-конфиг не
участвовали, сети и вызовов модели нет.

- **Подтверждено (agent-файлы):** файл с `protect: true` и с `protect: 2.19.0`
  загружается, агент виден в `opencode debug agents`, `mode` распознан, stderr
  пуст, exit 0.
- **Опровергнуто в формулировке «игнорирует»:** неизвестный ключ не
  отбрасывается — он попадает в `request.body` (`{"protect": true}` /
  `{"protect": "2.19.0"}` против `{}` у control), то есть становится параметром
  model-запроса. Реакция провайдера (200 или 400) не проверена — **blocked**,
  план проверки приведён (design §5, plan T14).
- **Негативный контроль не сработал:** агент с битым YAML молча отсутствует в
  списке (exit 0, пустой stderr) → опираться на «ошибок нет» нельзя; отсюда
  требование структурной проверки frontmatter до rename.
- Skills/commands: read-only перечисления в v2.1.4 нет (`debug` знает только
  `agents|config|paths`; `api` вернул HTML на `GET /command`) — проверено
  опосредованно, ограничение зафиксировано.

**Уточнение фазы 3 (2026-10-25, после ревью M-1):** `opencode debug agents` в
v2.1.4 на этой машине возвращает `[]`, то есть вывод выше не воспроизводится;
первичным evidence стал перехват реального HTTP-запроса — провайдер отвечает
200, ключ `protect` в тело model-запроса **не попадает** (ни primary, ни
subagent). Риск R-01 для v2.1.4 снят; актуальное evidence — design §5, разбор —
`phase3-fix-report.md`.
