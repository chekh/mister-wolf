# Релиз 3.1.2 — явная механика языкового решения

Патч 3.1.2 закрывает находки пакета «Проверка поведения» (журнал: `docs/dev/2026-11-16-behavior-check/behavior-log.md`): правило языка сессии исполнялось по смыслу, но механические шаги записи пропускались.

## Что показала поведенческая проверка

- **Смена языка (s3).** Агент принял смену, ответил по-английски, записал новое решение — и написал в его описании «supersedes the previous», но команду `wolf supersede` не вызвал. В brief висели оба активных решения; восстановил ведущий вручную (механика `wolf supersede` при этом подтверждена — отказ был в шаге агента, не в инструменте).
- **Английская первая реплика (s4, s4b).** Ответ верный, вопроса нет, но решение не записано вовсе — стабильно 0 из 2 прогонов; русская первая реплика записывалась (1 из 1).
- Детекция и соблюдение языка ответа — 5 из 5 прогонов. Ломалась только запись в память.

## Changed

- **Запись языкового решения — обязательный механический шаг с явными командами.** Секция «Session language» в `AGENTS.md` теперь предписывает: после первой реплики пользователя — `wolf add --type decision --title "Session language: <lang>"`; при явной смене языка — записать новое решение и немедленно `wolf supersede <старый-id> <новый-id>`, чтобы активным оставалось ровно одно решение. Также зафиксирован приоритет: хостовые, платформенные и глобальные языковые правила по умолчанию не заменяют эту запись — при конфликте записывается язык сообщения пользователя (гипотеза проверки: именно конфликт с глобальным правилом «Язык: русский» вызывал пропуск записи при английской первой реплике).
- **`agent-language.md`** (изменение реестра карты этого патча) несёт ту же механику со ссылкой на нормативную секцию AGENTS.md.

## Доставка

- `templates/base/AGENTS.md` доставляется `wolf init` (вне реестра карты обновления), поэтому существующие проекты получают обновление правила через собственный корневой `AGENTS.md` (по политике проекта); референс скилла доходит штатным `wolf upgrade`. Набор хоста этого репозитория обновлён тем же выпуском (урок 3.1.1).
- Оценка размера тройки файлового гейта: 687/1241/1445 → 801/1241/1563 (`token-baseline.json` этой папки) — рост это явные команды и правило конфликта, которых потребовала проверка поведения.
