## 3. Спорные REQ — разбор

### 3.1 REQ-14 / REQ-19 — «классы проверок» и «условие остановки» существуют только как проза

В продукте есть ровно два близких механизма, но ни один не является требуемой трёхклассовой схемой.

### 3.2 REQ-16 / REQ-17 — курсор и инбокс: чего нет на самом деле

## 7. Риски и ограничения отчёта

1. **«Частично» означает разные вещи.** Для REQ-14/15/19 «частично» = есть текст методики, нет кода; для REQ-16/20/21/22 «частично» = есть код, нет полноты покрытия; для REQ-24/25 «частично» = аппаратура есть, но в лаборатории и вне продукта. При планировании волны эти три группы надо разводить отдельно.
2. **REQ-23 — самая дорогая дыра.** Пока нет writer'а usage, ни REQ-23, ни NFR-06, ни AC-08 не закрываются в принципе: нечем считать «стоимость принятой задачи». Это не «мало данных», это отсутствие измерителя. Требуется решение владельца: вводить writer (и тогда это кодовая задача волны 2.22) или закрывать REQ-23/24 явно как ограниченный/непроведённый исход (AC-01 это разрешает).
3. **Я не проверял истинность чисел в `.wolf/metrics`** — только их наличие и форму. Панель показывает шум 62.6% [BAD] и `prevented/checked: 0/0`; интерпретация (почему шум такой, почему prevented ноль) — вне моего мандата.
4. **По REQ-20 я оценивал механизм, а не поимённую дельту.** Если поимённая дельта (считает другой воркер) покажет, что какой-то исходник не покрыт картой, это может потребовать правки `update-map.json` — то есть изменения в `scripts/generate-update-map.mjs`/`update-map.json`, а не в `src/`.
5. **Тесты не запускались.** Все выводы о покрытии гейтов — из чтения состава test-файлов и `package.json`/workflows, а не из фактического прогона. `npm run check`/`e2e`/`docs:build` гоняет lead (по границе задачи).
6. **Версия инструмента аналитики.** Использовался `dist` репозитория (2.21.0, mtime 2026-10-26 14:17), а не установленный бинарь (`wolf` 2.20.1) — иначе часть выводов была бы по более старой версии. `wolf insights` печатает предупреждение о депрекейте (2.13) и отображает `analytics --view readiness`.
7. **Плагин `wolf-router` и `wolf-session-start` я читал только по строкам про model/effort/cache.** Полный аудит их поведения (что реально пишется в `.wolf/router.log` и в `skill-invocations.jsonl`) не проводился — для REQ-25 этого достаточно, чтобы сказать «batching и effort отсутствуют», но недостаточно, чтобы описать всю маршрутизацию.
8. **Приоритет.** По «цена / риск закрытия» на 2.22.0 первыми идут REQ-23 (нет измерителя) и REQ-17/REQ-16 (нет cursor → нет инбокса), затем REQ-14/15/19/24 (текст методики + прибор), затем REQ-18/25/26/20/21/22 (частично закрыты, доработки локальные).
