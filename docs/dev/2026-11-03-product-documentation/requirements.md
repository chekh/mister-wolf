# Требования

## 1. Контекст и проблема

Основание — согласованный диалог владельца 2026-11-03. Документация смешивает память, организацию и harness; пользователь видит внутренние команды раньше пользы. Эффективность не должна быть главным аргументом позиционирования.

## 2. Область

README EN/RU, сайт EN/RU и его навигация/главная, миграция docs/guide, актуальные ссылки, процедуры актуализации и проверки. Без изменения runtime, активных лиц, публикации npm, тега, merge/deploy и назначения версии. Публикация рабочей ветки и PR — предъявление результата.

## 3. Глоссарий

Пользовательская документация — опубликованный сайт, исходники docs/site. Инженерные документы — концепция, требования, дизайн, планы, исследования; остаются в Git. Самообучение — управляемое изменение методов и поведения, не обучение весов модели.
