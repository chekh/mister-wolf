## Сводка требований (REQ-01..REQ-05)

1. **REQ-01 (C1 — Служебный запуск Стюарда / Launcher):**
   - Фоновый запуск процесса Стюарда (`wolf job start --agent steward` / `wolf job learn --bg`) без блокировки терминала.
   - Detached-процесс с перенаправлением вывода в лог-файл `.wolf/jobs/<job_id>.log`.
   - Немедленный возврат CLI (`{ job_id, status: 'running', pid, log_path }`) с p95 < 200 ms.

2. **REQ-02 (C2 — Управление жизненным циклом и Job State):**
   - Инвариант: строго один активный job на проект.
   - Защита от параллельного запуска (отклонение второй попытки с кодом `JOB_ALREADY_RUNNING` и указанием текущего активного PID).
   - Жизненный цикл: `pending` → `running` → `completed` | `failed` | `cancelled` | `noop`.
   - Dead PID detection: автоматическое определение падения процесса (`ESRCH` через `process.kill(pid, 0)`), перевод в `failed` и безопасное снятие блокировки.
   - Команды инспекции: `wolf job status [id]`, `wolf job list`.

3. **REQ-03 (C3 — No-empty guard / Честный итог):**
   - Предварительный детерминированный аудит неагрегированных уроков (`detectUnaggregatedLessons`), открытых жалоб и необработанных предложений перед обращением к модели.
   - При 0 сигналов — отказ от вызова LLM/OpenCode, фиксация статуса `noop`/`skipped`, нулевой расход токенов.
   - При наличии сигналов — выполнение анализа и фиксация честного итога в памяти.

4. **REQ-04 (C4 — Opt-in расписание и триггеры без демона):**
   - Фоновое периодическое обучение по умолчанию выключено.
   - Активация явной конфигурацией проекта (`learn.schedule`, `learn.min_interval_hours`).
   - Архитектура без системных демонов (daemonless): триггер встроен в хук завершения сессии (`wolf session wrap-up`) и CLI-команду `wolf job trigger --if-scheduled`.

5. **REQ-05 (C5 — Доставка результатов и идемпотентность):**
   - Фиксация результатов работы Стюарда стандартными объектами памяти Wolf (`decision`, `lesson`-агрегаты со связями `aggregates`/`aggregated_in`, мутации версий лиц по контракту волны 2.17.0).
   - Изоляция контекста: новые лица и правила вступают в силу только для последующих задач, активные задачи не подменяются на лету.
   - Идемпотентность перезапуска: при сбое повторный запуск обрабатывает только оставшиеся необработанные сигналы.

## Нефункциональные требования (NFR)

- **NFR-01 (Латентность возврата):** Возврат промпта CLI при запуске в фоне < 200 ms (p95).
- **NFR-02 (Надежность логов):** Изоляция файловых дескрипторов stdout/stderr (`stdio: ['ignore', fd, fd]`), лог не прерывается при закрытии терминала инициатора.
- **NFR-03 (Dead PID detection):** Автоматическое распознавание краха процесса Стюарда без ручного удаления lock-файлов.
- **NFR-04 (Совместимость CLI):** Обратная совместимость с существующими командами `recap`, `call`, `brief`.
