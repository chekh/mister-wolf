# Релиз 3.1.1 — согласованность правил и пост-релизные фиксы

Патч 3.1.1 закрывает замечания ревью владельца от 2026-11-16 по поставке 3.0.0–3.1.0: несовпадающие формулировки прав коммитов исполнителя, следы трёхуровневой модели в правиле планирования, устаревшие входные документы проекта, и переносит пост-релизный фикс macOS-гонки хелпера в опубликованный пакет.

## Fixed

- **Гонка process-group в поставляемом хелпере `workflow-helper.py`.** После завершения верифицируемой команды `wait_group_empty` проверял пустоту группы через `os.killpg(pgid, 0)` и ловил только `ProcessLookupError`. На macOS, когда группа уже завершилась и её pgid переиспользован процессом другого владельца, вызов отвечает EPERM (`PermissionError`); исключение всплывало до `except OSError` в `main()`, helper выходил с кодом 2 и `{"error": "[Errno 1] Operation not permitted"}` — sporadic, зависит от таймингов (CI main 42742061297, PR #18). Теперь `PermissionError` трактуется как «наша группа завершилась». Воспроизведено прямым spawnSync-циклом: до фикса 3 падения за первые 5 итераций, после — 80 итераций на Node 22 и 40 на Node 24 чисто. `update-map.json` несёт хелпер как `changed` против 3.1.0. **Важно: опубликованный пакет 3.1.0 содержал хелпер без этого фикса — 3.1.1 и есть носитель фикса.**

## Changed

- **Права коммитов и публикации — одна формулировка во всём каноне.** Роутер запрещал коммиты безусловно (`using-skills/SKILL.md`), роль разработчика разрешала «per TASK/project rights» (`wolf-developer.md`), скилл исполнения запрещал на шаге результата (`wolf-execute/SKILL.md`), а канон wolf-git давал постоянное право чекпоинт-коммитов при назначении (§3 `git-collaboration-policy-v1.1.md`) — один вопрос, четыре ответа. Теперь везде правило владельца: исполнитель коммитит и публикует только при явном разрешении в TASK; иначе передаёт изменения и их состояние. Если TASK право дал — дальнейшие чекпоинты внутри этого TASK не требуют нового разрешения. Байты канона изменены: закреплённый sha256 `git-collaboration-policy-v1.1.md` теперь `794679a76e8385d7d8323564921d0eeb3c55fd5ca1bb916203fcf1ca270d0127` (прежний `de60c9b5…dde70` в записи 3.1.0 остаётся как факт релиза); имя файла сохранено, guard закреплённого SHA в тестах обновлён.
- **Планирование: план принадлежит ведущему.** `division-of-labor.md` говорил, что исполнитель-планировщик «organizes needed help» и хранит детальный план, а ведущий принимает план «adding no technical decomposition» — следы упразднённого промежуточного уровня. Теперь исполнитель-планировщик возвращает ограниченный результат планирования (предложения брифов, зависимости, параллелизм, бюджет, владелец интеграции) как предложения и никого не нанимает; ведущий владеет общим планом, распределением и интеграцией, может сам исправить понятный локальный пробел и возвращает автору существенные ошибки.

## Docs

- Корневой `AGENTS.md` проекта больше не открывается снятой лестницей L0/L1/L2 и обучением Стюарда: действующая база — двухуровневая модель; управляемое обучение набора названо отдельным планируемым направлением roadmap, не частью текущей модели.
- Активный roadmap (`roadmap-v4.md`) фиксирует выпущенные факты: 3.0.0 выпущен 2026-11-10 (тег `v3.0.0`, npm, сайт, хост переведён на набор 3.0.0), 3.1.0 выпущен 2026-11-15 (тег `v3.1.0`, npm, сайт, GitHub Release = Latest, слияние PR #18, CI зелёный); пост-релизные фиксы main поставляются этим патчем. В ledger внесена статусная правка без изменения очереди.

## Обновление

```bash
npm install -g mister-wolf@3.1.1
wolf upgrade          # или wolf upgrade --here для одного проекта
```

Отчёт upgrade покажет счётчики replaced/protected/kept/deferred и путь к бэкапам. Откат — ручная процедура из `.wolf/backup/` (путь печатается в отчёте). Повторный проход идемпотентен. Изменений поведения, кроме перечисленных, нет.

Формулировка прав коммитов добавляет роутеру ~16 оценённых токенов (chars/4, методика волны 3.1.0): baseline тройки в `token-baseline.json` этой папки — 687/1241/1445 против 712/1225/1453 у 3.1.0 (AGENTS.md и agent-language.md сократились/не менялись, роутер вырос из-за правила прав). Это ограничитель объёма, не измерение экономии — методика переименования метрики рассматривается отдельно (замечание 6 ревью).

Основание: ревью владельца 2026-11-16 (замечания 1–5); метрика токен-бенчмарка, возвращение Стюарда и пересмотр набора агентов — отдельные следующие пакеты.
