## E1 — программа экспериментов E1a–E1e (протокол зафиксирован ДО запуска)

Один эксперимент не может доказать четыре разные гипотезы: каждая ось требует своего набора задач и временной структуры. Поэтому E1 — программа **раздельных** экспериментов. Полный факториал (до 16 конфигураций) не проводится; порядок экспериментов **последовательный**.

**Цель программы (сохранена для всех осей):** количественное сравнение Wolf с одиночным агентом + ablation — доказать, что качество возникает из архитектуры, а не из большего числа вызовов моделей.

| Эксперимент | Ось               | Руки                                      | Класс задач                                                                    |
| ----------- | ----------------- | ----------------------------------------- | ------------------------------------------------------------------------------ |
| E1a         | Hierarchy         | single agent vs L0/L1/L2                  | сложные декомпозируемые поставки                                               |
| E1b         | Continuity        | без typed memory vs с typed memory        | последовательности связанных задач с повторяющимися классами и сбросами сессий |
| E1c         | Council           | без Council vs с Council                  | заранее определённые неоднозначные/высокорисковые развилки                     |
| E1d         | Governed Learning | без mutation vs complaint-driven mutation | повторяемые failure classes; holdout-варианты; измеряется перенос исправления  |
| E1e         | Capabilities      | одноразовые скрипты vs tool registry      | повторяющиеся проверки                                                         |

## Режимы сравнения

Равное число вызовов может искусственно лишить Wolf собственной архитектуры (иерархия и консилиум — сами потребители вызовов). Поэтому каждый эксперимент программы проводится в двух режимах:

- **Equal-budget** — одинаковые во всех руках: модели, стоимость, токены, wall-clock limit, число разрешённых model calls или общий compute budget. Отвечает на вопрос: эффективность при равных ресурсах.
- **Natural-operation** — каждая система работает в штатном режиме. Измеряется сочетание качество / стоимость / время / human effort; сравнение по **Pareto frontier**, а не по одному score.

## Статистический и оценочный протокол

Обязателен для каждого эксперимента программы:

**Дизайн**

- единица рандомизации — **последовательность проекта**, а не отдельная задача (задачи внутри одной истории не независимы);
- одинаковые модели и task sets; случайное распределение последовательностей по рукам;
- порядок задач рандомизируется; контроль carryover (фиксация случаев, где остаток предыдущей задачи мог повлиять на следующую);
- число повторов фиксируется до запуска из расчёта на доверительные интервалы.

**Измерение**

- primary endpoint фиксируется до запуска; secondary metrics — стоимость (токены/$), wall-clock, число model calls, human effort;
- severity ошибок — классификация фиксируется до запуска;
- критерии значимого ухудшения/улучшения фиксируются до запуска;
- confidence intervals на все ключевые метрики.

**Оценка**

- независимый evaluator, не участник разработки;
- blind review: оценщик не знает, из какой руки результат;
- учёт human intervention: каждое вмешательство фиксируется.

**Воспроизводимость**

- random seed прогонов;
- model/version pinning + полный provenance (модель, версия, конфиг, seed данных);
- правила обработки model variance (вариативность между запусками одной конфигурации);
- handling failed runs: заранее заданные правила, когда прогон считается failed, пересчитывается или исключается; каждое исключение фиксируется с причиной.

**Фиксация**

- критерии успеха и правила остановки зафиксированы ДО эксперимента;
- протокол фиксирован до запуска; изменения после старта — только отдельным решением владельца с указанием причины.

**Статус:** запланирован (Фаза E roadmap-v3); 30–100 задач на каждый эксперимент программы (не на программу целиком); точный размер и под-протокол каждого E1x фиксируются до его запуска.
