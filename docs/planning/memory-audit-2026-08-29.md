### «Пишется-но-не-читается» (по relations/events)

> **Калибровка 2026-08-30** (решение владельца по итогам этого аудита): тип
> `document-ref` исключён из метрики шума панели `wolf effectiveness` — и из
> числителя, и из знаменателя. Это функциональный «индекс документов»: их
> использование = регистрация/обновление сканом, а не связи/чтение. Повторные
> сканы теперь пишут событие `memory.scan.updated` (для любых типов оно
> считается подтверждением актуальности — объект не шум). Панель печатает
> document-ref'ы отдельной информативной строкой `documents:`. Рекомендация 1
> (stale-разметка при устаревании файла) остаётся в силе.

312 из 369 объектов (85%) не имеют ни одной связи и ни одного события кроме
`memory.added`. Оговорка: read-path сейчас не логируется вовсе, поэтому метрика
показывает «объекты, ни с чем не взаимодействовавшие», а не «не читавшиеся».
Тем не менее по назначению типа:

- **Тревожно — article (26 proposed, 0 accepted)**: очередь пост-аудита без
  дренажа; статьи копятся с 2026-08-26 и не проходят приёмку.
- **Тревожно — call-injection (5 active)**: механизм работает (инъекции видны
  в сессиях), но срабатывания не логируются → невозможно посчитать
  rule_utilization и decay по пробегу.
- **Норм по назначению — document-ref (122)**: справочный тип; но ни один не
  переведён в stale при устаревании файла.
- **Норм — session-summary (55)**: журнал; требует retention-политики, не
  «чтения».

## A8a. Рекомендации (НЕ исполнять без решения владельца)

1. **document-ref → ввести stale-разметку**: реестр 122 active при живых
   docs/archive/\*\* — предложения: (а) при скане помечать stale объекты, чей
   файл переехал в archive/; (б) не регистрировать archive/ вообще (фильтр
   artifact_sources). Ожидаемый эффект: −40–60% шума реестра.
2. **session-summary → retention**: оставлять «полный» wrap-up 1 на N
   сессий, промежуточные → archived (статус есть, не используется: 1 archived
   на 55). Либо перевести в режим «последний + счётчики».
3. **article → дренаж очереди proposed (26)**: пост-аудит-проход владельцем
   (accept/supersede), дальше — конвейер Ф22 с дайджестами, чтобы очередь не
   росла снова.
4. **Логировать чтение/доставку**: без delivery_event (Ф20) метрики
   «читаемости», decay по пробегу и rule_utilization не вычислимы — это
   блокер всего контура обработки знаний.
5. **open-question**: использовать статусы lifecycle по смыслу
   (answered/obsolete), «completed» — чужой для типа.
6. **growth-контроль**: 237 объектов за август при 369 всего — при сохранении
   темпа память удвоится за ~2 недели; контур Ф21–22 (кластеризация,
   консолидация) нужен до, не после.
