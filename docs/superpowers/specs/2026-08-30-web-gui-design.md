# Дизайн: Web GUI (wolf serve + SPA)

- **Дата:** 2026-08-30
- **Статус:** на ревью пользователем
- **Зависимости:** `2026-08-30-distribution-install-design.md` — реестр `projects.yaml`, `wolf doctor`, XDG-пути, миграционный guard, состав npm-пакета. GUI-спека ничего из этого не переопределяет, только потребляет.

## 1. Цель

Read-only веб-интерфейс над памятью Wolf: контроль состояния всех проектов, чтение памяти с markdown-рендером, preview инъекций. Три режима использования:

1. **Радар** — «что происходит в моих проектах и со здоровьем памяти»: светофоры, счётчики, активность.
2. **Библиотека** — «что в памяти и почему»: браузер, связи, история объектов, thinking-traces.
3. **Preview инъекций** — «что получит агент на `wolf call`»: состав и объём всухую.

Local-first до конца: localhost, без аккаунтов, сети и синхронизаций. **Одна копия данных** — GUI только читатель `.wolf/` и реестра, своих хранилищ не имеет.

## 2. Принятые решения (диалог 2026-08-30)

| Вопрос                          | Решение                                                                                                                                        |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Мультипроектность               | Через реестр дистрибуционной спеки (`~/.config/wolf/projects.yaml`); GUI не создаёт новых глобальных данных                                      |
| Тип приложения                  | SPA: Vite + React + TypeScript + Tailwind, над JSON API. SSR отклонён (риск упереться в ограничения на следующем шаге); desktop-оболочки — нет |
| Главный экран MVP               | Матрица проектов (светофоры + счётчики инбокса), от неё drill-down                                                                             |
| Markdown-рендер                 | `react-markdown` + `DOMPurify` (+ `remark-gfm`, подсветка `shiki`) — на клиенте, с обязательным санитайзом (тела пишут агенты = недоверенный текст) |
| Готовые платформы (HedgeDoc и пр.) | Отклонены: вторая копия данных, покрывают ~10% задачи (специфика Wolf — реестр, агрегаты, injections — не покрыта)                            |
| Режим MVP                       | Read-only; все мутации — v2                                                                                                                    |
| Обновление данных               | Poll (TanStack Query), websockets — нет                                                                                                        |
| Редактор памяти                 | Анти-скоуп: агенты пишут, человек читает и курирует (v2 — действия, не контент)                                                                |
| Оркестрация агентов из GUI      | Анти-скоуп: Wolf — не оркестратор                                                                                                              |
| Cloud / auth / team             | Вне видимости                                                                                                                                  |

## 3. Архитектура

### Сервер — `wolf serve`

- Новая команда CLI поверх существующего bootstrap-контейнера (тот же DI, те же use-cases: brief, effectiveness, search — ноль дублирования логики).
- Флаги: `--port` (дефолт `4141`), `--no-open`.
- Раздаёт статику фронтенда из `dist/web/` → глобальная установка получает GUI из коробки (`npm i -g mister-wolf` → `wolf serve` → браузер открылся).
- Точка входа — CLI, поэтому миграционный guard уровня 2 (дистрибуционная спека §3) покрывает `serve` автоматически.
- Только чтение: реестр и `.wolf/` проектов не мутируются.

### API — read-only JSON, `/api/v1/...`

| Эндпоинт                                    | Назначение                                                              |
| ------------------------------------------- | ----------------------------------------------------------------------- |
| `GET /api/v1/projects`                      | реестр + статус каждого (`ok \| unreachable \| invalid`)                 |
| `GET /api/v1/projects/:id/summary`          | светофор + счётчики инбокса (ядро матрицы)                              |
| `GET /api/v1/projects/:id/memory`           | список объектов: фильтры `type, status, lifetime, q`, пагинация         |
| `GET /api/v1/projects/:id/memory/:objectId` | карточка: метаданные + markdown-тело + связи + история (events)         |
| `GET /api/v1/projects/:id/timeline`         | лента `events.jsonl`: кто/что/когда                                     |
| `GET /api/v1/projects/:id/effectiveness`    | те же 5 блоков, что выводит CLI `wolf effectiveness`                    |
| `GET /api/v1/projects/:id/injections-preview` | прогон call-пайплайна всухую: состав (объекты, порядок), токены        |

### Фронт

- `web/` — отдельный package (npm workspaces от корня). Сборка `prepublishOnly` → `dist/web` (попадает под `files: ["dist"]` дистрибуционной спеки — состав пакета не меняется).
- TanStack Query: `staleTime` 30с, poll 60с.
- Роуты: `/` (матрица), `/p/:id` (обзор), `/p/:id/memory`, `/p/:id/m/:oid` (карточка), `/p/:id/timeline`, `/p/:id/injections`.

## 4. Экраны

1. **Матрица проектов** `/` — дефолт. Карточка проекта: имя, светофор (пороги effectiveness → OK/WARN/BAD), счётчики инбокса (blockers / open questions / info requests), последняя активность из `events.jsonl`, статус записи реестра. Битый путь = бейдж «недоступен», матрица не падает.
2. **Обзор проекта** `/p/:id` — светофор по блокам effectiveness, активные треды с возрастом (старение = цвет), топ инбокса, весовые токены за сегодня из `session-metrics.jsonl`.
3. **Память** `/p/:id/memory` — таблица с фильтрами (type / status / lifetime / importance) + поиск, пагинация.
4. **Карточка объекта** `/p/:id/m/:oid` — метаданные, рендер тела, связи из `relations.jsonl` (кликабельные → другие карточки), история из `events.jsonl`, thinking-trace при наличии.
5. **Timeline** `/p/:id/timeline` — лента событий, фильтры по типу события и автору.
6. **Injections preview** `/p/:id/injections` — «прогнать call всухую»: состав (объекты, порядок, токены).

## 5. Данные

- Источники — только существующие артефакты: реестр `projects.yaml`; в проекте — markdown-объекты `.wolf/memory/`, `events.jsonl`, `relations.jsonl`, `metrics/session-metrics.jsonl`, `run-log.jsonl`, агрегаты effectiveness.
- Пересчёт на запрос; на диске GUI ничего не кэширует.
- Статусы `ok | unreachable | invalid` определяет сам `serve` read-тестом корня `.wolf/` при формировании ответа. `wolf doctor` — офлайн-средство чистки реестра, в рантайме GUI не участвует.
- **Ключ записи реестра — стабильный `id`, не путь** (проект переехал → id сохраняется, doctor чинит путь). Уточнение к дистрибуционной спеке: `projects.yaml` должен содержать `id` + `path` (+ `registeredAt`); требует синхронной правки той спеки при реализации.

## 6. Обработка ошибок

- Недоступный проект — ошибка **в записи** проекта (`per-project error envelope`), не в ответе целиком: матрица живёт.
- Объект не найден → 404. Невалидные значения фильтров → пустой результат + подсказка, не 500.
- Большие тела отчётов: серверная обрезка + дозагрузка по клику; списки — limit 50.
- Реестр не читается — единственный фатальный случай: экран «Нет проектов» + подсказка `wolf init`.
- Схема проекта новее бинаря — обрабатывается миграционным guard CLI (дистрибуционная спека §3), до API не доходит.

## 7. Тестирование

- **API:** vitest на хендлерах инстанса сервера с tmp-фикстурами `.wolf/` — паттерн проекта уже отработан (bench dry на fixture-NDJSON).
- **Web:** smoke — `vite build` зелёный в `npm run check` + один render-тест матрицы.
- **E2E:** полный прогон после реализации плана (правило проекта): `wolf serve` → эндпоинты отвечают → статика раздаётся → матрица рендерится на fixture-реестре.

## 8. Стадийность

- **MVP (эта спека):** реестр (из дистрибуционной спеки) + `wolf serve` + 6 read-only экранов.
- **v2:** мутации — transitions (archive/supersede/resolve), ответы на questions/info-requests из GUI; лог фактических инъекций (мутация ядра: одна строка jsonl на каждый `call` — даёт аудит «что читал агент перед действием»); управление инъекциями.
- **v3:** граф связей на `mermaid` (`relations.jsonl` ложится напрямую), кросс-проектный поиск.

## 9. Анти-скоуп

- Редактор контента памяти (включая WYSIWYG) — навсегда: агенты пишут, человек читает.
- Оркестрация агентов из GUI — навсегда: Wolf не оркестратор.
- Cloud-синхронизация, аккаунты, team-доступ, RBAC — до явного отдельного спроса.
- Websockets/realtime-push — poll достаточен.

## 10. Риски

| Риск                                            | Митигация                                                                                            |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Недоверенный markdown от агентов (XSS)          | `DOMPurify` на каждом рендере, без исключений                                                        |
| Статика не попадает в npm-пакет                 | Сборка `web/` в `prepublishOnly` → `dist/web` (покрыто `files: ["dist"]`); e2e-шаг «serve раздаёт статику» |
| Интерактивность упрётся в read-only API         | API версионируется (`/api/v1`), v2-мутации — расширение, не переделка                                 |
| Большие тела/списки тормозят                    | Обрезка тел + пагинация limit 50 + ленивая дозагрузка                                                |
| Платформы                                       | Согласовано с дистрибуционной спекой: Windows/musl не заявлены v1; сервер — обычный Node, ограничений сверх того нет |
| Двойной источник правды о состоянии проектов    | GUI читает те же артефакты, что CLI (`effectiveness`, `events.jsonl`); собственной логики консистентности нет |
| `:id` в API требует поля `id` в реестре         | Синхронная правка дистрибуционной спеки (добавить `id` в записи `projects.yaml`) — до старта реализации    |

## 11. Scope

- **Трогаем:** `src/adapters/cli/` (команда `serve`), `src/app/` (read-only use-cases при нехватке существующих), `web/` (новый workspace), `package.json` (workspaces, scripts), `tests/`.
- **Не трогаем:** ядро памяти, MCP-слой, learn-механизмы, реестр и init (в дистрибуционной спеке).
