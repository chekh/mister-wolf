## 1. Проблема (из ревью)

1. Run'ы анонимны относительно эксперимента: нельзя сгруппять прогоны в кампанию «та же задача, с памятью и без» и сравнить когорты.
2. Нет per-memory ROI: какие объекты памяти ассоциированы с принятыми задачами, а какие только занимают контекст.
3. A/B-оценка «с памятью / без» пока ручная на глаз — нужна сплит-витрина с честными n/a на малых выборках.

## 3. Не делаем (границы P3)

WolfEval-раннер и сущности кампаний в памяти Wolf (внешний план `docs/plans/2026-09-04-wolfeval-v1.md` — не дублируем; P3 даёт только аналитическую витрину по campaign_id), p-values/доверительные интервалы, ROI в деньгах, memory_snapshot_id, span-модель (P4-ревизия), автоматический подбор когорт.

## 4. Критерии приёмки

1. `wolf run --campaign eval-01` пишет campaign_id в run-сигнал (roundtrip); без флага поля нет; `task-eval --campaign` прокидывает в task_evaluated (unit).
2. `--view campaign`: fixture-тест — кампания с двумя когортами (с injected / без) → n, медианы, accepted-доля; n<3 → n/a+reason; без verdict'ов → n/a.
3. ROI-секция `--view memory`: associatedAccepted/associatedApplied/injectedTotal по id, сортировка, дисклеймер correlational (fixture-тест).
4. Views в CLI и MCP (fixture-тест MCP-проводки).
5. Доки: analytics.md + сайт EN/RU (живые примеры), signal-log.md, Harness integration (сценарий кампании).
6. `npm run check` зелёный; чистый e2e — падений не больше известных 3 pre-existing (регрессия = 0 новых); merge в main; РЕЛИЗ НЕ ДЕЛАТЬ.
