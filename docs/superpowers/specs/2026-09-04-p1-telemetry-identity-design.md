## 1. Проблема (из ревью)

1. Сигнальные события не имеют идентичности: нет `event_id/run_id/trace_id/parent/role_level/attempt/hash` — невозможно восстановить цепочку «задача → L0 → L1 → L2 → приёмка» и посчитать стоимость задачи сквозняком.
2. Телеметрией покрыт только `wolf run`; MCP-вызовы (`search/get/list/…`) и штатные сессии невидимы → dashboard меряет случайную подмножество работы.
3. Два лога (`run-log.jsonl` + `session-metrics.jsonl`) пишутся последовательно без транзакции — риск расхождения; run-log дублирует run-сигналы.
4. Data-quality ограничен valid/malformed: нет duplicate/unknown-model/pricing-coverage счётчиков.

## 3. Не делаем (границы P1)

Span-модель start/finish с integrity-чеком (P2 — нужны парные события), `memory_snapshot_id` (дорого считать на каждый прогон; решим в P2 с автоснапшотами), `campaign_id` и WolfEval-сущности (P3), OpenCode-плагин как код (отдельный проект; P1 даёт MCP-границу + гайд), SQLite-проекция лога (когда объёмы потребуют; JSONL локально достаточен).

## 4. Критерии приёмки

1. `SignalEventSchema` v2: новые поля валидируются; запись v1 (без новых полей) проходит zod и читается аналитикой (unit-тест upcast).
2. `wolf run` после фикса: в run-сигнале присутствуют `event_id/run_id/trace_id/config_hash/prompt_hash/tools` (roundtrip-тест); `run-log.jsonl` больше не создаётся; `toolStats`/economy работают при отсутствии run-log (тест: аналитика на сигналах без run-log), старый run-log в истории читается (compat-тест).
3. MCP-вызов любой mr-wolf-\* тулзы пишет `mcp_call` с duration_ms/outcome (тест обёртки; интеграционно — живой прогон + счётчик в логе).
4. `dataQuality` содержит `duplicateEventRatePct` (тест на дубле event_id), `unknownModelRatePct`, `pricingCoveragePct`, `completeTraceRatePct: null` с reason.
5. Доки: signal-log.md схема v2; Harness integration в мануале + сайт EN/RU; примеры живые.
6. `npm run check` зелёный; существующие тесты обновлены под сигнальный источник экономики.
7. Merge в main; РЕЛИЗ НЕ ДЕЛАТЬ (v2.6.0 — отдельно).
