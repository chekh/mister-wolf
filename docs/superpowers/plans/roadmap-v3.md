## Фаза D · Контур самообучения Ф20–26 (~5–8 сессий)

Зачем фазы: без обработки накопленная память превращается в шум (П4 концепта §1); контур превращает сигналы сессий в обновляемые правила, промпты и роутинг — основа УТП-1 (концепт §8, Pillar 2).

Промышленная версия обработки знаний (концепт §5). Порядок фиксирован спекой самообучения (`docs/superpowers/specs/2026-08-26-self-learning-design.md`):
Ф20 сигнальный лог (журнал метрик и событий сессий) → Ф21 паттерны (кластеризация по ключу) → Ф22 Стюард полный (пост-аудит, Analyzer-Worker, Sandbox Replay, complain) → Ф23 STOP-гейт (самооптимизация промптов по метрике) + read-only зоны → Ф24 GEPA (эволюция промптов по метрике) → Ф25 AFlow (поиск оптимального workflow из блоков) → Ф26 decay по пробегу.

**+ Новое (решение владельца 2026-08-29): Архивариус калибрует роутер** — агрегат «модель × тип задачи × вердикт × weighted-цена» по сигнальному логу → правки routing-объектов через конвейер активации. Роутер самонастраивается на фактах проекта.

**+ Новое (v3.1, 2026-08-31):**

- **D+ · Метрика эффекта мутаций** — связь мутаций playbook'ов с `wolf effectiveness`: доставка сработала? поведение изменилось? жалоб/повторов меньше? Замыкает петлю «изменение → измерение → сохранить/откатить».
- **D+ · Temporal-валидность** — поля `valid_from` / `valid_until` / `observed_at` для architecture / dependencies / constraints / procedures (не копируя Graphiti — внешнюю графовую память с временной валидностью).
- **D+ · Динамическая evidence-валидация** — `last_verified_at` + invalidation triggers (референс: Copilot revalidation).
- **Стоп-правило таксономии**: новые типы памяти — только как schema extensions существующих структур, не новые state machine (бюджет таксономии ~24 типа исчерпан).

Чекпоинты: E2E после каждой фазы; стадии автономии B→B+→C (B — пре-аппрув каждой записи человеком; B+ — пост-аудит дайджестом, стартовый режим; C — расширенная автономия по метрикам доверия); повышение и возврат стадии — решением пользователя на чекпоинтах пробега (окна 30/60/90 сессий — дефолты внешнего аналитика [ВА], калибруются); возврат B+→B при ≥30% отмен.

## Фаза E · Экосистема и измерение эффекта

Зачем фазы: измерить накопительный эффект Wolf внешне проверяемыми числами (benchmark + ablation) — опора позиционирования (B6) и moat (B8).

### E1 · Benchmark накопительной эффективности — явная фаза (не по триггеру)

Vanilla agent vs agent+Wolf на 30–100 повторяющихся задачах. Метрики: **project discovery tokens · repeated mistake rate · duplicated diagnostic scripts · time to resume task · stale knowledge injection rate · council impact on ambiguous decisions**.

**Ablation-тесты** (вкл/выкл): иерархия (один агент vs L0→L1→L2) · память (без/с таксономией) · консилиум (без/с) · Стюард (без/с).

### По триггерам

- Ariadne (вынесение адаптера) — при срабатывании критериев: использование вне Wolf · второй платформенный клиент · npm-публикация · протечка в `src/`
- Нити (линии развития платформенных адаптеров) других платформ / второй платформенный адаптер (кандидат — OpenHands) — после зрелости Уровней 1–2 (фаз B–C)
- v1.1+: A-MEM (динамическая агентская память из внешних исследований — по триггеру деградации recall), cross-project (переиспользование знаний между проектами), GEPA template evolve

### Границы

**Durable execution runtime не делаем** — leases / heartbeats / recovery (аренда задач, пульс, восстановление после сбоев) вне scope по концепту §9 и внешней экспертизе 2026-08-31 (диалог, §20.6); при потребности — сторонний runtime под протоколом (B8).
