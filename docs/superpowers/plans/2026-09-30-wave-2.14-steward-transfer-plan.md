### P300 Guard коллизии id + событие перезаписи (S, P0 жалобы) — спека §5.1, §5.2, §11.1

Требование: коллизия детерминированного id при add — отказ с подсказкой (edit/supersede/--title), никогда тихая перезапись; любое перезаписывающее save пишет event-след до записи. Первая задача волны, независима.

Шаги: (а) guard в `addMemoryObject` (`src/app/use-cases/add-memory-object.ts:76-148`): внутри `run()` (уже исполняется под lock, `:148`), после typeCheck/validateMemoryObject и **до** `deps.store.save(object)` (`:128`) — `const existing = await deps.store.get(object.id); if (existing) throw new UserFacingError(...)` с текстом дословно по спеке §5.1 (формат подсказки — прецедент `getDeclaration`):

```
Memory object "<id>" already exists (same title produced same id).
Use: wolf edit <id> (правка) | wolf supersede <id> <new-id> (смена) | другой --title.
```

`store.get` — существующий метод порта (использует `get-memory-object.ts`); один locate-обход, add — не hot-path (Р5 спеки); (б) событие на перезапись в хранилище: `MarkdownMemoryStore` получает опциональную зависимость `overwriteLog?: Pick<EventLog, 'append'>` (конструктор); в `save` (`src/adapters/fs/markdown-memory-store.ts:107-113`) перед `writeFileAtomic`: если целевой файл существует — прочитать существующий объект (парсер store) и **до записи** append событие `{ type: 'memory.overwritten', payload: { memory_id, prev_title: <обрезка 120>, prev_status } }` (формат события — прецедент `memory.edited` в `memory-edit.ts:50-58`; actor — `system`); новый объект — событие не пишется; (в) тип `memory.overwritten` в enum `MemoryEventSchema` (`src/domain/schemas/memory-event-schema.ts:5-14`, аддитивно — инвариант (i) спеки §9); (г) связывание в `createCliContainer` (`src/bootstrap/container.ts:25-39`) одной строкой: `log` создаётся раньше `store`, конструктор store получает `{ overwriteLog: log }`.
