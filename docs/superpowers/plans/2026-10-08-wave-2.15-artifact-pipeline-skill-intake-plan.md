# Волна 2.15 «Конвейер артефактов + skill intake» — план реализации

> **Исполнителям:** REQUIRED-СКИЛЛ: используй wolf-sdd (рекомендуется) ИЛИ wolf-execute
> для поэтапной реализации этого плана. Шаги оформлены чекбоксами (`- [ ]`) для трекинга.

**Цель:** разложить конвейер документов на маленькие связанные артефакты в `docs/dev/` с детерминированным тулингом (`scaffold artifact` / sync-индексы / doctor-линт), переписать скиллы конвейера под парные артефакты и добавить подключение внешних скиллов через гейт владельца.

**Архитектура:** три слоя — тулинг (расширение существующих поверхностей `scaffold`/`sync`/`doctor`; ноль новых CLI-команд), скиллы (файлы `templates/base/skills/<имя>/SKILL.md`, рендерятся в базовый набор и в `.opencode/skills/`), догфуд (эта волна мигрирует `docs/dev/` на новую структуру сама). Скиллы создают/читают артефакты через команды Wolf, не вручную; уникальность и консистентность гарантирует машина, линзы ловят смысл, скрипты — механику.

**Стек:** TypeScript, Node 22, vitest, commander; скиллы — markdown в `templates/base/skills/`; точечные прогоны `npx vitest run <путь>`, полный гейт `npm run check`.

Дата: 2026-10-08. Спека: `docs/superpowers/specs/2026-10-07-artifact-pipeline-skill-intake-design.md` (DESIGN APPROVED; базлайн-коммит спеки `211ac84` = текущий main на момент планирования — совпадают). Прецедент структуры: план волны 2.14 (`2026-09-30-wave-2.14-steward-transfer-plan.md`) — потоки с дизъюнктными файлами, порядок влитий, DoD, разделы доков и чек-листа. function memFs(initial: Record<string, string> = {}) {
```typescript
  const files = new Map<string, string>(Object.entries(initial));
  return {
    files,

      exists: async (p: string) => files.has(p),
      writeFile: async (p: string, c: string) => {
        files.set(p, c);

    },
  };
```

```typescript
const SLUG_RE = /^[a-z0-9][a-z0-9-]*$/;

function frontMatter(slug: string, title: string, created: string): string {
  return ['---', `slug: ${slug}`, `title: ${title}`, 'status: draft', `created: ${created}`, '---', ''].join('\n');
}

export async function scaffoldArtifact(
  deps: ScaffoldArtifactDeps,
  input: ScaffoldArtifactInput
): Promise<ScaffoldArtifactResult> {
  if (!SLUG_RE.test(input.slug)) {
    throw new UserFacingError(`Invalid slug "${input.slug}" (expected ^[a-z0-9][a-z0-9-]*$)`);
  }
  const now = deps.clock.now();
  const created = now.toISOString().slice(0, 10);
  const dir = join(deps.baseDir, 'docs', 'dev', `${created}-${input.slug}`);
```

```typescript
 * seed-base-playbooks.ts:38-47; риск спеки §9 «линт хрупок к формату»:
 * нечитаемый файл → пустая карта, не исключение). */
export function parseArtifactFrontMatter(raw: string): Record<string, string> {
  const m = raw.match(/^---\r?\n([\s\S]*?)\r?\n---\r?\n?([\s\S]*)$/);
  if (!m) return {};
  const meta: Record<string, string> = {};
  for (const line of m[1].split('\n')) {
    const kv = line.match(/^([\w-]+):\s*(.+)$/);
    if (kv) meta[kv[1]] = kv[2].trim();
  }
  return meta;
}
```

```typescript
import { join } from 'path';
import { parseArtifactFrontMatter } from './artifact-front-matter.js';

export interface ArtifactIndexFs {
  exists: (p: string) => Promise<boolean>;
  readFile: (p: string) => Promise<string | null>;
  writeFile: (p: string, c: string) => Promise<void>;
  /** Имена записей каталога (файлы и папки, без «.»-записей). */
  listDir: (p: string) => Promise<string[]>;
  /** .md-файлы каталога рекурсивно, относительные пути. */
  listFiles: (p: string) => Promise<string[]>;
}

export interface SyncArtifactIndexDeps {
  fs: ArtifactIndexFs;
  baseDir: string;
}

export type SyncArtifactIndexAction = 'written' | 'unchanged' | 'skipped';

const INDEX_HEADER =
  '<!-- wolf:generated docs/dev/INDEX.md — regenerates on wolf sync; hand edits are overwritten -->\n\n' +
  '# Артефакты — docs/dev\n\n';

/** Спека §4-A2: таблица слаг/дата/title/status/профиль; §4-A4: _index.md частей.
 * Идемпотентность — по прецеденту штампов: identical → не пишем. */
export async function syncArtifactIndex(deps: SyncArtifactIndexDeps): Promise<{ action: SyncArtifactIndexAction }> {
  const devDir = join(deps.baseDir, 'docs', 'dev');
  if (!(await deps.fs.exists(devDir))) return { action: 'skipped' };

  const writes = new Map<string, string>();
  const rows: string[] = [];
  const waves: string[] = [];
  const folders: string[] = [];

  for (const name of (await deps.fs.listDir(devDir)).sort()) {
    if (name === 'INDEX.md') continue; // сам индекс не индексируем — иначе повторный sync не идемпотентен
    const p = join(devDir, name);
    if (name.endsWith('.md')) {
      const raw = await deps.fs.readFile(p);
      if (raw) {
        const meta = parseArtifactFrontMatter(raw);
        waves.push(`- ${name} — ${meta.title ?? name} (${meta.status ?? 'draft'})`);
      }
      continue;
    }
    const reqRaw = await deps.fs.readFile(join(p, 'requirements.md'));
    if (!reqRaw) continue;
    const meta = parseArtifactFrontMatter(reqRaw);
    if (!meta.slug) continue;
    const files = await deps.fs.listFiles(p);
    const profile = files.includes('design.md') && files.includes('test-plan.md') ? 'full' : 'fix';
    folders.push(name);
    rows.push(
      `| ${meta.slug} | ${meta.created ?? ''} | ${meta.title ?? meta.slug} | ${meta.status ?? 'draft'} | ${profile} |`
    );
  }

  let out = INDEX_HEADER;
  out += '| Слаг | Дата | Title | Статус | Профиль |\n| ---- | ---- | ----- | ------ | ------- |\n';
  out += rows.length > 0 ? rows.join('\n') + '\n' : '(пока нет папок фич)\n';
  if (waves.length > 0) out += '\n## Волны\n\n' + waves.join('\n') + '\n';

  // Части (спека §4-A4): подпапки design/ и plan/ с файлами-частями получают _index.md.
  for (const folder of folders) {
    for (const sub of ['design', 'plan']) {
      const subDir = join(devDir, folder, sub);
      if (!(await deps.fs.exists(subDir))) continue;
      const parts = (await deps.fs.listFiles(subDir)).filter((f) => f.endsWith('.md') && f !== '_index.md').sort();
      if (parts.length === 0) continue;
      writes.set(
        join(subDir, '_index.md'),
        ['<!-- wolf:generated parts index -->', '', `# ${sub} — части`, '', ...parts.map((f) => `- ${f}`), ''].join(
          '\n'
        )
      );
    }
  }

  const indexPath = join(devDir, 'INDEX.md');
  const existingIndex = await deps.fs.readFile(indexPath);
  const allIdentical =
    existingIndex === out &&
    (await Promise.all([...writes].map(async ([p, c]) => (await deps.fs.readFile(p)) === c))).every(Boolean);
  if (allIdentical) return { action: 'unchanged' };

  await deps.fs.writeFile(indexPath, out);
  for (const [p, c] of writes) {
    if ((await deps.fs.readFile(p)) !== c) await deps.fs.writeFile(p, c);
  }
  return { action: 'written' };
}
```

2. **Дубли ID**: в `requirements.md` папки найти все `^### (REQ|NFR)-(\d{2})`; повтор id → `<id> дублируется в <folder>/requirements.md`.
3. **Битые ссылки**: во всех `design.md`/`plan.md`/`test-plan.md` папки найти `REQ-\d{2}`; id, отсутствующий в requirements.md → `<id> не найден в requirements.md (упомянут в <file>)`.

8. **Дубли требований**: в requirements.md папки собрать строки `^- Требование:`; нормализация = trim + lowercase + схлопывание пробелов; совпадение двух → `дубликат требования: "<нормализованный фрагмент до 60>" (<REQ-id1> ↔ <REQ-id2>)`.

```markdown
# receiving-code-review: приём фидбека

## Обзор

Фидбек владельца = высший приоритет лестницы приоритетов. Но «внедри совет» — не
поведение по умолчанию: ревью может быть технически неверным.

## Процесс

1. Прочитать фидбек целиком; классифицировать каждый пункт: факт-исправление /
   вопрос / возражение.
2. Согласен → внедрить + коммит + строка «что исправлено» в отчёт.
3. Сомневаешься → проверить по коду/документу ДО ответа; возражение обосновать
   пруфом (file:line), не мнением.
4. Фидбек противоречит памяти Wolf/рамке → по лестнице приоритетов (память выше
   скиллов); расхождение правил → жалоба по протоколу жалоб, не самовольная
   правка правила.
5. Уроки фидбека (воспроизводимый паттерн ошибки) → `wolf add --type lesson`.

## Запреты

- Перформативное согласие без проверки.
- Внедрение совета вслепую при явном техническом возражении.
- Тихое игнорирование пункта фидбека.

## Трассировка адаптации

| Пункт источника (superpowers receiving-code-review) | Судьба                                           | Почему            |
| --------------------------------------------------- | ------------------------------------------------ | ----------------- |
| Техническая строгость, не перформативное согласие   | сохранено                                        | ядро              |
| Проверка перед внедрением                           | сохранено                                        | ядро              |
| «Совет может быть неверным»                         | сохранено                                        | ядро              |
| —                                                   | добавлено: лестница приоритетов + протокол жалоб | Wolf-переплетение |
| —                                                   | добавлено: уроки фидбека → память Wolf           | самообучение      |
```

```markdown
# writing-skills: создание и правка скиллов Wolf

## Обзор

Скилл Wolf = промпт-методология в `templates/base/skills/<имя>/SKILL.md`; в
проекты-пользователи попадает рендером (штампы, `wolf init`/`wolf sync`).
Правка живого скилла ведётся в шаблоне, не в отрендеренной копии.

## Жизненный цикл

1. Новый скилл: папка `templates/base/skills/<имя>/SKILL.md` с front-matter
   `name` + `description` (описание — триггер загрузки: когда применять).
2. Тело: обзор → вход/выход → процесс (шаги) → железные запреты.
3. **Таблица трассировки адаптации обязательна** для каждого адаптированного
   скилла: источник → судьба пункта (сохранено/заменено/выброшено/добавлено) → почему.
4. Правка существующего: шаблон → `wolf sync` → guard-тесты соответствующего набора.
5. Граница с intake: скиллы базового набора — здесь; внешние скиллы мира —
   через wolf-skill-intake (гейт владельца), не через этот скилл.

## Запреты

- Править `.opencode/skills/<имя>/SKILL.md` напрямую (перезатрётся sync).
- Создавать скилл без таблицы трассировки (для адаптаций) или без описания
  триггера (для новых).
- Дублировать существующий скилл набора — сначала `wolf search`.
```

````markdown
# wolf-skill-intake: подключение внешнего скилла

## Обзор

Чужой скилл меняет поведение агентов — это мутация лица. Процесс: поиск →
ревью → гейт владельца → установка → регистрация → наблюдаемость. Единственный
новый скилл блока intake; линза кандидата — роль в этом протоколе, не отдельный скилл.

## 1. Поиск

- CLI: `npx skills find <запрос>`; leaderboard: skills.sh.
- Критерии качества: ≥1K установок, репутация источника, звёзды репозитория.
- Изоляция: внешние вызовы только здесь; при поломке внешнего CLI — деградация
  к ручному поиску; контур (линза, гейт, регистрация) не страдает.

## 2. Ревью-линза кандидата

Чистый воркер-ревьюер читает SKILL.md кандидата по ОДНОМУ вопросу:
«опасен ли/конфликтует ли этот скилл?» Проверки:

- опасные инструкции: `rm -rf`, `curl | sh`, запросы секретов, авто-коммиты;
- конфликты с рамкой/правилами проекта — по памяти Wolf (`wolf search`);
- качество промпта: расплывчатые/конфликтные предписания.

Вердикт (подключаем/отклонить + находки) — владельцу. Отклонение = конец, установки нет.

## 3. Гейт владельца

Без явного «да» владельца установка не идёт. Вопрос формулируется: скилл, источник,
находки линзы, вердикт. Только после явного аппрува — шаг 4.

## 4. Установка

`npx skills add <имя>` (в проекте-пользователе). Откат: `npx skills remove <имя>`.

## 5. Регистрация

Тул-объект в памяти Wolf (гасит линт скиллов-призраков doctor):

```bash
wolf add --type tool --title "skill: <имя>" \
  --set name=<имя> \
  --set script_path=.opencode/skills/<имя>/SKILL.md \
  --set language=markdown \
  --set owner_skill=<имя> \
  --set version=<версия-источника> \
  --set source_url=<URL репозитория/страницы>
```

Ребро на проект/поток — по необходимости (`wolf relation add`).

## 6. Наблюдаемость (уже существует — проверяется, не строится)

- телеметрия: `.wolf/metrics/skill-invocations.jsonl` (панель `analytics --view delivery`);
- жалобы на скилл: `wolf complain --about skill:<имя>` → kind behavioral;
- линт призраков: секция «Артефакты» в `wolf doctor`.

## 7. Откат

`npx skills remove <имя>` + `wolf supersede <tool-id> <new-id>` или
`wolf transition <tool-id> archived` (существующими командами, без новых).
````
