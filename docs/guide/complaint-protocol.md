# Протокол обработки жалоб (complaint protocol)

**Версия:** Phase B3 (roadmap v3) — `wolf complain` + Наставник (Стюард)  
**Статус:** продукт-минимум, без LLM в самой команде

---

## 1. Что такое жалоба

Жалоба — hot-signal от владельца или агента на поведение агента/методики.
Это наблюдение о факте («что случилось»), а не извлечённый урок — поэтому
жалоба хранится как объект типа `observation` (не `lesson`): урок с
`trigger_keywords` — продукт расследования, жалоба — вход в него.

## 2. Подать жалобу

```bash
node dist/bootstrap/cli.js complain \
  --about skill:apprentice \
  --text "агент пропускает шаги плана и не проверяет результат"
```

- `--about` — адресат: id playbook-объекта, agent-id или имя скилла
  (строки вида `skill:apprentice` допустимы).
- Создаётся `observation` с полями `about`, `complaint`, `trigger: true`
  (сигнал Стюарду), тег `complaint` и relation `complain` к адресату
  (обратная — `complained_by`).

## 3. Конвейер обработки

```text
жалоба (wolf complain)
  → обнаружение: координатор/воркер видит объект с trigger=true
    (wolf search complaint / wolf call в начале сессии)
  → вызов Наставника: рамка .opencode/agents/steward.md,
    запуск как opencode-агент в режиме grow
  → Стюард расследует: читает playbook-адресата, журнал, контекст жалобы
  → Стюард создаёт НОВУЮ версию playbook (полное содержимое, не дифф):
      wolf add --type playbook --title "<skill> playbook vN+1: …" \
        --set owner_skill=skill:apprentice --set version=vN+1 \
        --set steps="[шаг 1,шаг 2,шаг 3]"
  → сапсейд старой версии: wolf supersede <old-playbook-id> <new-playbook-id>
  → вердикт записывается в жалобу (итог — в body жалобы,
    либо отдельным объектом с relation)
  → жалоба закрывается: wolf transition <complaint-id> resolved
```

## 4. Обязанности сторон

- **Владелец/воркер** — подаёт жалобу с конкретикой: что сделал агент,
  чего ожидалось. Не мутирует playbook сам.
- **Координатор** — при обнаружении `trigger: true` передаёт жалобу
  Наставнику; не разбирает её сам.
- **Стюард (Наставник)** — единственный, кто мутирует контекст агента:
  новая версия playbook → supersede → вердикт → закрытие жалобы.
  Без жалобы/фидбека не меняет ничего.

## 5. Инварианты

1. Воркер сам себя не мутирует — мутация только через Стюарда.
2. Playbook версифицируется: замена только через `supersede`, полное
   содержимое новой версии + причина в конце.
3. Жалоба без вердикта не закрывается; вердикт доступен пост-аудиту.
