# Экономика переиспользования инструментов

## Зачем

Удачное рассуждение-скрипт кристаллизуется в постоянный инструмент: вызов инструмента =
переиспользование уже проделанного мышления. Экономика подтверждена снаружи (Voyager 15.3×)
и внутри проекта (один checker переиспользован ×6) — см. `docs/concept/concept.md` §6.
Эта методика превращает «кажется, экономит» в измеримое число по собственному run-log.

## Как помечать запуск

```bash
wolf run --agent worker --title "правка конфигов" --tool my-tool "..."
```

- `--tool <name>` — repeatable: несколько флагов = несколько инструментов.
- Пометка попадает в `.wolf/run-log.jsonl` в поле `tools` (записывается только если флаг задан;
  старые строки без `tools` остаются валидными).

## Методика

- Стоимость задачи — `weighted` из run-log:
  `weighted = input + 0.1 × cache.read + 5 × output`
  (кэш-чтение почти бесплатен, генерация — в 5 раз дороже входа).
- Сравниваем **weighted-медиану** задач с пометкой `tools` против **медианы всех задач**.
- Минимальная выборка — 3 задачи на группу; при нехватке отчёт честно говорит
  «недостаточно данных», числа не выдумываются.
- Если медиана всех задач ≤ 0 — процент экономии не выводится (медианы печатаются).

Формула: `savingsPct = (1 − medianTool / medianAll) × 100`.

## Честность интерпретации

**Корреляция ≠ причинность.** Задачи, решённые с инструментами, могут быть проще сами по
себе (инструмент пишут под частую рутину). Метрика — индикатор здоровья библиотеки
инструментов, а не доказательство причинности. Не стройте на одном числе выводов об
архитектуре; смотрите на него в динамике и вместе со счётчиками `usage_count`.

## Правило search-before-write

Перед написанием нового скрипта — сначала `wolf tool list` и `wolf search`: возможно,
инструмент уже есть. Повторное использование регистрируйте `wolf tool use <name>` —
это обновляет `usage_count`/`last_used_at` и делает экономику измеримой.

Правило закреплено объектом `rule` в памяти проекта и всплывает injection'ом
при работе с кодом.

## Сводка по данным

- Источник: `.wolf/run-log.jsonl` (append-only журнал `wolf run`).
- Расчёт: `src/domain/tool-economy.ts` (чистые функции), use-case `toolStats`.
- Пример вывода: `tool-задач: 12, всего: 40, медианы 8.4k vs 25.1k → экономия ≈67%`.
