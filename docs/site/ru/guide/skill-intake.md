# Skill intake (подключение скиллов)

Внешние каталоги скиллов — недоверенный код для ваших агентов: инструкции, которые будут направлять каждую будущую сессию с момента установки. Skill intake — протокол, позволяющий всё же подключить такой скилл — осознанно, с проверкой качества и явными воротами владельца. Найденные так скиллы **не** входят в базовый набор ([Артефактный конвейер — оси скиллов](/ru/guide/artifact-pipeline)); в проект они попадают только через этот цикл.

## Цикл подключения

### 1. Поиск

Ищите кандидатов через `npx skills find` или каталог [skills.sh](https://skills.sh). Планка качества: минимум 1K установок и репутация, которой можно доверять.

### 2. Линз-ревью кандидата

Линз-ревью скилла проверяет три вещи:

- опасные инструкции — всё, что эксфильтрирует данные, разрушает или вводит в заблуждение;
- конфликты с правилами и памятью проекта;
- качество промпта — действительно ли скилл хорош в том, что заявляет.

Вердикт уходит владельцу.

### 3. Ворота владельца

Нет явного «да» от владельца — нет установки. Это жёсткие ворота всего цикла: вердикт линзы рекомендует, решает только владелец.

### 4. Установка

```bash
npx skills add <name>
```

### 5. Регистрация в памяти

Незарегистрированный скилл — призрак: есть в наборе, невидим для Wolf. Регистрация делает его памятью — запрашиваемым, наблюдаемым и изменяемым:

```bash
wolf add --type tool --title "skill: <name>" \
  --set name=<name> \
  --set script_path=<path/to/SKILL.md> \
  --set language=markdown \
  --set owner_skill=<name> \
  --set version=<version> \
  --set source_url=<url>
```

### 6. Наблюдение

Каждый вызов скилла пишется в `.wolf/metrics/skill-invocations.jsonl`, поэтому использование измеримо (см. [Аналитика — панель доставки](/ru/guide/cli/analytics#панель-доставки)). Жалобы на скилл идут через жалобный контур с `about: skill:<name>` ([Контур обучения](/ru/guide/feedback)), а `wolf doctor` линтит призрачные скиллы — в наборе, но не в памяти.

### 7. Откат

Скилл, который ведёт себя плохо, удаляется и разрегистрируется:

```bash
npx skills remove <name>
```

плюс `wolf supersede` или архивация его записи в памяти, чтобы история оставалась доступной ([Модель памяти](/ru/guide/memory)).

## Пример: `commit-messages`

1. **Поиск:** `npx skills find commit-messages` — кандидат с 4.2K установок на skills.sh.
2. **Линза:** опасных инструкций нет, конфликтов с правилами проекта нет, промпт сфокусирован и конкретен → вердикт «безопасно, стоит того» уходит владельцу.
3. **Ворота владельца:** владелец говорит «да».
4. **Установка:** `npx skills add commit-messages`.
5. **Регистрация:**

```bash
wolf add --type tool --title "skill: commit-messages" \
  --set name=commit-messages \
  --set script_path=.opencode/skills/commit-messages/SKILL.md \
  --set language=markdown \
  --set owner_skill=commit-messages \
  --set version=1.0.2 \
  --set source_url=https://skills.sh/someone/commit-messages
```

6. **Наблюдение:** вызовы попадают в `.wolf/metrics/skill-invocations.jsonl`; предложение, ломающее конвенцию → `wolf complain` с `about: skill:commit-messages`.
7. **Откат** (если нужен): `npx skills remove commit-messages`, затем supersede записи в памяти.
