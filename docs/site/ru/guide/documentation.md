# Поддержание документации

Сайт — единое актуальное руководство пользователя. Исходники находятся в `docs/site/`; `docs/README.md` указывает сюда и перечисляет инженерные документы. README знакомит с продуктом и ссылается на сайт. Требования, дизайн, исследования и роадмап остаются в Git как память проекта.

## Ответственность и момент обновления

Владелец изменения обновляет затронутую документацию в той же задаче. Принимающий проверяет покрытие и примеры. Подготовка релиза включает обзор опорных страниц, даже если новых команд нет. Пересматривайте объяснение при изменении назначения, ответственности, подключения, обратной связи или пользовательского контроля.

Начало должно объяснять: что делает Wolf, как удерживает цель, как процесс связывает скиллы/инструменты/правила/память, как Стюард меняет методы и как человек работает с организацией. Первый результат не требует изучения таксономии или внутренних протоколов отчёта. Измеренные эффекты полезны по месту; бенчмарки не являются условием знакомства.

## Карта проверки

| Изменение                     | Что проверить                                                        |
| ----------------------------- | -------------------------------------------------------------------- |
| Назначение и позиционирование | README EN/RU, обзор, возможности, главную и описание пакета          |
| Роли и методики               | Организацию, базовый набор, работу с Wolf, затронутые рамки и скиллы |
| Память и документы            | Память, bootstrap, конфигурацию и разделы CLI                        |
| Обучение и мутация            | Обратную связь, доставку, примеры контроля и текущие ограничения     |
| Подключение и обновление      | Начало работы, bootstrap, upgrade, неполадки и установку на главной  |
| CLI и MCP                     | Тематическую страницу, генератор справочника, каталог MCP и примеры  |

Сверяйте описание с действующими исходниками и подходящими проверками. Запись CHANGELOG сама по себе не доказывает поведение. Иллюстративный диалог обозначайте примером, не фактическим прогоном. Не обещайте чистый контекст, автоматическое восстановление процесса или положительное обучение без обеспечивающего механизма.

## Проверка

```bash
npm run docs:check
```

Команда собирает CLI, генерирует справочник и зеркала CHANGELOG, собирает сайт, проверяет локальные ссылки/якоря и парность страниц EN/RU. Она не удостоверяет точность объяснения или доступность внешнего сервиса. Также выполняйте проектные проверки и относящиеся примеры; при визуальных изменениях смотрите desktop/mobile и обе локали.

Предпросмотр: `npm run docs:preview`. Базовый путь публикации — `/mister-wolf/`. Меняйте исходники, а не `.vitepress/dist/`. Результаты проверки сохраняйте в существующий тест-план задачи.

CI проверяет сайт до интеграции PR. Публикация остаётся существующим workflow после разрешённого включения в `main`; локальная сборка не означает публикацию.
