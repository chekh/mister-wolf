# Понимать работу своей организации

Аналитика помогает изучать фактическую работу: что доставлялось агентам, какие результаты приняты, какие инструменты переиспользуются и что изменил Стюард. Она поддерживает решения по проекту; для использования Wolf не требуется проводить программу бенчмарков.

Начните с вопроса, а не со всех доступных метрик:

| Вопрос                                        | Команда                                   |
| --------------------------------------------- | ----------------------------------------- |
| Что происходит в проекте?                     | `wolf analytics --view dashboard`         |
| Что изменил Стюард?                           | `wolf analytics --view steward`           |
| Память найдена, доставлена или применена?     | `wolf analytics --view memory`            |
| Какие скиллы и лица доставлялись?             | `wolf analytics --view delivery`          |
| Где происходили передачи и блокировки?        | `wolf analytics --view coordination`      |
| Соответствуют ли ожиданиям вызовы и доставка? | `wolf analytics --view acceptance --json` |
| Какие инструменты используются повторно?      | `wolf tool stats`                         |

Команды детерминированно агрегируют локальные логи и память. Они не просят LLM придумать оценку. Недостаток данных обозначается `n/a` с причиной там, где этого требует метрика. Консольный дашборд не является веб-интерфейсом.

## Смотрите на результат, а не только на активность

Завершённый прогон отличается от принятой задачи. Фиксируйте вердикт относительно реальных критериев приёмки, с настоящими идентификаторами задачи и сессии, когда они доступны:

```bash
wolf task-eval --verdict accepted --task-id docs-navigation \
  --session docs-session --scorer human \
  --criteria-passed 3 --criteria-total 3 \
  --note "Installation, navigation and EN/RU content checked"
```

Это иллюстрация записи, а не результат проверки вашего проекта. При необходимости используйте `partial`, `rejected` или `inconclusive`. Scorer должен обозначать фактического оценщика результата.

Запись вердикта сама по себе не проверяет артефакт. Сохраняйте основания проверок и приёмки вместе с задачей. Покрытие задач отличается от числа прогонов; высокая активность не доказывает полезное продвижение.

## Источники и интерпретация

| Данные                             | Локальный источник                                 |
| ---------------------------------- | -------------------------------------------------- |
| Вызовы, доставка, usage и вердикты | `.wolf/metrics/session-metrics.jsonl`              |
| Решения доставки лиц               | `.wolf/router.log`                                 |
| Вызовы скиллов                     | `.wolf/metrics/skill-invocations.jsonl`            |
| Объекты памяти и их изменения      | `.wolf/memory/`, `events.jsonl`, `relations.jsonl` |
| Снапшоты эффективности             | `.wolf/metrics/effectiveness-snapshots.jsonl`      |

Поля событий, импорт usage и идентичность сессий — в [Телеметрии](/ru/guide/telemetry). Получение памяти отличается от ссылки на неё или применения; запись следующих стадий объяснена в [Интеграции харнессов](/ru/guide/harness-integration).

Денежная стоимость требует настроенных цен и подходящих записей usage. Неизвестная модель, отсутствующие токены или связь сессии — ограничение качества данных, а не нулевая стоимость. `weighted = input + 0.1 × cache_read + 5 × output` — фиксированная эвристика токенов, а не счёт провайдера.

Представление Стюарда включает исходы жалоб и агрегацию уроков. Сопоставляйте числа с реальными изменениями и их применимостью: закрытая жалоба не доказывает доставку исправленной методики в следующую сессию или улучшение поведения.

## Необязательные сравнения

Кампании объединяют прогоны и вердикты через `--campaign`. Атрибуция памяти связывает доставленные объекты с результатами сессий. Это наблюдательные сравнения: различие могут объяснять задачи, модели и условия сессий. Ассоциация не доказывает, что улучшение вызвано Wolf.

Разделяйте группы кампании по сессиям, указывайте способ оценки и проверяйте размер выборки и пробелы данных. Малые или неполные группы дают `n/a` там, где метрику нельзя рассчитать. Практические примеры и наблюдения своего проекта полезны без универсальных обещаний экономии.

Подробный справочник сохраняет поля представлений, lifecycle-классы, пороги, снапшоты, JSON, цены и правила связывания кампаний: [CLI аналитики](/ru/guide/cli/analytics). Расчёты переиспользования — в [Накопленных инструментах](/ru/guide/tool-economy).
