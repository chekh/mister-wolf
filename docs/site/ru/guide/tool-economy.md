# Накопленные инструменты

Полезный скрипт может стать постоянной способностью проекта. Wolf хранит доступную для поиска карточку: назначение, исходные файлы, входы, выходы и среда. Следующая задача может использовать готовое решение вместо повторного создания.

Рабочий процесс связывает инструмент с задачей и проверкой; одна регистрация не подтверждает пригодность или безопасность скрипта в любой среде.

## Найти перед созданием

```bash
wolf tool list
wolf search "documentation links"
```

Перед применением изучите контракт и исходники кандидата. Устаревший или несовместимый инструмент не становится подходящим только потому, что уже существует. О нехватке возможностей и повторном трении сообщайте ответственному исполнителю; изменения методики проходят [контур Стюарда](/ru/guide/feedback).

## Зарегистрировать проверенный ресурс проекта

Для существующего, проверенного скрипта `scripts/check-links.sh`:

```bash
wolf tool register scripts/check-links.sh --name check-links --language bash \
  --contract-in "Project root" \
  --contract-out "Exit 0 for valid links; nonzero with diagnostics" \
  --contract-env "Bash and the script's declared dependencies"
```

Файл должен существовать в проекте. Пример задаёт ожидаемый контракт; перед регистрацией проверьте соответствие реального скрипта. Существенные вспомогательные файлы добавляются повторяемым `--resource <path>`.

Регистрация сохраняет ссылку, не копирует исходники в `.wolf/tools/`. После изменения файлов явно обновите ту же карточку через `--update <name-or-id>` с текущим путём и параметрами. Старые карточки с путями в `.wolf/tools/` продолжают работать. Digest проверяет перечисленные файлы, а не всю среду или побочные эффекты.

## Применить, экспонировать и вывести из использования

```bash
wolf tool use check-links
```

`tool use` фиксирует использование и печатает контракт. **Скрипт эта команда не исполняет.** Настоящий entrypoint запускается только в пределах разрешений и среды задачи.

`wolf tool expose check-links` генерирует OpenCode-скилл из карточки. Экспозиция добавляет канал обнаружения, но не даёт полномочий исполнения. `tool deprecate` и `tool revive` управляют доступностью при изменениях проекта. Точные флаги: [справочник CLI](/ru/guide/cli/command-reference).

## Оценить переиспользование при необходимости

`wolf tool stats` показывает счётчики и, при наличии подходящих run-записей, сравнение переиспользования. `usage_count` подтверждает регистрацию использования, а не величину экономии времени или денег.

Сравнение использует `weighted = input + 0.1 × cache_read + 5 × output`. Медиана weighted прогонов с пометкой инструментов сравнивается с медианой всех записанных прогонов. Нужно не менее трёх пригодных записей в каждой группе; при неположительной общей медиане процент экономии не вычисляется. Группы пересекаются и могут содержать разные задачи, поэтому процент описательный и не доказывает причинный эффект.

Локальное наблюдение полезно для обслуживания библиотеки без универсальных обещаний продуктивности. Качество данных и интерпретация: [Аналитика](/ru/guide/analytics).
