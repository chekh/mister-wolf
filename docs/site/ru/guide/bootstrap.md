# Знакомство Wolf с проектом

Bootstrap готовит стартовое понимание существующего проекта. Пользователю не нужно вручную классифицировать память: команда сканирует проект, регистрирует ссылки на документы и предлагает начальные конвенции для проверки.

## Что происходит

`wolf init` создаёт структуру памяти. Затем `wolf bootstrap`:

1. Сканирует файлы и документы проекта.
2. Готовит черновики конвенций из найденных фактов: языки, команда проверки, расположение документации.
3. Сохраняет правила как низкоуверенные объекты `proposed`.
4. Открывает или переиспользует тред знакомства и печатает его ID и дальнейшие шаги.

Предложенные конвенции ещё не действуют. Язык по расширению файла — не проверенное описание стека; команда из `package.json` может требовать уточнения для проекта.

## Начните с диалога

После [установки](/ru/guide/getting-started) выполните в проекте:

```bash
wolf bootstrap
```

Затем обратитесь к Mr. Wolf в настроенной агентной среде:

> Разбери со мной результаты bootstrap. Поясни предложенные конвенции проекта, уточни существенные пробелы и помоги завершить знакомство с проектом.

Сама команда не вызывает LLM и ничего не запускает автоматически. Помощник организует проверку в пределах полномочий проекта; изменения методик проходят авторизованный маршрут обратной связи — в 3.0.0 Стюард за ним временно отключён, сигналы фиксируются до его возврата. В режиме только памяти используйте подключённого помощника или проверьте черновики через CLI.

## Что подтвердить

В результате должны быть понятны назначение проекта, авторитетные документы и обязательные проверки. Исправьте существенные ошибки; запоминать типы объектов не требуется. Попросите помощника объяснить итог обычным языком и выделить неразрешённые конвенции.

Для ручной проверки:

```bash
wolf list --type rule --status proposed
wolf list --type document-ref
wolf list --type thread
```

Используйте реальные ID правил и треда из этих команд или bootstrap brief. Принятое правило и действующее правило — разные состояния жизненного цикла. Перед активацией проверьте область применения; закрывайте тред знакомства после обработки или явного откладывания оставшихся вопросов. Изменения и переходы описаны в [Модели памяти](/ru/guide/memory) и [командах памяти CLI](/ru/guide/cli/memory).

## Завершение и повторный запуск

Полезный итог — краткое объяснение подтверждённых конвенций, команды проверки, зарегистрированных документов и открытых вопросов. `wolf doctor` проверяет целостность проекта, но не подтверждает понимание или согласование каждой конвенции человеком.

Повторный bootstrap при активном знакомстве переиспользует тред и пропускает предложенные правила с тем же заголовком. После завершения или откладывания треда команда возвращается без нового сканирования; установленный проект не возвращается к черновикам. Для последующих изменений документов используйте обычное сканирование и обслуживание памяти вместо удаления завершённого треда.

Источник поведения: [`bootstrap-project.ts`](https://github.com/chekh/mister-wolf/blob/main/src/app/use-cases/bootstrap-project.ts).
