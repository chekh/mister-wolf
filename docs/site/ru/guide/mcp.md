# Интеграция MCP

## Что такое MCP

Model Context Protocol — стандарт подключения внешних инструментов к AI-агентам. Mr. Wolf поставляет MCP-сервер: вся память и процессы проекта доступны агенту любой MCP-совместимой платформы. Сервер запускается по stdio командой `wolf mcp`.

## Подключение

MCP-конфиги платформ — opt-in: их пишет `wolf init --platform opencode,claude` (список заменяет текущий набор); простой `wolf init` конфигов не пишет. Платформы v1: opencode, Claude Code. После init, записавшего конфиги, перезапустите платформу — сервер подключается при старте.

Каноническая команда запуска — глобальный бинарник, **никогда npx**:

```json
{ "command": "wolf", "args": ["mcp"] }
```

### opencode

Пишется в `opencode.json`, ключ `mcp.servers.wolf` (плоская карта `mcp.wolf` — deprecated, читается только для миграции):

```json
{ "mcp": { "servers": { "wolf": { "type": "local", "command": ["wolf", "mcp"], "disabled": false } } } }
```

Wolf читает и второе место, откуда opencode берёт конфиг проекта, — `.opencode/opencode.json(c)`: opencode мержит его после корневого файла, поэтому он перекрывает корневой. Сервер, объявленный только там, считается объявленным: `doctor` не сообщает, что его нет, `init` не дописывает рядом второй ключ, а `uninstall` снимает его оттуда, где он объявлен.

### Claude Code

Пишется в `.mcp.json`, ключ `mcpServers.wolf`:

```json
{ "mcpServers": { "wolf": { "command": "wolf", "args": ["mcp"] } } }
```

Оговорка: try-out-режим (`npx mister-wolf init`) никогда не пишет MCP-конфиги — установите пакет глобально и запустите `wolf init --platform opencode,claude`, чтобы подключить платформы.

MCP-клиент автоматически добавляет префикс `<имя-сервера>_`, поэтому агент видит инструменты как `mr-wolf_search`, `mr-wolf_get` и т.д.

## Все инструменты

8 инструментов (7 + health check `ping`). Семейство create\_\*, инструменты мышления, `scan`, `insights` и `analytics` удалены в 2.13 — вызов удалённого инструмента возвращает ошибку с подсказкой миграции; используйте `add` (типы), `transition` (статусы) или CLI-эквиваленты.

| Инструмент           | Описание                                                                                          | Ключевые параметры                                                                                                                                                                                                                                                                   |
| -------------------- | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `mr-wolf_search`     | Поиск объектов памяти по запросу с опциональными фильтрами                                        | `query` (string, обяз.); опц.: `type`, `status`, `confidence` (low\|medium\|high), `memoryClass`, `truthRole`, `lifetime`, `tags` (string[]), `minImportance`/`maxImportance` (number), `createdAfter`/`createdBefore` (string), `file_path`, `limit`, `includeSuperseded` (boolean) |
| `mr-wolf_get`        | Получить объект памяти по id                                                                      | `id` (string, обяз.)                                                                                                                                                                                                                                                                 |
| `mr-wolf_list`       | Список объектов памяти с опциональными фильтрами                                                  | `type`, `status`, `stale` (boolean), `memoryClass`, `truthRole`, `lifetime` — все опциональны                                                                                                                                                                                        |
| `mr-wolf_add`        | Добавить объект памяти любого типа таксономии (включая бывшие цели create\_\*)                    | `type` (обяз.), `title` (обяз.), `createdBy` (обяз.); опц.: `body`, `tags` (string[]), `confidence`, `importance` (number) + поля отдельных типов                                                                                                                                    |
| `mr-wolf_transition` | Сменить статус жизненного цикла (включая закрытие блокеров — это статус, а не отдельный тул)      | `id` (обяз.), `status` (обяз.); actor фиксируется как `agent:mcp`                                                                                                                                                                                                                    |
| `mr-wolf_brief`      | Бриф агента по последнему скану и памяти                                                          | — (переиспользует кэшированный снапшот проекта)                                                                                                                                                                                                                                      |
| `mr-wolf_recap`      | Сводка активной памяти: правила, рабочие треды, блокеры, вопросы, info requests, недавние решения | —                                                                                                                                                                                                                                                                                    |
| `mr-wolf_ping`       | Health check MCP-сервера Mr. Wolf                                                                 | — (возвращает `pong`)                                                                                                                                                                                                                                                                |

## Бриф и кэш скана

`mr-wolf_brief` не пересканирует проект на каждый вызов — он переиспользует кэшированный снапшот проекта. Кэш инвалидируется автоматически при **структурных** изменениях: добавление, удаление или переименование файлов, смена зависимостей в `package.json`, переключение ветки. Контентные правки существующих файлов перескана не требуют: бриф зависит от множества путей, а не от содержимого файлов.

Если нужен гарантированно свежий снапшот — CLI `wolf scan` всегда делает полный перескан с регистрацией документов: это его работа, не работа брифа (MCP-тул `scan` удалён в 2.13).

Кроме того, бриф читает память через mtime-кэш разбора, поэтому повторные брифы дёшевы: неизменённые объекты памяти отдаются без перечитывания и перепарсивания файлов.

## Доставка: дедупликация сессии и бюджет контекста

Инъекции `wolf call` дедуплицируются в рамках сессии: запись доставляется в сессию **один раз**, повторно — только при изменении текста (контрольная сумма блока). Ключ сессии берётся из `WOLF_SESSION` — плагин wolf-router ставит один ключ на процесс платформы, поэтому все спавны `wolf call` внутри сессии делят его; свежая сессия всегда получает полную доставку. Когда дедупликация отфильтровывает всё, вызов объясняет себя вместо пустого списка: `[wolf] N инъекций уже доставлены в этой сессии (дедупликация; изменившиеся записи доставляются повторно)`. Реестр доставок — derived-кэш в `.wolf/cache/sessions/`, файлы старше 7 дней удаляются. Вызовы без ключа сессии не дедуплицируются — каждый новый контекст получает свою конституцию.

`wolf call` также считает, сколько байт инъекций накопила сессия (аппроксимация токенов: bytes/4), и при превышении настроенной доли бюджета контекста (дефолт 20% от 200 000 токенов) печатает одну строку в stderr:

```text
[wolf] инъекции сессии ~27% бюджета контекста (216000 bytes / 200000 tokens) — лимит предупреждения 20%
```

Предупреждение не блокирует доставку и не меняет код возврата. Настраивается (или отключается) в `.wolf/config.yaml` — см. [Конфигурация](/ru/guide/configuration):

```yaml
delivery:
  context_budget_tokens: 200000 # бюджет контекста сессии, токены
  context_warning_pct: 20 # порог предупреждения, %; 0 — выключить
```

Общая картина доставки — топ доставляемых записей, miss-rate по агентам, средний размер инъекции — видна в `wolf recap` (строка доставки) и `wolf analytics --view delivery` ([CLI-аналитика](/ru/guide/cli/analytics)).

## Типичная сессия агента

Подключённый агент обычно ходит по этому циклу:

1. **Проверка здоровья** — `mr-wolf_ping` (ожидайте `pong`).
2. **Ориентация** — `mr-wolf_brief` (по кэшированному снапшоту проекта — см. [Бриф и кэш скана](#бриф-и-кэш-скана)) и/или `mr-wolf_recap` для активного состояния: правила, рабочие треды, блокеры, открытые вопросы, недавние решения.
3. **Точечный поиск** — `mr-wolf_search` с фильтрами, напр. `{ query: "supersede", type: "rule" }`; `mr-wolf_get` с `{ id: "mem_…" }` — прочитать найденное; `mr-wolf_list` с `{ type: "decision", status: "active" }` — обзор.
4. **Запись обратно** — `mr-wolf_add` для любого типа (поля отдельных типов — в том же вызове, напр. `{ type: "decision", title, body, thread }`), `mr-wolf_transition` (`{ id, status }`, actor фиксируется как `agent:mcp`) для смены статусов — включая закрытие бывших блокеров: это теперь статус, а не отдельный тул.
5. **Завершение** — снова `mr-wolf_recap`, чтобы подтвердить состояние, которое унаследует следующая сессия.

Каждый шаг имеет CLI-эквивалент (`wolf scan`, `wolf brief`, `wolf search`, `wolf add`, `wolf recap`) — память одна и та же, канал любой.

Атрибуция: объекты, созданные через MCP, несут `createdBy`, который вы передали (actor-строки вида `agent:mcp`); `mr-wolf_transition` фиксирует actor как `agent:mcp`.
