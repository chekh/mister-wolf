# Постоянная организация из временных агентов

Каждый ИИ-агент — временный работник: он приходит с холодным контекстом, отрабатывает одну сессию и уходит. Более умная модель это не меняет — опыт всё равно испаряется вместе с сессией.

Mr. Wolf атакует проблему с другой стороны. Он даёт проекту **постоянную организацию**: роли, рабочий цикл, память и контур обучения живут в репозитории, пока агенты приходят и уходят. Организационная структура долговечна; люди в ней сменяемы. Local-first — всё живёт в ваших файлах, не в чужом облаке.

Мы разрабатываем самого Wolf через эту организацию каждый день. Страница, которую вы читаете, написана L2-воркером по брифу от L1 и принята L0 — ровно тот цикл, что описан ниже. Релизы Wolf собираются так же; паттерн несущий, а не декоративный.

## Три уровня, чистые запреты

Иерархия маленькая намеренно. Каждый уровень владеет одним делом и прямо запрещён делать чужое:

| Уровень              | Владеет                                                 | Никогда не делает                                 |
| -------------------- | ------------------------------------------------------- | ------------------------------------------------- |
| **L0** — координатор | целью, критериями приёмки, финальным вердиктом          | не исполняет работу; не вызывает L2               |
| **L1** — executor    | поставкой одной задачи: декомпозиция, интеграция, отчёт | не обходит процесс; не трогает поведение воркеров |
| **L2** — воркер      | ровно одной ограниченной подзадачей в чистой сессии     | никого не спавнит; не расширяет scope             |

Эскалация идёт **вверх** (L2 → L1 → L0) или **вбок** — в Council, но никогда в обход структуры. L0 — единственный, кто говорит с владельцем проекта; L1 — единственный, кто говорит с воркерами. Каждый бриф несёт только то, что нужно следующему уровню, поэтому любая сессия остаётся маленькой, сфокусированной и сменяемой. Запреты — не кодекс чести: каждый вызов в топологии имеет машинно проверяемое основание.

Роли — не метафора: они соответствуют конкретным агентам, которые доставляет `wolf init`, — см. [Базовый набор](/ru/guide/base-set).

Ограничение — половина дизайна; компенсация — вторая половина. Иерархия намеренно ограничивает контекст и полномочия каждого агента. Типизированная память компенсирует то, что теряется при каждой передаче работы. Council компенсирует односторонность вертикальной цепочки. Чекпоинты компенсируют дрейф за время длительной работы. Ничего из этого не живёт в голове агента — всё живёт в проекте.

## Рабочий цикл

```text
goal → brief → plan → execute → report → accept → checkpoint
```

| Шаг          | Кто               | Что происходит                                                                                       |
| ------------ | ----------------- | ---------------------------------------------------------------------------------------------------- |
| `goal`       | владелец → L0     | открывается work-thread с целью и критериями успеха                                                  |
| `brief`      | L0                | желаемый результат, scope, ограничения, критерии приёмки — без техдекомпозиции                       |
| `plan`       | L1                | декомпозиция, зависимости, назначения воркеров, план проверки                                        |
| `execute`    | L1 → L2           | воркеры выполняют ограниченные подзадачи в чистых сессиях; на трудных развилках подключается Council |
| `report`     | L1                | executor-report плюс проверяемые артефакты                                                           |
| `accept`     | L0                | вердикт по acceptance-package: принять, вернуть или эскалировать                                     |
| `checkpoint` | runtime / L0 / L1 | детерминированный recap состояния плюс свежие сигналы для контура обучения                           |

Чекпоинты срабатывают не только после приёмки, но и внутри длительной работы: перед сменой исполнителя, после крупного этапа, перед рискованной развилкой, при остановке прогресса. Сессия может умереть в любой момент — состояние организации её переживёт.

Правило чистых сессий делает воркеров дешёвыми в замене. Воркер, умерший посреди задачи, не уносит ничего с собой: бриф лежит на диске, находки — в памяти, а свежий воркер продолжает с чекпоинта.

Последний шаг питает первый: уроки, жалобы и метрики, зафиксированные на чекпоинте, формируют следующий цикл, — здесь рабочий цикл передаёт эстафету контуру обучения.

## Приёмка по проверяемым артефактам

Вердикт никогда не принимается на слово. L0 принимает или возвращает работу по **acceptance-package** — машинно проверяемым доказательствам, приложенным к отчёту:

```text
результаты по критериям · команды проверки · коды выхода · хеши артефактов
вердикт независимого ревью · известные ограничения · нерешённые риски
```

«Работает» — это утверждение. «Команда проверки → exit 0» — это доказательство. Критерии приёмки приходят из брифа, поэтому L0 остаётся независимым от реализации: он судит артефакты, а не уверенность исполнителя. Известные ограничения — часть пакета: заявленные, а не спрятанные.

Для высокорисковых поставок добавляется ещё один слой: работа L1 попадает к **отдельному L2-ревьюеру** до того, как её увидит L0, а сверху может добавиться независимый L1-аудит.

```text
поставка L1 → отдельный L2-ревьюер → acceptance-package → вердикт L0
```

Пакет — фиксированный контракт, поэтому вердикт остаётся аудируемым месяцы спустя: что проверялось, какими командами, по каким критериям — и что заведомо осталось несделанным.

## Council — независимые мнения на трудных развилках

**Статус: DESIGNED** — схема уже живёт в памяти; runtime — в дорожной карте. Честное состояние — в [maturity.md](https://github.com/chekh/mister-wolf/blob/main/docs/concept/maturity.md).

Когда развилка по-настоящему трудная, рабочий цикл может созвать Council. Созыв измерим, а не дело вкуса — триггеры перечислены явно:

- высокая неопределённость или высокий риск;
- необратимое решение;
- междисциплинарный конфликт;
- противоречивые данные;
- остановившийся прогресс у L1;
- архитектурное решение с большим радиусом воздействия.

L1 созывает Council для технических развилок внутри своей поставки; L0 — для продуктовых и стратегических. Несколько агентов затем выдают **независимые мнения**, каждое формируется до чтения чужих, чтобы консилиум не превратился в пять копий первого ответа. Синтез сохраняет то, что пережило проверку: принятые утверждения, отвергнутые альтернативы, неразрешённые разногласия.

Мнение — это контракт, а не голос: позиция, утверждения, evidence, допущения, уверенность, риски, контрпримеры и рекомендуемая проверка. Council рекомендует; решение принимает тот уровень, которому оно принадлежит. А поскольку консилиум из нескольких агентов дорог, он ограничен: кворум, бюджет и максимум раундов.

## Штампы статусов — легенда честности

Каждый механизм канона несёт штамп зрелости — и эта страница тоже:

| Штамп                | Значение                                                            |
| -------------------- | ------------------------------------------------------------------- |
| **I3**               | внедрено и используется ежедневно в разработке самого Wolf          |
| **validating (E1x)** | целевой эффект проходит benchmark-подтверждение (программа E1a–E1e) |
| **DESIGNED**         | описано в каноне; runtime ещё нет — в дорожной карте                |

На сегодня: иерархия L0/L1/L2 и рабочий цикл — **I3**, догфудинг в этом репозитории; runtime Council — **DESIGNED**. Полная матрица — в [maturity.md](https://github.com/chekh/mister-wolf/blob/main/docs/concept/maturity.md).

## Куда организация идёт дальше

Организация совершенствуется благодаря текучке, а не вопреки ей. Поведение агента живёт в его playbook'е — мутируемом «лице», хранящемся в памяти, — а рамка (роль, границы, запреты) остаётся статичной. Когда контур обучения находит способ лучше, лицо сменяется новой версией; сам агент никогда не владеет собственной эволюцией.

- [Модель памяти](/ru/guide/memory) — где живёт состояние организации: семь типов, lifecycle, supersede-цепочки.
- [Контур обучения](/ru/guide/feedback) — как организация учится: жалоба → триаж → мутация playbook'а.
- [Начало работы](/ru/guide/getting-started) — развернуть организацию в своём проекте.
