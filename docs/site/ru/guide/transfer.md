# Перенос и мультипроектность

Mr. Wolf — local-first: память проекта это каталог внутри проекта, а список проектов машины — локальный индекс. Формула переноса отсюда прямая:

**Память коммитится → клонирование переносит.**

`.wolf/memory/` (markdown-объекты, `events.jsonl`, relations) принадлежит git. Клонируете репозиторий на другую машину — запускаете любую команду волка — и вся память уже на месте: решения, уроки, правила, плейбуки. Без экспорта, без импорта, без облака.

## Реестр — телефонная книга

Реестр машины (`~/.config/wolf/projects.yaml`) хранит только соответствие имён проектов путям. Это **не** память, и переносить его не нужно: на новой машине любая команда волка в проекте с существующим `.wolf/memory/` перерегистрирует его автоматически (самолечение). Реестр остаётся локальным индексом — и поскольку в нём пути всех ваших проектов, держите его вне коммитов и баг-репортов.

Одна команда показывает всё, что знает телефонная книга:

```bash
wolf projects
```

```text
имя          путь                          версия схемы  последняя активность  размер памяти
mister-wolf  /Users/…/mister-wolf          v2            2026-09-30            2.6 MB
Tender       /Users/…/Tender               v2            2026-09-30            2.3 MB
old-box      /mnt/archive/old-box          missing

проектов 3 | активны за 7д: 2 | суммарный размер памяти: 4.9 MB
```

Все поля вычисляются на лету (активность = mtime `events.jsonl`, размер = рекурсивный размер `.wolf/memory/`) — схема реестра не расширяется, `missing` помечает мёртвые пути.

## Гигиена

`wolf doctor` держит реестр и обвязку честными:

- **Песочницы** — записи под системным tmpdir это остатки тестов/песочниц; doctor чистит их автоматически (с пометкой `sandbox — pruned`; данные песочницы по определению временные).
- **Мёртвые записи** — пути, которых больше нет, чистятся с отчётом.
- **Призрак-детект** — для текущего каталога и каждого зарегистрированного проекта doctor сравнивает маркер onboarding в `AGENTS.md`/`CLAUDE.md` с наличием `.wolf/memory/`:
  - маркер есть, памяти нет — «инструктирует wolf, памяти нет»: выполните `wolf init`;
  - память есть, маркера нет — «память есть, агент не подключён»: выполните `wolf sync`.
- **Самолечение** — любая команда волка в проекте с памятью, но без записи в реестре, тихо перерегистрирует его (no-op при идентичной записи).

## Что коммитить

`.wolf/memory/` — durable-ядро, коммитьте его. Рантайм-артефакты (метрики, кэши, бэкапы) пересоздаются локально; более тонкий durability-сплит (что коммитить и что игнорировать внутри `.wolf/`) — в дорожной карте. Экспорт/импорт архивом сознательно не сделан — git уже является форматом переноса.
