# Formulate requirements

Read the agreed frame, constraints and project-rules.md from using-skills.
Keep the existing template, IDs, statuses; assign unique IDs to new statements.
Every requirement describes observable behavior; an NFR has a measurable criterion
and conditions where possible. Separate independent AC/Given-When-Then with real blocks.
State normal, negative and substantial boundary cases, scope and exceptions.
Do not hide a new requirement in a test or design. Do not add the author's wish
as an owner's fact. Mark the unknown with a question. When done → writer → independent
review → approval per the project rules. A change to accepted content — a CR and an
addressed downstream-impact assessment.
