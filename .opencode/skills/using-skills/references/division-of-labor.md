# Разделение труда и границы поручений

Загружает наниматель L0/L1 перед назначением, продолжением или заменой подчинённого.
Доставленный актуальный текст повторно не ищи. Методика выбирает границы работы и
экземпляр исполнителя; действующие планирование, проверки, независимое ревью и
приёмка сохраняются. Права задаёт рамка: L0 назначает L1, L1 — L2; L1 не нанимает
других L1, L2 никого не спавнит.

## Ограниченное поручение

Нанимай на законченный по смыслу, самостоятельно принимаемый результат с явными
критериями, входами, scope, полномочиями и бюджетом. L1 организует ограниченную
поставку через L2; L2 выполняет конечную часть. Общие цель, thread, тема, лицо и
пользовательская сессия не задают срок жизни экземпляра. Несколько связанных
действий, проверок и исправлений могут составлять одну поставку; не создавай
агента на файл, команду или формальный этап. Не объединяй самостоятельные
поставки в поручение «весь проект», «всё до завершения сессии» ради удобства.

Перед следующим назначением различи:

| Выбор | Основание |
| --- | --- |
| fresh | Новый самостоятельно принимаемый результат → новый экземпляр и отобранный TASK. Это действует и для последовательной работы одного L1. |
| continue | Тот же непринятый результат → прежний экземпляр: ответ на вопрос, разблокировка, предусмотренная часть поставки или исправление замечаний. |
| replace | То же поручение, но исполнитель недоступен либо контекст непригоден → новый экземпляр через wolf-handoff. |

Новое имя TASK не делает старую сессию свежей; совпадение task_id с параметром
инструмента не делает task_id идентификатором сессии. Continue не расширяет scope.
После приёмки самостоятельного результата следующую поставку не добавляй прежнему
исполнителю, даже если проект и тема прежние. Промежуточное согласование внутри
одного заранее ограниченного поручения не закрывает всё поручение автоматически.
Недоступный fresh/close или наследование истории host'ом укажи как ограничение;
не выдавай новую метку за сброс контекста и не обходи permissions.

## Подготовка и назначение

Оценка и планирование — существующие виды работы, а не четыре обязательных
вызова перед каждым назначением. Используй уже достаточные входы и принятый план.
Если распределение общей цели между несколькими L1 требует предметной работы,
L0 поручает L1 подготовить план по wolf-plan. Планирующий L1 организует нужную
помощь L2 и возвращает готовые ограниченные брифы L1, зависимости/условия запуска,
предложения по параллельности, общий бюджет и владельца интеграции. L0 принимает
план по цели/полномочиям и выполняет назначения, не дописывает техническую
декомпозицию сам. Пробел возвращает автору плана. План — отдельный результат,
если именно планирование было поручено; его приёмка не разрешает реализацию.
Малая понятная поставка не требует отдельного планировщика: L1 планирует свой
мандат и назначает L2 в его пределах. Планирование не расширяет права на найм.

Готовые независимые поручения запускай параллельно в пределах общего бюджета
и возможностей host. Границы записи/общих ресурсов, dependencies и порядок
интеграции должны быть известны; блокер останавливает зависимых, не остальных.
При нескольких L1 каждый владеет своей поставкой; техническую интеграцию
организует назначенный L1, итоговый verdict сохраняет L0/владелец. Общие plan,
память и иные изменяемые артефакты имеют одного назначенного писателя; изменение
владельца проходит handoff. L0 получает краткие статусы и ссылки на версии,
а не весь контекст планирования; подробный план ведёт назначенный L1.

## Коммуникация и завершение

Применяй действующий agent-language.md целиком и формы contracts.md. Назначение
оценки, плана или поставки выражай целью/результатом/scope существующего TASK;
новых типов сообщений, профилей, обязательных слотов и статусов нет. Ссылки на
поручение и входы адресные, по ID с версией; описательное обсуждение остаётся
свободным. Сохраняй формы RESULT роли: L1 REPORT/STATUS/CRITERIA, L2 — по профилю.
Готовность отчёта не означает приёмку, приёмка плана не означает исполнение.
Непокрытое формой — «вне контракта» по R6; доказанное языковое затруднение —
LANGUAGE-предмет через wolf-feedback, не самостоятельное изменение языка.

Возврат вопроса/отчёта завершает вызов, но не обязательно поручение. Наниматель
применяет существующие гейты; новую сессию не используй для автоматического
повтора достаточных проверок. Новый исполнитель получает относящиеся артефакты,
evidence, ACTIVE_CONSTRAINTS/DECISIONS[] и открытые вопросы, не архив чата.
Replace сохраняет task_id, критерии, замечания и уже израсходованный бюджет
поручения; fresh не отменяет лимит общей поставки. Неизвестные расходы отметь,
не объявляй нулём; нового механизма учёта это правило не создаёт.

После приёмки сохрани нужные результаты/evidence и заверши использование
экземпляра для поручения. Перед закрытием/заменой останови запись и проверь
процессы по wolf-handoff; закрытие не удаляет worktree или evidence. Если host
не умеет закрывать сессию, перестань назначать ей работу и укажи ограничение.
