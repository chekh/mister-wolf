# Линейное исполнение

## Обязательный вход

До правок проверь входы, роль, текущую рабочую копию и разрешения. L0 не выполняет этот процесс: передаёт его executor. L2 исполняет только назначенную подзадачу без коммитов и спавна. Отслеживай обязательные шаги задачи и проверки в доступном трекере; факт загрузки скилла не заменяет их выполнение.

Загрузи полный текст назначенной методики до её выполнения. Обязательные пункты отслеживай в доступном трекере или рабочем брифе; не добавляй новые статусы памяти. Недоступное действие передай ответственному уровню.


## Вход и ограничения

Применять только исполнительской роли. Этот маршрут применим, когда диспетчеризация недоступна или не нужна. Входы и TASK/RESULT/EVIDENCE — как в using-skills. Утверждённый FULL plan требует design и test-plan; LITE/FIX достаточно разрешённого брифа. Проверь workspace, профиль проекта, baseline и права на git. L0 передаёт работу executor, не использует fallback для обхода своей рамки.

## Процесс

1. Сверь входы с текущим кодом; обозначь несовместимость до правок. Зафиксируй зависимости и исходные падения проверок.
2. L1 при недоступной/ненужной диспетчеризации выполняет разрешённую линейную работу; L2 — только один назначенный конечный мандат без интеграции поставки. Выполняй свои ready-шаги последовательно: прочитай затронутый код, пройди подходящую тестовую дисциплину, внеси allowlist-изменения, проверь результат и сохранённые инварианты.
3. После каждой задачи запиши RESULT/evidence. Коммит выполняй только при разрешении роли и пользователя. L1 ставит отметку [x] после нужного ревью; до него сохрани состояние «готово к ревью» без выдуманного значения таксономии.
4. L2 возвращает checkpoint по своему стоп-условию. L1 сохраняет checkpoint на завершённом компоненте, перед сменой этапа или сессии; default не более 3 небольших задач без сохранения состояния. В него включи baseline/current state, completed/remaining, evidence и dirty-state.
5. L2 возвращает результат/запрос ревью L1. L1 организует независимое ревью разрешённым каналом; при его отсутствии передаёт ограничение L0/владельцу. Саморевью не независимо.
6. L1 после интеграции выполняет test-plan и полный применимый гейт, формирует ACCEPTANCE; L2 возвращает RESULT, не выполняет этот этап. Дальнейший git-финал — finishing-a-development-branch.

## Завершение без повторов

Режим execute не открывает заново утверждённое решение. Читай только нужные
источники; повторяй проверку при изменении её входов, новой ошибке или явном
требовании. L2 при неожиданной сложности/новом способе или двух шагах без
продвижения возвращает результат и вопрос L1; сам исследование не выбирает.
Конечный лимит обязателен, без заданного — возврат через 8 обращений. Сбой инструмента: один осмысленный обход, затем FRICTION и остаток,
не отдельное исследование устройства среды. После назначенных проверок верни
RESULT; не увеличивай объём работы ради более длинного отчёта.

## Блокер и восстановление

При недостатке контекста верни NEEDS_CONTEXT; при невозможности продолжения — BLOCKED с причиной, выполненным и безопасным следующим действием. Локальную очевидную ошибку исправь в лимите. Неизвестная причина/новый способ для L2 — возврат L1, а не самостоятельный запуск wolf-debug. L1 выбирает следующую диагностическую подзадачу без опроса владельца о локальных деталях. Изменение scope/контракта эскалируй.

После прерывания сверяй план с фактическими файлами, git и evidence. Не повторяй миграции, публикации и внешние действия без проверки их исхода. По лимиту назначенных повторов (default 2) L1 пересматривает подход; L2 возвращается раньше по своему стоп-условию. Недоступную запись памяти передай ответственному уровню.

## Гейт перехода

L2 после самопроверки возвращает RESULT/evidence L1; DONE означает готовность к ревью. L1 организует предусмотренное ревью, интеграцию, ACCEPTANCE и согласованный git-финал. verification-before-completion применяет каждая роль к собственным утверждениям. Недоступный канал явно ограничивает результат, не расширяет роль.

## Не пропускай процесс

| Мысль | Действие |
| --- | --- |
| «Сам проверю и сам приму» | Саморевью не независимо; приёмка остаётся у назначенного уровня. |
| «Нет агентов, значит L0 может писать код» | Недоступность инструмента не расширяет роль. |
| «Продолжу после сбоя с того же действия» | Сначала проверь исход предыдущего действия и checkpoint. |
