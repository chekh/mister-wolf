# Наглядное обсуждение решения

Определи вопрос, который поможет решить показ. Используй уже известные факты
и границы; визуализация не разрешает новое исследование. L0 ведёт разговор,
L1 назначает конечный материал L2 с нужным лицом/скиллами. Отдельный постоянный
агент и три последовательных файла не нужны.

1. Выбери достаточное представление: таблица для точных различий, схема для
   связей/переходов, макет для компоновки, график по реальным данным для чисел,
   интерактивность для вопроса «что изменится». Не украшай ради нормы.
2. Покажи относящееся объяснение по wolf-explain: что видеть, чем отличаются
   варианты, какие последствия/ограничения важны. Условный пример обозначь.
3. Получи различимую обратную связь: вариант, действие либо ответ в чате.
   Изменение UI само по себе не доказывает, что событие получено агентом.
4. Обнови нужное или зафиксируй выбор с его границами. Выбор макета не
   утверждает ещё не показанные requirements/design/реализацию.

## Реальный путь показа

Используй доступный подтверждённый renderer, не придумывай API. Переносимый путь:
показать схему/изображение/статический макет с обозначенными вариантами → получить
ответ в чате → обновить показ. Не запускай сервер, если среда уже умеет показывать.
Если заявлен интерактивный путь, проверь отображение, получение события и
обновление; один HTML-файл не равен работающему взаимодействию. При недоступной
интерактивности используй статический путь и назови ограничение. Если и показ
недоступен, дай понятное текстовое объяснение; не объявляй визуальную проверку.

## Согласованный документ

Самостоятельный документ — отдельный согласованный результат. По запросу или
согласию пользователя подключи wolf-user-report и собери читаемый документ из
обсуждённого; HTML не навязывай. Уже данное разрешение на формат/результат
сохраняется, вопросы на каждый раздел не нужны. wolf-explain обеспечивает язык,
visual-dialogue — наглядность, report — содержание/структуру и оформление.
Вместе они могут создать один результат. Основной ответ и важные ограничения
доступны без обязательных кликов; точные графики/схемы не генерируй как картинки.

Решения и нужный контекст сохраняет L1 по правилам памяти; не каждый экран
становится документом/уроком. Повторяемый шаблон или инструмент учитывай по
`using-skills/references/project-tools.md`, без новой системы ресурсов.
Заверши, когда вопрос понятен или нужный выбор сделан; подготовку документа
без запроса не добавляй как обязательный этап.
