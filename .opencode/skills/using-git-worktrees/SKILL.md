# Подготовка рабочего пространства

## Обязательный вход

L0 поручает подготовку L1; L2 получает готовую рабочую копию. До создания проверь existing worktrees, baseline и владельца изменений. Если работа уже изолирована подходящим способом и политика соблюдена, используй её, не создавая вложенный worktree. Изоляция файлов не доказывает изоляцию БД, памяти и внешних действий.

Загрузи полный текст назначенной методики до её выполнения. Обязательные пункты отслеживай в доступном трекере или рабочем брифе; не добавляй новые статусы памяти. Недоступное действие передай ответственному уровню.


## Владелец

Создание, настройка и git-операции — L1 либо разрешённая исполнительская роль. L2 получает готовые cwd, branch и allowlist. Следуй профилю проекта; local .worktrees/<task> — рекомендуемый fallback, не универсальный запрет других путей.

## Процесс

1. Прочитай AGENTS.md/CI, проверь git status, worktree list, текущую ветку, base branch/SHA и наличие нужной ветки. Зафиксируй чужие незакоммиченные изменения; не убирай их автоматически.
2. Выбери уникальные branch и абсолютный путь. Для внутреннего каталога проверь ignore. Если нужно изменить .gitignore — делай это в пределах scope и полномочий; коммит не является автоматическим условием setup.
3. Создай worktree от явно выбранного baseline, не от случайного текущего HEAD. При существующей ветке/пути выясни владельца; не удаляй и не переиспользуй чужую работу.
4. Установи зависимости согласно lockfile, package manager и CI: frozen/reproducible install, где доступно. Не предполагай npm install или poetry по одному наличию файла. Не меняй lockfile ради setup без причины.
5. Определи .wolf/: с 2.16.0 linked worktree резолвит общую память main-чекоута; записи по умолчанию `scope: worktree:<name>`, перенос в общую память — `wolf promote`. Владелец записи и порядок интеграции фиксируй в TASK.
6. Выполни baseline-проверки профиля; сохрани evidence и исходные падения. Детерминированное известное нерелевантное падение допускается при разрешённой политике с явным ограничением; блокирующее или неизвестное передай L1/L0.
7. Передай TASK: cwd, branch, base_sha, allowlist, setup, checks, memory ownership и baseline limitations.

## Параллельность и cleanup

Отдельные worktree изолируют файлы, но не общую внешнюю БД, процессы, порты и память. Назначь раздельные fixtures/ports и write ownership. Совместимые изменения интегрирует L1 в известном порядке. Память Wolf общая: в linked worktree `wolf` резолвит `.wolf/` в основной чекаут проекта (git common-dir); записи из worktree по умолчанию получают `scope: worktree:<name>` и скрыты из доставки другим рабочим копиям; перенос в общую память — `wolf promote`, а не копирование `.wolf/`.

Путь worktree и имя ветки сохраняй до checkout/cleanup. Уборка — finishing-a-development-branch: после PR рабочая копия сохраняется, пока она нужна для исправлений; грязную или чужую копию не удалять.

## Гейт перехода

Исполнитель получает проверенные cwd, branch, baseline, setup, allowlist, ownership памяти и исходные ограничения проверок. Нельзя передать workspace только по факту создания каталога. Cleanup выполняется отдельно по finishing-a-development-branch и действующему разрешению.

## Не пропускай процесс

| Мысль | Действие |
| --- | --- |
| «Создам от текущего HEAD» | Выбери baseline задачи явно. |
| «Каталог уже есть — удалю» | Выясни владельца и сохранность работы. |
| «Общая .wolf удобнее» | Общая память уже штатна (git common-dir); записи из worktree — `scope: worktree:<name>`, перенос — `wolf promote`, без ручной синхронизации. |
