## Обзор

Git worktree создаёт изолированное рабочее пространство с общим репозиторием: работа в нескольких ветках одновременно без переключений.

**Принцип:** систематический выбор каталога + верификация безопасности = надёжная изоляция.

**Анонс в начале:** «Использую скилл using-git-worktrees для настройки изолированного workspace».

## Выбор каталога

Правило проекта: worktree — **внутри проекта**, `.worktrees/<имя-задачи>` (никаких глобальных путей).

Приоритет:

1. **Существует `.worktrees/`** → использовать его.
2. **AGENTS.md проекта** → прочитать; если указана иная конвенция — следовать ей без вопросов.
3. **Ничего не указано** → создать `.worktrees/` внутри проекта; при сомнениях спросить владельца.

`<имя-задачи>` берётся из брифа executor-lead'а (слаг задачи/фичи).

## Верификация безопасности

Каталог project-local → **ОБЯЗАТЕЛЬНО проверить игнор до создания worktree:**

```bash
# Учитывает локальный, глобальный и системный gitignore
git check-ignore -q .worktrees
```

**НЕ игнорируется?** Правило «почини сломанное сразу»:

1. Добавь строку в `.gitignore`
2. Закоммить изменение
3. Продолжай создание worktree

**Почему критично:** предотвращает случайный коммит содержимого worktree в репозиторий.

## Шаги создания

### 1. Создать worktree

```bash
git worktree add .worktrees/<имя-задачи> -b <имя-ветки>
cd .worktrees/<имя-задачи>
```

### 2. Запустить сетап проекта

Автодетект по файлам проекта:

```bash
# Node.js
if [ -f package.json ]; then npm install; fi

# Rust
if [ -f Cargo.toml ]; then cargo build; fi

# Python
if [ -f requirements.txt ]; then pip install -r requirements.txt; fi
if [ -f pyproject.toml ]; then poetry install; fi

# Go
if [ -f go.mod ]; then go mod download; fi
```

### 3. Верифицировать чистый бейзлайн

Прогнать тесты, чтобы worktree стартовал с чистого состояния (в проектах Wolf — `npm run check`):

```bash
npm run check   # или тестовая команда проекта
```

**Упали?** Доложить о падениях, спросить: продолжать или исследовать.

**Зелёные?** Доложить о готовности.

### 4. Отчитаться о расположении

```
Worktree готов: <полный-путь>
Тесты проходят (<N> тестов, 0 падений)
Готов к реализации <имя-фичи>
```

## Быстрая шпаргалка

| Ситуация | Действие |
|-----------|--------|
| `.worktrees/` существует | Использовать (проверить игнор) |
| Не существует | Создать внутри проекта `.worktrees/` (правило проекта) |
| Каталог не игнорируется | Добавить в .gitignore + коммит |
| Тесты падают на бейзлайне | Доложить о падениях + спросить |
| Нет package.json / Cargo.toml и т.п. | Скипнуть установку зависимостей |

## Частые ошибки

### Пропуск проверки игнора

- **Проблема:** содержимое worktree попадает под трекинг, замусоривает git status
- **Фикс:** всегда `git check-ignore` перед созданием project-local worktree

### Предположение о расположении каталога

- **Проблема:** неконсистентность, нарушение конвенций проекта
- **Фикс:** следовать приоритету: существующий `.worktrees/` → AGENTS.md → правило проекта (внутри проекта)

### Продолжение с падающими тестами

- **Проблема:** не отличить новые баги от существующих
- **Фикс:** доложить о падениях, получить явное разрешение на продолжение

### Хардкод команд сетапа

- **Проблема:** ломается на проектах с другими инструментами
- **Фикс:** автодетект по файлам проекта (package.json и т.д.)

## Пример workflow

```
Ты: Использую скилл using-git-worktrees для настройки изолированного workspace.

[Проверяю .worktrees/ — существует]
[Верифицирую игнор — git check-ignore подтверждает: .worktrees/ игнорируется]
[Создаю: git worktree add .worktrees/auth -b feature/auth]
[npm install]
[npm run check — 47 passing]

Worktree готов: /путь/к/проекту/.worktrees/auth
Тесты проходят (47 тестов, 0 падений)
Готов к реализации фичи auth
```

## Red flags

**Никогда:**
- Не создавать worktree без проверки игнора (project-local)
- Не пропускать бейзлайн-верификацию тестов
- Не продолжать с падающими тестами без вопроса
- Не предполагать расположение каталога при неоднозначности
- Не пропускать проверку AGENTS.md

**Всегда:**
- Следовать правилу проекта: worktree внутри проекта, `.worktrees/<имя-задачи>`
- Верифицировать игнор для project-local каталогов
- Автодетектить и запускать сетап проекта
- Верифицировать чистый тестовый бейзлайн
