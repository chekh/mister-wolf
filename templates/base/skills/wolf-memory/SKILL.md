# Использовать существующую память

Не менять код, таксономию и поля схемы. Документы каноничны в исходных файлах,
индекс производен. Работать через существующий CLI/MCP; точный синтаксис брать
из установленного help при первом неизвестном действии. Не изобретать команды/поля.

| Материал | Запись |
|---|---|
| Цель и состояние многошаговой работы | thread |
| TASK/mini-plan, актуальные вводные | note/context |
| RESULT, checkpoint, review, handoff | note/history |
| Принятое существенное решение | decision со ссылкой на документ |
| Подтверждённый переносимый опыт | lesson |
| Дефект инструкции | complaint |

Рабочим note задавать поддержанные поля: memory_class=working,
truth_role=proposed_knowledge, lifetime=short_term (или session), review_state=proposed,
status=active. TASK ID, owner, dependencies, branch, checks и stop-condition — в теле,
не новые schema-поля. Связь с thread — поддержанное related_to; help уточняет синтаксис.
Мини-план нужен многошаговому поручению; короткому TASK достаточно его CHECK.
Отчёт хранит результат, SHA/digest, evidence refs, LIMITS, остаток и следующий шаг.
Не сохранять каждый tool-call или полное рассуждение. Один канонический текущий указатель,
исторические результаты не переписывать под новый вердикт.

На старте L0 без состояния адресно найти текущий thread и относящиеся правила/решения;
достаточный brief допустим один раз, не перед каждым TASK. L1 читать переданные ID/версии,
не весь brief и архив. Не создавать thread на каждый вопрос или дочерний TASK.
L0 ведёт общую карту, исполнители — собственные назначенные записи; не допускать
одновременную запись одного объекта. По умолчанию L1 возвращает RESULT, L0 сохраняет
только значимое. Перед worktree проверить фактический memory root; копия .wolf в ветке
не доказывает общее хранилище. Не коммитить производную SQLite/секреты против правил проекта.
Нет записи — вернуть ограничение и сохранить по согласованному резервному пути;
не утверждать, что память записана. Лица/face/playbook-доставка не используются.
