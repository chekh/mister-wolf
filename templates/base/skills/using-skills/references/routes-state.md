# Saving, Git and handoff

| When | How to apply | Result |
| --- | --- | --- |
| Git boundary: start, checkpoint, completion | wolf-git: check baseline, preserved state, rights | A confirmed Git state |
| Isolating writes | using-git-worktrees: assign an owner and a separate place | A working copy per the rules |
| Session or executor change, or a restore | wolf-handoff: hand off state and decisions as addressed | Continuation without repeated work |
| Integration and cleanup ready | finishing-a-development-branch: check the preserved state and available actions | A permitted completion |
| Choosing a document's mode or place | [Project rules](project-rules.md): follow the existing agreement | FULL/LITE/FIX and the right materials |
| New useful script | [Project tools](project-tools.md): save it, add a card | A tool for later tasks |

Working memory follows the [addressed contract](context-and-memory.md). Accepted
work at the applicable revision is not repeated; unfinished work continues;
outdated evidence gets an addressed check. Do not turn "unavailable" into "successful". A
dirty working copy is not cleaned for convenience: save the needed result first.
