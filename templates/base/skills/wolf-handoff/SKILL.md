# wolf-handoff: передача в свежую сессию

## Обзор

Когда контекст перегружен, сессия обросла ошибками или впереди много шагов — запиши сжатое резюме handoff и продолжи работу в свежем субагенте через {{tool.task}}.

**Экономика тёплых/холодных сессий:** тёплая сессия дорожает с каждым токеном истории; холодная стартует дёшево, но не знает ничего. Память Wolf ломает этот компромисс: сначала зафиксируй значимое в памяти (`wolf add` — решения, уроки, блокеры), затем передай минимум — свежая сессия подтянет состояние сама (`wolf call` + `wolf brief` на холодном старте).

## Когда использовать

- Окно контекста заполняется или сессия дрейфует
- Переключение с исследования на реализацию
- Нужно сбросить якорь после серии неудачных попыток
- У задачи несколько оставшихся независимых шагов
- Ты сам запущен как субагент и тебе нужно делегировать дальше

## Шаги

1. **Зафиксируй значимое в памяти Wolf.** До передачи:
   - Решения и их обоснование → `wolf add --type decision`
   - Уроки (что сработало / что нет) → `wolf add --type lesson`
   - Открытые блокеры → `wolf add --type blocker`
   Преемник получит их через `wolf call` / `wolf brief` — дублировать в промпте не нужно.

2. **Запиши резюме handoff.** Включи:
   - Что сделано
   - Что осталось
   - Ключевые решения и их логика (ссылками на объекты памяти)
   - Релевантные пути файлов, URL, ссылки на issues/PR
   - Какие скиллы преемнику стоит задействовать
   - Отметку о редактированных секретах, API-ключах, токенах, PII

3. **Запусти свежий субагент через {{tool.task}}.**
   - `description`: короткое описательное имя задачи
   - `subagent_type`: роль преемника — исполнительская роль проекта (например, worker-implementer для реализации, worker-researcher для исследования; координация — через executor-lead)
   - `prompt`: резюме handoff

4. **Отчитайся владельцу: ID и статус задачи субагента.**

## Пример

Резюме handoff:
- Решили оставить публикацию v9-сигналов в `adviser/` (решение: mem от 2026-08-30).
- Реализован `adviser/src/publishers/signal_v9.py`.
- Осталось: подключить в DI-контейнер `adviser/services/di.py` и добавить тесты.
- Файлы: `adviser/src/publishers/signal_v9.py`, `adviser/services/di.py`.
- Скиллы преемнику: test-driven-development, verification-before-completion.

Затем диспетчеризация:
```
{{tool.task}}
  description: Подключить v9-паблишер в DI и тесты
  subagent_type: worker-implementer
  prompt: <резюме handoff>
```

## Что включить

- Конкретные пути файлов и имена символов
- Принятые решения и почему (или ссылки на них в памяти)
- Открытые вопросы и блокеры
- Релевантные тесты, команды, шаги верификации

## Что исключить

- Длинные транскрипты и полные листинги кода
- Секреты, учётные данные, персональные данные
- Контент, уже зафиксированный в артефактах (планы, спеки, коммиты, диффы, память Wolf)

## Red Flags

- Передача без письменного резюме
- Копирование всей беседы в промпт субагента
- Включение API-ключей или токенов
- «Кажется» и размытые следующие шаги вместо исполнимых задач
