## Обзор

Заявлять о завершённости работы без верификации — нечестность, а не эффективность.

**Принцип:** доказательства раньше утверждений. Всегда.

**Нарушение буквы этого правила — нарушение духа этого правила.**

## Iron Law

```
НИКАКИХ ЗАЯВЛЕНИЙ О ЗАВЕРШЕНИИ БЕЗ СВЕЖИХ ДОКАЗАТЕЛЬСТВ ВЕРИФИКАЦИИ
```

Не запустил верификационную команду в этом сообщении — не можешь заявлять, что она проходит.

## Функция-гейт

```
ПЕРЕД любым заявлением статуса или выражением удовлетворения:

1. ОПРЕДЕЛИ: какая команда доказывает это заявление?
2. ЗАПУСТИ: полную команду (свежую, целиком)
3. ПРОЧИТАЙ: весь вывод, проверь exit code, посчитай падения
4. СВЕРЬ: вывод подтверждает заявление?
   - НЕТ → назови фактический статус с доказательствами
   - ДА → делай заявление С доказательствами
5. ТОЛЬКО ПОТОМ: заявляй

Пропустил любой шаг = ложь, а не верификация
```

## Типовые сбои

| Заявление | Требуется | Недостаточно |
|-------|----------|----------------|
| Тесты проходят | Вывод тестовой команды: 0 падений | Прошлый прогон, «должно пройти» |
| Линтер чист | Вывод линтера: 0 ошибок | Частичная проверка, экстраполяция |
| Сборка проходит | Команда сборки: exit 0 | Линтер зелёный, логи выглядят хорошо |
| Баг исправлен | Тест исходного симптома: проходит | Код изменён, «предположительно исправлено» |
| Регрессионный тест работает | Проверен цикл красный-зелёный | Тест прошёл один раз |
| Воркер завершил задачу | git-дифф показывает изменения | Отчёт воркера «успех» |
| Требования выполнены | Построчный чеклист | Тесты проходят |

## Red flags — СТОП

- «должно», «вероятно», «кажется»
- Выражение удовлетворения до верификации («Отлично!», «Идеально!», «Готово!» и т.п.)
- Вот-вот коммит/пуш/PR без верификации
- Доверие отчётам воркеров об успехе
- Опора на частичную верификацию
- Мысль «только этот раз»
- Устал и хочешь, чтобы работа закончилась
- **ЛЮБАЯ формулировка, подразумевающая успех без запуска верификации**

## Профилактика рационализаций

| Оправдание | Реальность |
|--------|---------|
| «Сейчас должно работать» | ЗАПУСТИ верификацию |
| «Я уверен» | Уверенность ≠ доказательство |
| «Только этот раз» | Без исключений |
| «Линтер прошёл» | Линтер ≠ компилятор |
| «Воркер доложил об успехе» | Проверь независимо |
| «Я устал» | Усталость ≠ оправдание |
| «Частичной проверки хватит» | Частичное не доказывает ничего |
| «Другие слова — правило не применяется» | Дух важнее буквы |

## Ключевые паттерны

**Тесты:**
```
✅ [npm run check] [Видно: 591/591 pass] «Все тесты проходят»
❌ «Сейчас должно пройти» / «Выглядит корректно»
```

**Регрессионные тесты (TDD красный-зелёный):**
```
✅ Написал → Запустил (проходит) → Откатил фикс → Запустил (ОБЯЗАН УПАСТЬ) → Вернул → Запустил (проходит)
❌ «Я написал регрессионный тест» (без красно-зелёной верификации)
```

**Сборка:**
```
✅ [npm run build] [Видно: exit 0] «Сборка проходит»
❌ «Линтер прошёл» (линтер не проверяет компиляцию)
```

**Требования:**
```
✅ Перечитай план → составь чеклист → проверь каждый пункт → доложи пробелы или завершение
❌ «Тесты проходят, фаза завершена»
```

**Делегирование воркерам:**
```
✅ Воркер доложил успех → проверь git-дифф → верифицируй изменения → доложи фактическое состояние
❌ Доверять отчёту воркера (воркер, спавненный через {{tool.task}}, мог ошибиться)
```

## Почему это важно

Из 24 воспоминаний о сбоях:
- партнёр сказал «я тебе не верю» — доверие разрушено
- В прод уехали неопределённые функции — урон
- В прод уехали пропущенные требования — незавершённые фичи
- Время потрачено на ложное «готово» → перенаправление → переделка
- Нарушение принципа: «Честность — ключевая ценность. Солжёшь — тебя заменят»

## Когда применять

**ВСЕГДА перед:**
- Любой вариацией заявлений об успехе/завершённости
- Любым выражением удовлетворения
- Любым позитивным утверждением о состоянии работы
- Коммитом, созданием PR, завершением задачи
- Переходом к следующей задаче
- Делегированием воркерам

**Правило распространяется на:**
- Точные формулировки
- Парафразы и синонимы
- Импликации успеха
- ЛЮБУЮ коммуникацию, предполагающую завершённость/корректность

## Интеграция с Wolf

- **Верификационный примитив** проекта — `npm run check`; точечные проверки — `npx vitest run <путь-к-тесту>`.
- **Отчёты воркеров** — не доказательство: dispatcher (executor-lead) проверяет git-дифф и свежий прогон, прежде чем доложить наверх.
- **Инцидент ложного «готово»** — урок в память: `wolf add --type lesson`, чтобы ловушка была видна следующим сессиям.
