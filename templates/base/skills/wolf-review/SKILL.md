## Рамка (методика — НЕ в этом файле)

Линзы — playbook-объекты памяти Wolf: они эволюционируют без рестарта
(мутатор — Стюард, через жалобы). Этот файл — только рамка: протокол цикла
и границы.

### Протокол цикла (оркестратор — mr-wolf)

1. **До прогона** получи актуальный playbook линз:
   `wolf search "wolf-review playbook"` — запись с наибольшей версией.
   Состав и параметры каждой линзы — из playbook, не отсюда.
2. **Порядок линз**: полнота → консистентность → типоспецифичные.
3. **Спавн**: каждую линзу исполняет ОТДЕЛЬНЫЙ worker-reviewer в чистой
   сессии через {{tool.task}}. Изоляция бьёт по слепым зонам саморевью.
   Узкий ревьюер: чужие замечания запрещены — воркер получает только свой
   мандат (документ + своя линза), находки других линз ему не показываются.
4. **Контракты** — обязательные строки отчёта каждой линзы:
   - `SUMMARY: X critical / Y major / Z minor`
   - `VERDICT: APPROVED | CHANGES_REQUIRED`
5. **Дедуп и подсчёт**: mr-wolf сводит находки всех линз, убирает
   дубликаты, считает critical/major/minor по итоговому набору.
6. **Сходимость**: цикл останавливается при 0 critical / 0 blocking ИЛИ
   по лимиту раундов (по умолчанию 3).
7. **Цикл правок**: автор правит документ → перезапуск ТОЛЬКО упавшей
   линзы; прошедшие линзы не перегоняются.
8. **Конфликты**: противоречащие находки разных линз разрешает владелец
   (слепой судьи в MVP нет) — mr-wolf докладывает конфликт, не выбирает сам.

### Границы рамки

- Критичные запреты: `rm -rf`, `sudo`, деструктивный git, секреты.
- Продуктового кода оркестрации нет — цикл ведёт mr-wolf по этому протоколу.
- Этот файл не содержит методику линз и не должен её содержать:
   версии линз живут в памяти Wolf.
