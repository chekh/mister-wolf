# wolf-testplan: test-plan.md по requirements.md

## Обзор

Отдельная ось специализации: один скилл — один тип артефакта (как линзы).
Планирование (wolf-plan) и тест-планирование (этот скилл) раздельны.

## Вход

- `requirements.md` (approved) — AC, единый источник сценариев.
- `design.md` (review или approved) — контракты: сценарии проверяют интерфейс, не реализацию.

## Выход: test-plan.md

1. **Сценарий на каждый REQ-NN** в формате Given/When/Then. Нетривиальные AC —
   дословно их G/W/T из requirements.md; простые — развёртка AC без смены смысла.
2. **Маппинг** — каждый сценарий → целевой тестовый файл (юнит/e2e), которого ещё
   нет: путь `tests/…` + имя теста. Сценарии test-plan.md — заготовки КРАСНОЙ фазы
   TDD (дисциплинарный скилл test-driven-development).
3. **Прогоны** — точечные команды `npx vitest run <путь>`; полный гейт `npm run check`.

## Запреты

- Сценарии для поведения вне REQ/NFR (расширение объёма — дефект).
- Менять AC — правки только через CR в requirements.md.
- Реализовывать тесты: скилл пишет артефакт, не код.

## Процесс

1. Таблица трассировки REQ-NN → сценарий → целевой файл (покрытие 100% REQ;
   NFR — по измеримым AC).
2. Заполнить test-plan.md; front-matter `status: review`.
