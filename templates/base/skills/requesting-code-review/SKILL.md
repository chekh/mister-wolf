## Обзор

Диспетчеризуй воркера-ревьюера, чтобы поймать проблемы до того, как они каскадируют. Ревьюер получает точно сконструированный контекст для оценки — никогда не историю твоей сессии. Это держит ревьюера сфокусированным на продукте работы, а не на твоём мыслительном процессе, и сохраняет твой контекст для продолжения работы.

**Принцип:** ревьюруй рано, ревьюруй часто.

## Когда запрашивать ревью

**Обязательно:**
- После каждой задачи в wolf-sdd
- После завершения крупной фичи
- Перед мержем в main

**Опционально, но ценно:**
- Когда застрял (свежий взгляд)
- Перед рефакторингом (базовая проверка)
- После фиксации сложного бага

## Как запросить

**1. Получить git SHA:**
```bash
BASE_SHA=$(git rev-parse HEAD~1)   # или origin/main
HEAD_SHA=$(git rev-parse HEAD)
```

**2. Диспетчеризовать воркера-ревьюера через {{tool.task}}:**

Спавн worker-reviewer; контекст ревьюера заполняет диспетчер (executor-lead). Ревьюер сам подтягивает методику перед задачей: `wolf search "worker-reviewer playbook"` (контур лица, наибольшая версия).

**Поля контекста:**
- `{WHAT_WAS_IMPLEMENTED}` — что только что построено
- `{PLAN_OR_REQUIREMENTS}` — что оно должно делать (задача из плана / бриф)
- `{BASE_SHA}` — стартовый коммит
- `{HEAD_SHA}` — конечный коммит
- `{DESCRIPTION}` — краткое описание

**3. Действовать по фидбеку (act-on-feedback):**

| Категория | Действие |
|---|---|
| Critical | Исправить немедленно |
| Important | Исправить до продолжения работы |
| Minor | Зафиксировать и учесть позже (`wolf add --type lesson`) |

Возражай, если ревьюер неправ (с обоснованием).

## Пример

```
[Завершена задача 2: функция верификации]

Ты: Запрошу ревью перед продолжением.

BASE_SHA=$(git log --oneline | grep "Task 1" | head -1 | awk '{print $1}')
HEAD_SHA=$(git rev-parse HEAD)

[Диспетчеризую worker-reviewer через {{tool.task}}]
  WHAT_WAS_IMPLEMENTED: Функции verifyIndex() и repairIndex() для индекса диалогов
  PLAN_OR_REQUIREMENTS: Задача 2 из docs/plans/deployment-plan.md
  BASE_SHA: a7981ec
  HEAD_SHA: 3df7661
  DESCRIPTION: Добавлены verifyIndex() и repairIndex() с 4 типами проблем

[Воркер вернул]:
  Strengths: чистая архитектура, настоящие тесты
  Issues:
    Important: нет индикаторов прогресса
    Minor: магическое число (100) для интервала отчётности
  Assessment: готов к продолжению

Ты: [фиксируешь индикаторы прогресса]
[Minor фиксируешь: wolf add --type lesson "техдолг: магическое число 100 ..."]
[Продолжаешь задачу 3]
```

## Интеграция с процессами

**wolf-sdd (субагентная разработка):**
- Ревью после КАЖДОЙ задачи
- Ловить проблемы до того, как они накопятся
- Исправить до перехода к следующей задаче

**wolf-execute (исполнение плана):**
- Ревью после каждого батча (3 задачи)
- Получить фидбек, применить, продолжить

**Ad-hoc разработка:**
- Ревью перед мержем
- Ревью при застревании

## Red flags

**Никогда:**
- Не пропускать ревью со словами «это же просто»
- Не игнорировать Critical-находки
- Не продолжать с неисправленными Important-находками
- Не спорить с валидным техническим фидбеком

**Если ревьюер неправ:**
- Возразить с техническим обоснованием
- Показать код/тесты, доказывающие работу
- Попросить уточнение
