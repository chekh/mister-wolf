# Запрос ревью кода

## Обязательный вход

До запроса собери проверяемую версию результата, требования и мандат. L0 назначает executor, L1 — разрешённого reviewer; L2 возвращает запрос своему L1, не спавнит проверяющего. Для незакоммиченной работы допускается точный diff с untracked и digest. Независимость означает отдельный проверяющий контекст, а не второй абзац автора.

Загрузи полный текст назначенной методики до её выполнения. Обязательные пункты отслеживай в доступном трекере или рабочем брифе; не добавляй новые статусы памяти. Недоступное действие передай ответственному уровню.


## Подготовка

L1 фиксирует base_sha ДО исполнения задачи, current/head revision и dirty-state. Не используй HEAD~1 как универсальную границу: задача может включать несколько коммитов. Для незакоммиченного результата передай проверяемый diff и состояние файлов; не требуй коммита ради ревью.

## Пакет ревьюера

Передай task_id, цель, AC/REQ и утверждённый design, base/head, cwd/worktree, изменённые и релевантные файлы, contract dependencies, проверки/evidence, известные ограничения. Не передавай самооценку автора как ожидаемый вывод. Независимый reviewer проверяет код и основания, а не только пересказ.

Назначь мандат: соответствие, качество/интеграция или специализированный риск. Для значимых изменений проверь security, миграции и failures; для небольших — пропорциональный объём. L0 вызывает executor, L1 — worker-reviewer. Недоступное независимое ревью явно отметь, не имитируй второй голос.

## Конечный мандат

L1 применяет цикл wolf-review; L2 получает полную рамку/лицо reviewer и
назначенную специализированную методику один раз; в TASK укажи реальные model/variant/mode,
конечный бюджет (без заданного — возврат через 8 обращений), read scope и точные
пункты покрытия. Большой мандат разделяет L1, сохраняя проверку общих связей;
воркер не должен самостоятельно становиться руководителем полного аудита. Не создавай отдельную стадию ради ритуала или повторения evidence.
Проверяй изменения и связанные контракты; полный аудит проекта — только
отдельное явное поручение. Не передавай ожидаемый вердикт.

## Результат

Используй контракт wolf-review: finding_id, severity, location/revision, evidence, impact; verdict APPROVED | CHANGES_REQUIRED | INCONCLUSIVE. Critical/Major блокируют приёмку; Minor — нет, кроме явно обоснованного риска. Технический долг — отдельная задача/заметка, lesson только для повторяемого знания.

## Обработка

Прими фидбек через receiving-code-review. Перед повторным ревью обозначь изменённые версии и закрываемые finding IDs. Сохрани действительные результаты неизменённых проверок; повтори затронутые. Открытие PR и его приёмка — разные состояния, отчёт должен это различать.

## Гейт перехода

Ревью завершено после фактического отчёта по согласованной версии и обработки его находок через receiving-code-review. До нужного APPROVED не переходи к приёмке; отсутствие независимого канала обозначь. Новые правки требуют анализа актуальности старого вердикта.

## Не пропускай процесс

| Мысль | Действие |
| --- | --- |
| «Возьму HEAD~1» | Диапазон определяется задачей и сохранённым baseline. |
| «Скажу ревьюеру, что всё правильно» | Передай исходные артефакты без ожидаемого вывода. |
| «Создан запрос — ревью состоялось» | Нужны результат, версия и ограничения проверки. |
