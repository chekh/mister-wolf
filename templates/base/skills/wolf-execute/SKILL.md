# wolf-execute: линейное исполнение плана (FLAT)

## Обзор

Загрузи план, критически его осмотрись, исполняй все задачи, отчитайся по завершении. Это FLAT-режим — без спавна воркеров, всё в одной сессии.

**Анонс на старте:** «Использую скилл wolf-execute для исполнения этого плана».

**Если доступны субагенты** — используй wolf-sdd вместо этого скилла: свежий воркер на задачу + двухстадийное ревью дают заметно более высокое качество. wolf-execute — fallback для платформ/сессий без диспетчеризации.

## REQUIRED-предусловие: worktree

**До старта исполнения worktree ОБЯЗАН существовать:** `.worktrees/<имя-задачи>` внутри проекта (правило проекта). Trunk-based: main — истина, работа идёт в ветке внутри worktree (см. скилл using-git-worktrees). Никогда не начинай исполнение в main без явного согласия владельца.

## Процесс

### Шаг 1: загрузи и осмотрись
1. Прочитай файл плана
2. Критическое ревью — определи вопросы и сомнения по плану
3. Есть сомнения — подними их перед владельцем до старта
4. Нет сомнений — заведи трекинг задач через {{tool.todowrite}} и продолжай

### Шаг 2: исполняй задачи

Для каждой задачи:
1. Отметь in_progress
2. Следуй каждому шагу точно (план состоит из bite-sized шагов)
3. Запускай верификацию, как предписано планом; после завершённых блоков — `npm run check` (verification-примитив проекта)
4. Отметь завершённой

### Шаг 3: заверши разработку

После всех задач и верификации:
- Анонс: «Использую скилл finishing-a-development-branch для завершения работы»
- **REQUIRED-СКИЛЛ:** finishing-a-development-branch
- Следуй ему: верифицируй тесты, представь опции финала ветки, исполни выбор владельца

## Когда остановиться и спросить

**СТОП исполнения немедленно, когда:**
- Ударился в блокер (нет зависимости, падает тест, инструкция непонятна)
- В плане критические пробелы, мешающие стартовать
- Ты не понимаешь инструкцию
- Верификация падает повторно

**Проси уточнения, а не угадывай.** Застрял — зафиксируй блокер в памяти (`wolf add --type blocker`) и поднимись к владельцу.

## Когда вернуться к ранним шагам

**Вернись к ревью (шаг 1), когда:**
- Владелец обновил план по твоему фидбеку
- Фундаментальный подход требует пересмотра

**Не продавливай блокеры силой** — остановись и спроси.

## Помни

- Сначала критически осмотрись планом
- Следуй шагам плана точно
- Не пропускай верификации
- Обращайся к скиллам, когда план говорит
- Остановился — не угадывай, спроси
- Никогда не начинай исполнение в main без явного согласия владельца

## Интеграция

**Обязательные скиллы воркфлоу:**
- **using-git-worktrees** — REQUIRED: изолированный worktree `.worktrees/<имя-задачи>` ДО старта исполнения
- **wolf-plan** — создаёт план, который этот скилл исполняет
- **finishing-a-development-branch** — завершение разработки после всех задач
