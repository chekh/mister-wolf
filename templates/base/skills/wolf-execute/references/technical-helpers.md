# Технические операции конечного поручения

Помощник-агент — исполнитель с конечным TASK и назначенными скиллами. Следующий Python 3 helper обслуживает
повторяемую механику и не выбирает исполнителя/цель/AC. При необходимости
используй `python3 <каталог навыка>/scripts/workflow-helper.py --help`.
Это локальный инструмент, не новые команды Wolf или публичный TASK-parser.
Перед запуском проверь права роли, среду и назначенные выходные пути.

| Операция | Вход и использование | Подтверждение |
| --- | --- | --- |
| task-pack | --input с JSON конечного задания: task_id, role, goal, ac, scope, inputs (локальные пути), method (полный источник), verification, execution с budget/stop, expected_result | ready=false и список missing при недостатке; активные политики памяти разрешает ведущий |
| check | --repo корень worktree, --task, --claim, --log в разрешённом месте, затем -- команда аргументами | outcome/exit, revision до/после, dirty-state и log digest; не ACCEPTED |
| review-package | --repo, --task, --base, --head, --output вне проверяемого worktree | непустой диапазон committed-изменений без скрытой dirty-части; повтор публикации того же пакета не затирает другое содержимое |

Команда check выполняется без shell и в назначенном cwd. Этот helper требует
чистую committed-рабочую копию и лог вне неё; dirty-снимок отдельно не реализован.
Python требуется версии 3.9 или новее. Ненулевой исход,
timeout, недоступность или изменение HEAD не выдаются за успех. Лог сохраняется
в выбранном месте; если это tmp, ведущий обеспечивает сохранность нужного evidence
до передачи/очистки. Один и тот же завершённый результат имеет evidence_key;
Ведущий использует его для адресного сохранения/обновления существующей рабочей note.
Helper сам не пишет память, не дедуплицирует произвольные записи Wolf и не
повторяет побочный запуск после неизвестного исхода. Новый фактический запуск
может иметь отдельное подтверждение. Лог и исходники могут содержать секреты:
не выводи их целиком в чат; пользовательский вывод готовь по wolf-feedback.

Пакет ревью не содержит AC автоматически: ведущий передаёт нужные нормы и evidence
без ожидаемого verdict и чужих findings при первом независимом проходе.
Если выбранный режим не покрывает untracked/dirty, сначала обеспечь checkpoint
или назначь другой воспроизводимый снимок; helper не очищает рабочую копию.
Проверка актуальности evidence и ACCEPTANCE остаётся у принимающего уровня.
