## Обзор

Проведи финал работы через ясные опции и исполнение выбранного сценария.

**Принцип:** верифицируй тесты → предъяви опции → исполни выбор → приберись.

**Анонс в начале:** «Использую скилл finishing-a-development-branch для завершения этой работы».

## Процесс

### Шаг 1: верифицируй тесты

**До предъявления опций — прогнать тесты:**

```bash
npm run check   # тестовая команда проекта
```

**Упали:**
```
Тесты падают (<N> падений). Надо починить до завершения:

[показать падения]

Нельзя продолжать merge/PR, пока тесты не зелёные.
```

Стоп. Не переходить к шагу 2.

**Зелёные:** → шаг 2.

### Шаг 2: определи базовую ветку

Правило проекта — trunk-based: базовая ветка всегда `main` (main — истина).

```bash
git merge-base HEAD main
```

При сомнении спроси: «Ветка отделилась от main — верно?»

### Шаг 3: предъяви опции

Ровно эти 4 опции:

```
Реализация завершена. Что делаем?

1. Смержить обратно в <base-branch> локально
2. Запушить и создать Pull Request
3. Оставить ветку как есть (разберусь позже)
4. Выбросить эту работу

Какая опция?
```

**Без пояснений** — опции краткие.

### Шаг 4: исполни выбор

#### Опция 1: мерж локально

Только по явному поручению владельца (правило проекта: main — истина, мерж — осознанное решение владельца).

```bash
git checkout main
git pull
git merge <feature-branch>

# Верифицировать тесты на смерженном результате
npm run check

# Если зелёные
git branch -d <feature-branch>
```

Затем: уборка worktree (шаг 5).

#### Опция 2: пуш и PR

```bash
git push -u origin <feature-branch>

gh pr create --title "<заголовок>" --body "$(cat <<'EOF'
## Summary
<2-3 буллета что изменилось>

## Test Plan
- [ ] <шаги верификации>
EOF
)"
```

Затем: уборка worktree (шаг 5).

#### Опция 3: оставить как есть

Доложить: «Оставляю ветку <имя>. Worktree сохранён: <путь>».

**Worktree не убирать.**

#### Опция 4: выбросить

**Сначала подтверждение:**
```
Это навсегда удалит:
- Ветку <имя>
- Все коммиты: <список-коммитов>
- Worktree <путь>

Введи 'discard' для подтверждения.
```

Ждать дословного подтверждения.

Если подтверждено:
```bash
git checkout main
git branch -D <feature-branch>
```

Затем: уборка worktree (шаг 5).

### Шаг 5: уборка worktree

**Для опций 1, 2, 4:**

Проверить, находишься ли в worktree:
```bash
git worktree list | grep $(git branch --show-current)
```

Если да:
```bash
git worktree remove <worktree-path>
```

**Для опции 3:** worktree сохранить.

## Быстрая шпаргалка

| Опция | Мерж | Пуш | Сохранить worktree | Удалить ветку |
|--------|-------|------|---------------|----------------|
| 1. Мерж локально | ✓ | - | - | ✓ |
| 2. Создать PR | - | ✓ | ✓ | - |
| 3. Оставить как есть | - | - | ✓ | - |
| 4. Выбросить | - | - | - | ✓ (force) |

## Частые ошибки

**Пропуск верификации тестов**
- **Проблема:** смержить сломанный код, создать падающий PR
- **Фикс:** всегда верифицировать тесты до предъявления опций

**Открытые вопросы**
- **Проблема:** «Что делать дальше?» → двусмысленность
- **Фикс:** предъявлять ровно 4 структурированные опции

**Автоматическая уборка worktree**
- **Проблема:** удалить worktree, который ещё нужен (опции 2, 3)
- **Фикс:** уборка только для опций 1 и 4

**Без подтверждения для discard**
- **Проблема:** случайно удалить работу
- **Фикс:** требовать дословный ввод «discard»

## Red flags

**Никогда:**
- Не продолжать с падающими тестами
- Не мержить без верификации тестов на результате
- Не удалять работу без подтверждения
- Не форс-пушить без явного запроса

**Всегда:**
- Верифицировать тесты до предъявления опций
- Предъявлять ровно 4 опции
- Получать дословное подтверждение для опции 4
- Убирать worktree только для опций 1 и 4
