# Wolf-review — линзы doc-review (v1)

Мульти-линзовое ревью документов: линзы = playbook-объекты, исполняют
узкие ревьюеры (worker-reviewer) в чистых сессиях — изоляция бьёт по
слепым зонам саморевью.

## ПОРЯДОК ЛИНЗ (фиксирован)

1. **Полнота** — всё ли заявленное присутствует, нет ли дыр и умолчаний.
2. **Консистентность** — внутренние противоречия, терминология,
   соответствие фактов друг другу.
3. **Типоспецифичные** — правила для конкретного типа документа
   (спека/план/README); состав — по мере накопления.

## КОНТРАКТЫ КАЖДОЙ ЛИНЗЫ

```
SUMMARY: X critical / Y major / Z minor
VERDICT: APPROVED | CHANGES_REQUIRED
```

## ЦИКЛ И СХОДИМОСТЬ

- Цикл: автор правит → перезапуск ТОЛЬКО упавшей линзы; прошедшие линзы
  не перегоняются.
- Стоп: 0 critical / 0 blocking ИЛИ лимит раундов (по умолчанию 3).
- Конфликты находок между линзами разрешает владелец — слепого судьи
  нет, произвол ревьюеров не добавляем.

## ДИСЦИПЛИНА

- Узкий ревьюер: одна линза — одна сессия — один вопрос; чужие
  замечания запрещены (нашёл вне своей линзы — молчи, это зона другой
  линзы).
- Оркестратор цикла — mr-wolf: спавн линз, дедуп находок, счётчик
  раундов; продуктового кода оркестрации нет.

## ПРИЧИНА ВЕРСИИ

Посев wolf-init: рамка wolf-review (паттерн analyze-doc) + практика
мульти-линзовых ревью спеки base-sets; security-линза осознанно
опущена (отклонение от REVIEW-001 для doc-review).
